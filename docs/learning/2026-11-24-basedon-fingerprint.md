# basedOn เป็นลายนิ้วมือรายการ (24 พ.ย. 2569)

**ปัญหา:** ตอนบันทึกรายการขาย เว็บคำนวณ "ต้นทุนที่ตัดออก" จากรายการเดิมของสินทรัพย์นั้น แล้วส่งไปพร้อม `basedOn` = จำนวนรายการเดิม ฐานข้อมูลเทียบจำนวนนี้หลังล็อกสินทรัพย์ เพื่อจับกรณีเปิดหลายแท็บ แต่เมื่อมี "แก้รายการ" (ลบ 1 เพิ่ม 1) จำนวนรายการเท่าเดิม แท็บที่ยังถือข้อมูลก่อนแก้จึงผ่านด่านได้ และบันทึกขายด้วยต้นทุนที่ผิด ฐานข้อมูลตรวจแค่ว่าสมุดสมดุล (R16) ไม่ได้ตรวจต้นทุน (R17)

**แก้อย่างไร:** `basedOn` เปลี่ยนเป็นลายนิ้วมือ (sha256) ของรายการทั้งหมดของสินทรัพย์ (รหัส ชนิด วันที่ หน่วย ราคา ยอด ค่าธรรมเนียม ภาษีหัก อัตราแลก) แก้อะไรก็ตามที่กระทบต้นทุน ลายนิ้วมือเปลี่ยนทันที แท็บเก่าจึงได้ PT409 "ข้อมูลเปลี่ยนไป โหลดใหม่" เหมือนเดิม
- ฐานข้อมูล: `private.trades_fingerprint(user, asset)` + `record_trade`, `record_trade_fx`, `replace_trade` ตรวจหลังล็อกสินทรัพย์ (replace_trade ตรวจก่อนลบ แล้วตัด basedOn ออกก่อนส่งต่อ เพราะ record_trade จะตรวจหลังลบซึ่งเป็นสถานะอื่น)
- เว็บ: `src/domain/invest/tradesFingerprint.ts` สูตรเดียวกันทุกตัวอักษร (เรียงตามรหัสแบบไบต์ ค่าว่างเป็นข้อความว่าง)
- basedOn แบบตัวเลขเดิมยังรับอยู่ชั่วคราว เพื่อไม่ให้เว็บรุ่นเก่าพังระหว่างปล่อย จะตัดออกใน migration ถัดไปหลังเว็บใหม่ขึ้นแล้ว

**ทดสอบอย่างไร:** เทสต์ SQL ไฟล์ใหม่ `basedon_fingerprint_test.sql` (กรณีแก้แล้วจำนวนเท่าเดิมต้องได้ PT409 ทั้งบาทและ USD, replace_trade, รูปแบบผิด, ข้ามผู้ใช้, สิทธิ์) · เทสต์หน่วย `tradesFingerprint.test.ts` ใช้ค่าตัวอย่างที่คำนวณบนฐานข้อมูลจริง · live-contract `tradesFingerprint.live.ts` พิสูจน์ว่าสูตรเว็บตรงกับฐานข้อมูลจริง

## รหัส error: ทำไมเปลี่ยนจาก 40001 เป็น PT409 (migration 20261124000200)
- ตอนแรกให้กรณี "ข้อมูลเปลี่ยนระหว่างทำรายการ" ใช้รหัส 40001 (serialization_failure) แต่ PostgREST ถือว่า 40001 คือ "ลองใหม่ได้" แล้วลองรันคำสั่งซ้ำเองไปเรื่อยๆ จนค้างราว 60 วินาที (เทสต์ live ล้มแบบหมดเวลา ทั้งที่ฝั่งฐานข้อมูลตอบใน 19 ms)
- เอกสารยืนยัน: https://supabase.com/docs/guides/troubleshooting/high-cpu-and-infinite-transaction-retries-when-using-custom-error-codes-in-rpc-functions-77326b (ให้ใช้รหัสขึ้นต้น PT เช่น PT409 แทน)
- เคยเจอแบบเดียวกันกับ merge_settings_if มาแล้ว (20261113000400) · แก้เฉพาะรหัสใน record_trade, record_trade_fx, replace_trade ตรรกะเงินเหมือนเดิม
- หลังแก้ เทสต์ live ข้อเดิมใช้ 1.7 วินาที และได้ PT409 ตามคาด
