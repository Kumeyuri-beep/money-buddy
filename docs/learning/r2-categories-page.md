# หน้า Portfolio → Categories (R2 ฝั่งหน้าจอ)

## ทำอะไร
เปิดหน้า Categories ใน /invest (เดิมเป็น "Coming soon") ให้ผู้ใช้จัดหุ้นเป็นหมวดของตัวเอง ตั้งเป้า % ต่อหมวด แล้วดูตารางเทียบสัดส่วนจริงกับเป้า
- ตารางสรุปต่อหมวด: มูลค่า / ลงทุน / กำไร / สัดส่วน / เทียบเป้า (on target, over by, under by) พร้อมโดนัท
- ปุ่ม Change เปิดตัวแก้: เพิ่ม เปลี่ยนชื่อ ลบ เลื่อนลำดับ ตั้งเป้า ย้ายหุ้นเข้าหมวด รวมหมวด · ผลรวมเป้าต้อง 100% พอดี ไม่ครบกดบันทึกไม่ได้ (บอกว่าขาดหรือเกินเท่าไร)
- ปุ่ม Create categories from sectors: จัดกลุ่มจาก sector ของหุ้นที่ถืออยู่ (ไม่มี sector = Uncategorized) ผลเป็น "ร่าง" ให้ตั้งเป้าก่อนกด Save
- ช่อง Sector (ไม่บังคับ) ในฟอร์มเพิ่มหุ้น (เฉพาะคอม): เลือกจาก GICS 11 กลุ่มหรือพิมพ์เอง
- Export CSV / Export JSON / Import JSON: นำเข้าเป็นร่างเสมอ ต้องกด Save เอง

## ทำไมทำแบบนี้
- เป้าเก็บเป็น bps จำนวนเต็ม (45% = 4,500) แปลงเป็นข้อความเปอร์เซ็นต์ด้วยจำนวนเต็มล้วน ไม่มี float (R1)
- ตัวเลขทุกตัวในตารางมาจากฟังก์ชันที่มีอยู่ (`totalsOf`, `allocateBps`) หน้าจอไม่คิดสูตรเงินเอง ค่าที่ไม่มีราคาแสดง "—" ไม่เดา และไม่บวกข้ามสกุล (R20)
- กฎหมวด (ชื่อซ้ำ ไม่เกิน 50 เป้ารวม 100%) ใช้ `categoriesProblem` ตัวเดียวกับฐานข้อมูล ฝั่งเว็บตรวจก่อนเพื่อให้ข้อความชัด ฐานข้อมูลตรวจซ้ำอีกชั้น
- การสร้างจาก sector/นำเข้าเป็นร่างก่อน เพราะถ้าหมวดบางหมวดมีเป้าแต่บางหมวดไม่มี ฐานข้อมูลจะปฏิเสธ จึงให้ผู้ใช้ตั้งเป้าให้ครบก่อนบันทึก
