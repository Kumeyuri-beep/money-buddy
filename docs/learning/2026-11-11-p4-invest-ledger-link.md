# P4: ผูกการซื้อขายกองทุนกับสมุดบัญชี (สรุปแบบง่าย)

## ทำอะไร
ก่อนหน้านี้ เวลาคุณบันทึก "ซื้อกองทุน 1,000 บาท" ในหน้าพอร์ต เงินในกระเป๋าไม่ลดลงเลย เพราะสมุดบัญชีกับหน้าพอร์ตแยกกัน
P4 ทำให้สองอย่างนี้ขยับพร้อมกันเสมอ:

| คุณบันทึก | สมุดบัญชีจะเปลี่ยนยังไง |
| --- | --- |
| ซื้อ | เงินในกระเป๋าลด · ต้นทุนของกองทุนเพิ่มเท่ากัน (รวมค่าธรรมเนียม) |
| ขาย | เงินเข้ากระเป๋า (หลังหักค่าธรรมเนียม) · ต้นทุนของกองทุนลดตามส่วน · ส่วนต่างเป็นกำไรหรือขาดทุน |
| ปันผลเป็นเงินสด | เงินเข้ากระเป๋า (หลังหักภาษี) · ภาษีและปันผลถูกบันทึกไว้ |
| ปันผลลงทุนต่อ | ต้นทุนของกองทุนเพิ่ม ไม่มีเงินสดเข้าออก |

กำไร ขาดทุน ปันผล และภาษี **ไม่ถูกนับเป็น "รายรับ" หรือ "รายจ่าย" ปกติ** (เช่น เงินเดือน, ค่าอาหาร) จะดูได้แยกที่หน้าพอร์ต

## ทำไมต้องทำ
1. **ยอดเงินจะได้ตรง** กระเป๋าเงินสะท้อนความจริง ไม่ต้องจำว่าซื้อกองทุนไปเท่าไหร่
2. **กันข้อมูลเพี้ยนจากการเปิดสองแท็บ** ถ้าเปิดแอปสองหน้าต่างแล้วกดขายพร้อมกัน เดิมอาจขายเกินจำนวนที่ถืออยู่ได้ ตอนนี้ฐานข้อมูลเป็นคนเช็กและเข้าคิวเอง (ไม่ต้องเชื่อหน้าเว็บอย่างเดียว)
3. **บันทึกครบหรือไม่บันทึกเลย** รายการลงทุนกับรายการในสมุดถูกสร้างพร้อมกันในธุรกรรมเดียว ถ้าอันใดอันหนึ่งผิด ทั้งสองไม่ถูกบันทึก (ไม่มีกรณีเงินลดแต่ไม่มีรายการ)

## หลักการที่ต้องรู้ (จำง่ายๆ)
- **สมุดบัญชีคู่**: ทุกรายการมีสองด้านเท่ากัน เช่น เงินออกจากกระเป๋า = ต้นทุนกองทุนเพิ่ม ถ้าไม่เท่ากันระบบไม่ยอมบันทึก
- **ต้นทุนเฉลี่ย**: ซื้อหลายครั้งราคาต่างกัน ต้นทุนต่อหน่วยคือค่าเฉลี่ยถ่วงน้ำหนัก ตอนขายระบบตัดต้นทุนตามสัดส่วนที่ขาย
- **ลบรายการ**: ที่ผูกสมุดแล้วให้ลบจากรายการในสมุด ระบบลบรายการลงทุนตามให้ และคืนยอดกระเป๋า
- **ลบย้อนหลังได้แค่ไหน**: ถ้ามีรายการขายแล้ว ลบรายการซื้อ/ปันผลลงทุนต่อที่เกิดก่อนวันขายไม่ได้ ต้องลบรายการขายก่อน (เพราะต้นทุนเฉลี่ยขึ้นกับลำดับ)
- **รายการเก่า** ที่บันทึกก่อน P4 ไม่ได้ปรับยอดกระเป๋าย้อนหลัง

## ทดสอบอย่างไร
- **เทสต์ฐานข้อมูล** (`supabase/tests/invest_ledger_test.sql`): ลองบันทึกผิดแบบต่างๆ (ยอดไม่ตรง ขายเกิน ใช้บัญชีคนอื่น วันที่ย้อนหลัง) ต้องถูกปฏิเสธด้วยรหัสที่ถูกต้อง แล้วตรวจด้วยสิทธิ์ผู้ดูแลว่า **ไม่มีแถวไหนถูกเขียนค้างเลย**
- **เทสต์ฝั่งเว็บ** (`tests/unit/investLedgerLink.test.ts`): รายการในสมุดของแต่ละชนิดสมดุลและตัวเลขถูก รวมกรณีขอบ (ยอดสุทธิ 0, ขายเท่าทุน) และกำไรไม่ปนกับเงินเดือน
- **เทสต์จริงกับ Supabase** (`npm run admin:live-contract`): ลองกับฐานข้อมูลจริงด้วยผู้ใช้ทดสอบสองคน
- ก่อนใส่ migration จริงใช้ "dry-run แบบ rollback" คือรันทั้งหมดแล้วยกเลิก เพื่อดูว่าผ่านโดยไม่เหลืออะไรในฐานข้อมูล

## ศัพท์ที่เจอบ่อย
- **migration**: ไฟล์ SQL ที่เปลี่ยนโครงสร้างฐานข้อมูล
- **trigger**: ตัวเฝ้าในฐานข้อมูลที่ทำงานเองเมื่อมีการเพิ่ม/ลบแถว
- **RPC**: ฟังก์ชันในฐานข้อมูลที่เว็บเรียกใช้ (ที่นี่คือ `record_trade`)
- **RLS**: กติกาที่ทำให้ผู้ใช้แต่ละคนเห็นเฉพาะข้อมูลตัวเอง
