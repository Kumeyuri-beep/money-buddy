# เรียนรู้: โหลดหน้าที่ไม่ได้ใช้ทีหลัง (lazy loading)

**ทำอะไร:** เดิมแอปรวมโค้ดทุกหน้าเป็นไฟล์ JS ก้อนเดียว (988.6 kB, บีบแล้ว 268.1 kB) ทุกคนต้องโหลดทั้งก้อนก่อนเห็นหน้าแรก ตอนนี้หน้า ภาษี, เกษียณ, พอร์ต, ถัวเฉลี่ยต้นทุน, บัญชี (และส่วนดึงยอดจากพอร์ตของหน้าภาษี) แยกเป็นไฟล์เล็กๆ โหลดตอนเปิดหน้านั้นครั้งแรก

**ผลวัดจาก build จริง:**
| | ก่อน | หลัง |
|---|---|---|
| ไฟล์หลัก (JS) | 988.6 kB | 827.6 kB |
| ไฟล์หลักบีบแล้ว (gzip) | 268.1 kB | 232.6 kB (ลด 35.5 kB ≈ 13%) |
| ไฟล์แยก (gzip) | - | ภาษี 5.6 · ลิงก์พอร์ต 3.4 · เกษียณ 8.0 · พอร์ต 10.5 · ถัวเฉลี่ย 2.5 · บัญชี 2.1 kB |

ประมาณเวลาบนเครือข่าย 4G ช้า (~200 kB/วินาที): ส่วน JS ที่ต้องโหลดก่อนเห็นหน้าแรกเร็วขึ้นราว 0.18 วินาที บวกเวลาแปลโค้ดที่ลดลงบนมือถือ (ตัวเลขประมาณจากขนาดไฟล์ ไม่ได้วัดบนเครื่องจริง) · ผลไม่ใหญ่เพราะส่วนที่เหลือส่วนใหญ่เป็นไลบรารี (React, Supabase, Dexie) ที่หน้าแรกต้องใช้จริง · อ่านข้อความ OCR (Tesseract) โหลดแยกอยู่แล้วก่อนหน้านี้

**ทำไมไม่แยกเพิ่ม:** Supabase ใช้ตอนล็อกอิน, Dexie ยังต้องคงไว้จนย้ายข้อมูลเสร็จ (M2-D) จึงแยกไม่ได้โดยไม่เสี่ยง

**เรื่องการเข้าถึง:** ระหว่างรอมีข้อความ "กำลังโหลดหน้า…" (โปรแกรมอ่านจอบอกสถานะ) · ย้ายโฟกัสไปหัวข้อหน้าหลังโหลดเสร็จ (รอแล้วลองใหม่ทุก 0.1 วินาที สูงสุด ~3 วินาที) · ถ้าโหลดล้ม ลองใหม่ 1 ครั้งทันที ถ้ายังล้ม แสดงข้อความของ ErrorBoundary (ข้อมูลไม่ถูกแตะ)

**ทดสอบอย่างไร:** เทสต์ตรวจว่าหน้าเหล่านี้ไม่ได้ import ตรงใน App, มี Suspense ใน ErrorBoundary, ตรรกะโฟกัสใหม่ · `npm test`, typecheck, build ผ่าน
