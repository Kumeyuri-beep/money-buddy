# R2 ข้อ 4 ส่วน B: หน้าจอแก้รายการ + Delete asset (เฉพาะคอม)

## ทำอะไร
- ปุ่ม **Edit** ในตาราง Portfolio → Transactions ใช้งานได้แล้วบนคอม (≥1024px) เปิดหน้าต่าง (dialog) ฟอร์มเดียวกับตอน Add เติมค่าเดิมไว้ ครอบคลุมซื้อ / ขาย / ปันผล ของหุ้นสหรัฐ (USD) และ ซื้อ / ขาย / ปันผล / ปันผลลงทุนต่อ ของกองทุน-หุ้นไทย (บาท) ชนิดรายการเปลี่ยนไม่ได้
- กด **Review change** แล้วเห็นผลกระทบ **ก่อนแก้ → หลังแก้**: จำนวนหุ้น ต้นทุนเฉลี่ยต่อหุ้น ต้นทุนรวมของที่ถืออยู่ และกำไรที่ขายแล้ว (หุ้น USD แสดงบาทด้วย) แถวที่เปลี่ยนมีคำว่า "(changed)" จากนั้นกด **Save changes** จึงบันทึกจริง (ผ่าน `replaceTrade` ที่ทำไว้ใน PR #268)
- ปุ่ม Edit ที่แก้ไม่ได้จะปิด และบอกเหตุผลเมื่อกด เช่น "Delete the later sale first" (ซื้อที่อยู่ก่อนรายการขาย, ขายที่ไม่ใช่ล่าสุด) หรือ "แลกเงิน/เงินสด/โอน แก้ไม่ได้ ให้ลบแล้วเพิ่มใหม่"
- เมนู ⋯ ของ Holdings มีรายการ **Delete asset**: กดได้เฉพาะสินทรัพย์ที่ไม่เหลือรายการ (ที่เหลือรายการจะปิดและบอกว่า "Delete its N transactions first") มี dialog ยืนยัน
- **มือถือ (<1024px):** ปุ่ม Edit ปิดพร้อมข้อความ "Available on desktop" ส่วน Delete asset ไม่แสดงในเมนูเลย (หน้าตามือถือเหมือนเดิม)

## ทำไมออกแบบแบบนี้
- ใช้ฟอร์มและตัวตรวจเดียวกับ Add (`buildTradeRecord` / `buildUsTradeRecord`) กติกาจึงตรงกันทุกประการ ไม่มีสูตรเงินใหม่ใน component
- ตัวเลขก่อน→หลังมาจากฟังก์ชัน `previewTradeEdit` (`src/domain/invest/editImpact.ts`) ที่เรียกตัวเล่นซ้ำ (`replayTrades` / `replayTradesFx`) และตัวตรวจกติกา R17 ตัวเดียวกับที่ repository ใช้ ผู้ใช้จึงเห็นผลเดียวกับที่จะถูกบันทึก ผิดกติกาก็บอกก่อนส่ง
- ลบสินทรัพย์ต้องไม่มีรายการ เพราะรายการลงทุนทุกรายการผูกกับสมุดบัญชี ถ้าลบสินทรัพย์ทั้งที่ยังมีรายการ ยอดในสมุดจะค้าง ฐานข้อมูลปฏิเสธซ้ำอีกชั้น (RPC `delete_asset`)

## สิ่งที่แก้เพิ่มนอกโจทย์ (แจ้งแล้ว)
เมนู ⋯ ของ Holdings บนคอมเปิดต่ำกว่าปุ่มราว 300px จนหลุดจอ (มีอยู่แล้วบน `main`) เพราะการ์ดกระจกมี `backdrop-filter` ทำให้ `position: fixed` ของเมนูอิงกรอบการ์ดแทนหน้าจอ รายการ Delete asset จึงกดไม่ถึง แก้โดยวางเมนูลงใน `body` (portal) เฉพาะคอม มือถือไม่แตะ
