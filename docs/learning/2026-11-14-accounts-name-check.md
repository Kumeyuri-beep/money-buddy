# ห้ามอักขระควบคุมในชื่อบัญชี (check constraint ฝั่งฐานข้อมูล)

## ทำอะไร
- เพิ่ม check constraint `accounts_name_no_invisible` ที่ตาราง `accounts`: ชื่อบัญชีห้ามมีอักขระควบคุม (รวมแท็บ/ขึ้นบรรทัดใหม่) ตัวศูนย์ความกว้าง ตัวกำกับทิศ/กลับทิศข้อความ และ BOM
- ก่อนหน้านี้เว็บตรวจอยู่แล้ว แต่ใครยิงคำสั่งตรงเข้า API ด้วย token ของตัวเองก็ข้ามได้ (เสียหายเฉพาะข้อมูลของตัวเอง เช่น ชื่อดูซ้ำกันทั้งที่ต่างกัน หรือชื่อแสดงสลับทิศ) ตอนนี้ฐานข้อมูลปฏิเสธเอง
- ฝั่งเว็บเพิ่มการตรวจชื่อเดียวกันในตัวตรวจบัญชีกลาง (`accountProblem`) ทำให้หน้าตั้งต้น การนำเข้าไฟล์สำรอง ก็บอกเป็นข้อความไทยตั้งแต่ต้น ไม่ปล่อยให้ฐานข้อมูลปฏิเสธตอนบันทึก

## ทำอย่างระวัง
- นับแถวเดิมที่ขัดก่อน (นับอย่างเดียว ไม่แสดงเนื้อหา): 0 จาก 15 แถว จึงใส่ได้ · ใส่แบบ `NOT VALID` แล้ว `VALIDATE` (ตรวจแล้วผ่านเป็น validated)
- ดรายรันแบบ rollback ผ่านก่อน (TESTS_PASSED) · เทสต์ SQL ใหม่ครอบ 11 รูปแบบอักขระที่ต้องถูกปฏิเสธ (ทั้ง insert และ update ชื่อ) กับ 6 ชื่อปกติที่ต้องผ่าน (ไทยมีสระวรรณยุกต์ อังกฤษ สัญลักษณ์ อีโมจิ) และ setup_ledger
- รันเทสต์ SQL ที่แตะตาราง accounts ซ้ำหลังใส่: accounts_name_only, m2d_import_ledger, m2d_import_limits ขึ้น TESTS_PASSED · live-contract 60/60
