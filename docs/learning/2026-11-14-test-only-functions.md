# ไล่ฟังก์ชันที่ production ไม่เรียกแต่มีเทสต์ครอบ (9 ตัว)

ผลตามกติกาที่เจ้าของสั่ง (money-auditor ตรวจ 5 ตัวที่เกี่ยวกับเงิน/สลิป ผมตรวจที่เหลือเอง)

| ฟังก์ชัน | มีตัวที่ใช้จริงไหม | ผลเทียบ | ทำอะไร |
|---|---|---|---|
| `parseSlipText` | มี: `parseSlipTextDetailed` (production เรียกผ่าน `parseSlipTexts`) | เป็นตัวห่อ `.fields` ตรงๆ **ผลเท่ากันทุกกรณี** | export ตัวจริง ให้เทสต์เรียกโดยตรง **ลบตัวห่อแล้ว** (128 เทสต์ผ่านเท่าเดิม) |
| `draftFromOcrText` | มี: `draftFromOcrTexts` (App.tsx เรียก) | ตัวห่อ `[text]` ตรงๆ ผลเท่ากัน | เทสต์เรียกตัวจริง **ลบตัวห่อแล้ว** |
| `ALL_FILTER` | ไม่มี (หน้ารายการสร้างตัวกรองเองจากเดือนปัจจุบัน) | – | ย้ายไปเป็นค่าท้องถิ่นในเทสต์ **ลบจาก src แล้ว** |
| `SUMMARY_CARD_IDS` | ไม่มี (โครงสร้างจริงคือคีย์ของผล `buildOverview`) | – | เทสต์ "การ์ด 8 ใบ" นับจากคีย์ที่ `buildOverview` คืนจริง **ลบค่าคงที่แล้ว** |
| `convertToSatang` | ไม่มี (ยังไม่มีตัวแปลงสกุลเงินที่ไหน) | – | **เก็บไว้ + เขียนเหตุผลในโค้ด**: เตรียมไว้ตามกฎเงินข้อ 3 (ลงทุนข้ามสกุล) |
| `projectDca` | ไม่มี (หน้าถัวเฉลี่ยคำนวณงวดเดียวด้วย `dcaUnits`+`applyBuy`) | หนึ่งงวดเท่ากัน | **เก็บไว้ + เขียนเหตุผลในโค้ด**: เตรียมไว้สำหรับตัวคำนวณ DCA ล่วงหน้า (แผน P1) |
| `outstandingBeforePayday` | มี: `buildSafeToSpend`/`buildUpcomingPanel` (กรองบิลเสียด้วย `splitValidBills` ก่อน) | **ต่างกันเมื่อมีบิลเสีย** (ของ production ข้ามบิลเสียแล้วเตือน · ตัวนี้โยน error ทั้งก้อน) | **หยุด ไม่แตะ รอเจ้าของ** |
| `sumSatang` | ไม่มีฟังก์ชันรวมอาร์เรย์ใน production (ใช้ `safeAdd` ทีละตัว) | **ต่างกันที่อินพุตสุดขอบ** (ตัวนี้บวกลอยตัวแล้วตรวจท้ายครั้งเดียว) | **หยุด ไม่แตะ รอเจ้าของ** |
| `localDataAccess` | มี: `chooseDataSource` (ใช้ใน DataSourceGate) | **ต่างกัน** (ผลลัพธ์คนละชุด: `allow/bind/ask/blocked` vs `online/migrate/verify`; userId ว่าง → `blocked` vs โยน error) | **หยุด ไม่แตะ รอเจ้าของ** |

**ตัวอย่างที่ `sumSatang` ต่างจากการรวมด้วย `safeAdd`:** `[9007199254740991, 2, -2]` (ค่าสูงสุดที่ปลอดภัย, +2, −2) → `safeAdd` โยน RangeError ตั้งแต่ขั้นแรกที่เกิน · `sumSatang` ได้ `9007199254740990` เงียบๆ (ถูกต้องคือ `…991`) เพราะบวกลอยตัวเกิน 2^53 กลางทาง (ผมรันตัวเลขนี้จริงแล้ว) ไม่มีงานไหนเรียก `sumSatang` จึงไม่กระทบเงินจริง แต่เป็นของที่ขัดเจตนา R1 ถ้าวันหนึ่งมีคนเรียกใช้

**ที่เอกสารเก่าไม่ตรงความจริง:** `docs/decisions/2026-11-04-bills-safe-to-spend.md` ข้อ 15 เขียนว่าให้ใช้ `outstandingBeforePayday` เป็นทางเดียว แต่ production ไม่ได้ทำตามนั้นแล้ว (ยังไม่แก้เอกสาร รอเจ้าของตัดสินพร้อมเรื่องฟังก์ชัน)
