# แก้เทสต์จริงที่ไม่นิ่ง (สรุปแบบง่าย)

## อาการ
บางรอบชุดทดสอบจริงล้มเอง โดยไม่ได้แก้โค้ด เช่น "มีบิลรหัสนี้อยู่แล้ว", "ล้างข้อมูลผู้ใช้ทดสอบไม่สำเร็จ", "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้" รอบถัดไปผ่านหมด

## สาเหตุที่พบจริง (จากการรันแบบละเอียดและดูข้อผิดพลาด)
1. **เครือข่ายไปยัง Supabase หลุดเป็นระยะ** ทั้งคำขอปกติ (fetch failed) และคำสั่งล้างข้อมูลด้วยสิทธิ์ผู้ดูแล
2. ผลต่อเนื่อง: เมื่อการล้างข้อมูลหรือคำขอของเทสต์หนึ่งล้ม/ค้าง เทสต์ถัดไปที่ใช้รหัสเดิม (ทุกเทสต์ในชุดสัญญาใช้บิลรหัส `bill-1` เหมือนกัน) จึงชนกับข้อมูลหรือคำขอที่ตกค้าง → "มีบิลรหัสนี้อยู่แล้ว"
3. สำคัญ: ไม่ได้เกิดจากกติกาในฐานข้อมูลหรือโค้ดจริงผิดพลาด

## แก้อย่างไร (ไม่ลดความเข้มของเทสต์)
- **ล้างข้อมูลแบบลองใหม่**: การล้างด้วยสิทธิ์ผู้ดูแลลองสูงสุด 4 ครั้งและรายงานสาเหตุจริง (รหัส/ข้อความ) ของตารางที่ล้ม การลบซ้ำปลอดภัย
- **fetch ที่ลองใหม่เฉพาะเมื่อเครือข่ายล้มก่อนได้คำตอบ** และเฉพาะคำสั่งที่ทำซ้ำได้ปลอดภัย (อ่าน/ลบ) **ไม่ลองซ้ำคำสั่งเขียน** เพราะอาจเขียนซ้ำจนรหัสชน ซึ่งเป็นสิ่งที่กำลังกัน
- **รหัสบิลไม่ซ้ำต่อเทสต์** ในชุดสัญญา (ใช้กับทั้งที่เก็บในเครื่องและ Supabase) คำขอค้างของเทสต์ก่อนจึงไม่ชนเทสต์ถัดไป

## ผล
รันชุดทดสอบจริงติดกัน 3 รอบ ผ่านทั้ง 44 ข้อทุกรอบ (ก่อนแก้เคยล้ม 2–3 ข้อในบางรอบ) และ `npm test` 1332 ข้อผ่าน
ข้อจำกัดที่ต้องรู้: ปัญหาเครือข่ายยังเกิดได้ ถ้าเจออีก ข้อความล้มจะบอกสาเหตุและตารางชัดเจนกว่าเดิม
