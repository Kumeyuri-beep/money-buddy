# เว็บให้ฐานข้อมูลตรวจบัญชีก่อนเขียน (28 พ.ย. 2569)

## ปัญหา
เบราว์เซอร์ใช้การเข้าสู่ระบบร่วมกันทุกแท็บ ถ้าแท็บอื่นสลับบัญชีระหว่างที่หน้านี้ "ตรวจบัญชี" กับ "สั่งเขียน" คำสั่งอาจไปลงบัญชีใหม่

## ทำอะไร
- คำสั่งตั้งต้นสมุด นำเข้า ล้างข้อมูล และลบบัญชี เรียกฟังก์ชันชื่อลงท้าย `_as` พร้อมรหัสผู้ใช้ของหน้าจอ
- ฐานข้อมูลเทียบกับผู้ใช้ที่เข้าสู่ระบบจริงในธุรกรรมเดียวกับการเขียน ไม่ตรง = ตอบ `PT412` และคำสั่งนั้นไม่ทำอะไร
- เว็บแปลง `PT412` เป็นข้อความ "บัญชีที่เข้าสู่ระบบเปลี่ยนไป ..." บอกตามจริงว่ายังไม่ได้ทำ หรือทำไปแล้วบางส่วน
- การตรวจฝั่งเว็บเดิมยังอยู่ (บอกผู้ใช้ได้เร็วกว่า) ฐานข้อมูลเป็นด่านที่ไม่มีช่องว่าง

## ยังไม่ครอบ
การบันทึก/แก้/ลบรายการทั่วไป บิล การลงทุน และค่าตั้งค่า ยังไม่ผ่านด่านนี้

## ทดสอบอย่างไร
- `npm test` (ไฟล์ `tests/unit/expectedUserRpc.test.ts`)
- `npm run admin:live-contract` มีข้อ "หน้าจอของ A แต่เซสชันเป็น B" และ "ไฟล์ใหญ่ 1,600 รายการพร้อมค่าตั้งค่า"
- บนคอม: เปิดแอปสองแท็บ แท็บที่สองออกจากระบบแล้วเข้าอีกบัญชี กลับมาแท็บแรกแล้วสั่งล้างข้อมูล ต้องขึ้นว่าบัญชีเปลี่ยนไป ไม่มีอะไรถูกลบ (ใช้บัญชีทดลองเท่านั้น)
