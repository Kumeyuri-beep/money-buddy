# A2: วางรากฐานเงิน USD ในฐานข้อมูล (หุ้นสหรัฐ เฟส A)

## ทำอะไร
- เพิ่ม "ตัวคิดเลข" ภาษา TypeScript สำหรับเงินดอลลาร์ (`src/domain/invest/fx.ts`, `costBasisFx.ts`): แปลงเซนต์ USD เป็นสตางค์ด้วยอัตราแลกเปลี่ยน ปัดเศษครั้งเดียว คิดต้นทุนเฉลี่ย 2 ถัง (ถังดอลลาร์ + ถังบาท) แยกกำไรจากราคาหุ้นกับกำไรจากค่าเงิน
- เพิ่มของใหม่ในฐานข้อมูล (migration แบบ "เพิ่มอย่างเดียว" ไม่ลบ ไม่แก้ของเดิม): คอลัมน์สกุลของสินทรัพย์/ชื่อย่อหุ้น/ตลาด/อัตราของรายการ, ตาราง `fx_rates` (อัตราที่ผู้ใช้บันทึก) กับ `fx_exchanges` (การแลกเงินบาท↔ดอลลาร์), ฟังก์ชัน `record_trade_fx` (ซื้อ/ขาย/ปันผลหุ้น USD) กับ `record_fx_exchange` (แลกเงิน) ที่เขียนสมุดบัญชีคู่ให้สมดุลต่อสกุลในธุรกรรมเดียว
- **ยังไม่มีหน้าจอ** ที่สร้างข้อมูล USD ได้ (หน้าจอเป็นงาน A4) และไฟล์สำรอง/นำเข้ายังไม่รู้จัก USD (งาน A3)

## ทำไม
- เจ้าของอนุมัติกฎ R20 (หลายสกุลเงิน) แล้ว ต้องมีฐานข้อมูลที่ "บังคับกฎได้เอง" ก่อนทำหน้าจอ เพื่อให้แม้เว็บมีบั๊ก ข้อมูลก็ไม่เพี้ยน
- ข้อมูลบาทเดิมต้องไม่เปลี่ยนแม้แต่สตางค์เดียว

## ทดสอบอย่างไร
- เทสต์หน่วย 19 ข้อ: ตัวอย่าง A/B/C ในแผนต้องตรงทุกสตางค์ + ขอบเขต (ยอด 0, น้อยมาก, วันสิ้นเดือน) + สุ่ม 300 ลำดับรายการเช็กว่าต้นทุนรวมสมดุลเสมอ
- เทสต์ SQL ใหม่ `usd_phase_a_test.sql` 16 กลุ่ม (RLS, สิทธิ์ anon, ปฏิเสธรายการผิด, ยอดสมุดต้องตรงรายการ, ล้างข้อมูล/ลบบัญชีล้างตารางใหม่ครบ) และรัน **ครบทั้ง 20 ไฟล์** ใน `supabase/tests/` ให้ขึ้น TESTS_PASSED (เพราะ migration นี้แตะ GRANT/RLS/trigger)
- ก่อนใส่ migration เก็บสแนปช็อตข้อมูลบาทเดิมไว้นอก repo (เฉพาะจำนวนแถว + ค่า hash ไม่มียอดเงิน) หลังใส่เทียบแล้วทุกตาราง "ตรง"
- ชุดทดสอบจริง `admin:live-contract` 60/60 ผ่าน

## ผลตรวจและการแก้ (เพิ่มภายหลัง)
- ผู้ตรวจ 2 คนพบจุดเดียวกัน: การแลกเงินบันทึกไว้ 2 ที่ (ตารางแลกเงิน + สมุดบัญชี) ผู้ใช้แก้ยอดฝั่งสมุดตรงๆ ได้ ทำให้ 2 ที่ไม่ตรงกันและสร้างเงิน USD ขึ้นมาได้ (กระทบแค่ข้อมูลของตัวเอง) จึงเพิ่ม migration ที่สอง ล็อกให้แก้ไม่ได้ ต้องลบรายการแล้วบันทึกใหม่ พร้อมเทสต์
- เพิ่มเทสต์หน่วย 3 ข้อสำหรับกรณีขอบ (ปัดครึ่งติดลบ, ต้นทุนต้องเหลืออย่างน้อย 1, ขอบเลขใหญ่)
- สิ่งที่ยังไม่ทำและต้องทำก่อนมีหน้าจอ USD (งาน A3): ไฟล์สำรอง/นำเข้ารองรับ USD, คำเตือนเมื่อเงินสด USD ติดลบ, ตรวจต้นทุนฝั่งเว็บ
