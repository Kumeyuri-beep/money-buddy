# รหัส error ของด่านจ่ายบิล: 40001 → PT409 (24 พ.ย. 2569)

**ทำอะไร:** เปลี่ยนรหัส error ของ trigger `private.entries_bill_link` ตอนสถานะบิลเปลี่ยนไประหว่างจ่าย (แท็บเก่าจ่ายบิลที่อีกแท็บจ่ายไปแล้ว) จาก `40001` เป็น `PT409` และถอด `'40001'` ออกจากรายการรหัสของเรา (`OWN_CODES`) ฝั่งเว็บ

**ทำไม:** PostgREST ถือว่า 40001 (serialization_failure) ที่เรา raise เองคือ "ลองใหม่ได้" แล้วรันคำสั่งซ้ำเองไปเรื่อยๆ จนค้างราว 60 วินาที ([Supabase KB](https://supabase.com/docs/guides/troubleshooting/high-cpu-and-infinite-transaction-retries-when-using-custom-error-codes-in-rpc-functions-77326b)) รหัสขึ้นต้น `PT` ตอบเป็น HTTP ตามเลขท้ายทันที (PT409 = 409) เคยแก้แล้วกับ `merge_settings_if` และกับ `record_trade`/`record_trade_fx`/`replace_trade` (PR #264) ที่นี่เป็นตัวสุดท้ายที่ค้นเจอในฐานข้อมูลจริง (ตรวจจาก `pg_proc` ทุกฟังก์ชันใน public/private ไม่พบ 40001 หรือ 40P01 ที่เรา raise เองอีก)

**ทดสอบอย่างไร:** `supabase/tests/bill_link_conflict_code_test.sql` (จ่ายด้วย before ไม่ตรง → PT409 และไม่เขียนอะไร · จ่ายปกติยังผ่าน · แท็บเก่าจ่ายรอบก่อนหน้า → PT409 · นิยามฟังก์ชันไม่มี 40001 · trigger ยังชี้ฟังก์ชันเดิม) + `m2g_bill_lock_test.sql` ผ่านทั้งไฟล์ · unit test ล็อกว่า PT409 ส่งข้อความไทยต่อ และ 40001 ไม่ส่ง · live-contract 67/67

**ข้อสังเกต:** การจ่ายรอบเดิมซ้ำจะชนดัชนี `entries_bill_cycle_once_idx` (23505) ก่อนถึง trigger ตามออกแบบ ไม่ใช่ PT409
