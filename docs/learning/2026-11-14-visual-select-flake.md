# ภาพเทียบ VISUAL=1 ไม่นิ่งที่ select เดือน: สาเหตุจริงและวิธีแก้

## อาการ
เครื่องมือเทียบภาพ (`VISUAL=1 npx playwright test visual`) ล้มเป็นบางรอบ (ราว 1 ใน 8-12) ที่หน้าที่มี `<select>` (ภาพรวม รายรับ-รายจ่าย ฯลฯ) โดยต่างกันเฉพาะตัวหนังสือในช่อง select

## หาสาเหตุอย่างไร (ไม่เดา ไม่ใช้ retry)
1. จำลองเครื่องโหลดหนัก (วนลูป CPU 6 ตัวขนานกับเทสต์) จนอาการเกิดซ้ำได้ ~8% ของรอบ แล้วถ่ายภาพซ้ำและเทียบแฮช: ในหนึ่งหน้า ภาพซ้ำกันทุกครั้ง แต่ข้ามการโหลดหน้าให้ผลสองแบบ → ตัดสินตอนโหลดหน้า ไม่ใช่เวลาที่ถ่าย
2. เทียบสองภาพพิกเซลต่อพิกเซล: ต่างเฉพาะ ~1,000 พิกเซลในบริเวณตัวหนังสือของ select ทั้ง 3 ช่อง · ผลรวมความสว่างเท่าเดิม = ตัวหนังสือ**เลื่อนตำแหน่งไม่ถึง 1 พิกเซล** ไม่ใช่หนา/บางลง
3. ตัดสาเหตุทีละข้อ (รันซ้ำ 60 รอบต่อข้อ ภายใต้โหลด):
   - ฟอนต์โหลดไม่ทัน → ตรวจแล้วโหลดครบเสมอ (`document.fonts`) ✗
   - เลย์เอาต์ต่างกัน → ขนาดและตำแหน่งของ select เท่ากันทุกรอบ ✗
   - LCD vs เกรย์สเกล → แฟลก `--disable-lcd-text` ให้ภาพเหมือนเดิมทุกพิกเซล ✗
   - อนิเมชัน (ออโรรา ฯลฯ) → ปิดตั้งแต่เริ่ม ลดเหลือ ~2% แต่ไม่หาย ✗ (ไม่ใช่ต้นเหตุเดียว)
   - blur / ชั้น compositor → ปิด backdrop-filter ทั้งหมด หรือบังคับให้ select แยกชั้น ก็ยังเกิด (บางทีแย่ลง) ✗
   - **การวาด select แบบเนทีฟ** → ใส่ `select { appearance: none }` แล้วภาพ**เหมือนกันทุกรอบ 60/60** (ค่าเดิมผิด 5/60) ✓
4. สรุป: ตัวหนังสือของ `<select>` ที่วาดโดยธีมเนทีฟของเบราว์เซอร์ มีตำแหน่งย่อยพิกเซลไม่แน่นอนตอนเครื่องโหลดหนัก (สาเหตุลึกกว่านั้นอยู่ในโค้ดวาดของ Chromium ผมไม่ได้พิสูจน์ในระดับนั้น พิสูจน์ได้เพียงว่าตัวแปรที่เกี่ยวคือการวาดแบบเนทีฟ)

## วิธีแก้
ที่ตัวเครื่องมือ (`tests/e2e/visual.spec.ts`) ไม่แตะหน้าตาแอปจริง:
- ถ่ายด้วย `select { appearance: none }` (ฐานภาพไม่มีลูกศรเนทีฟของ select · หน้าตาจริงของ select ยังตรวจโดยเทสต์ layout และ contrast)
- ปิดอนิเมชันและทรานซิชันทั้งหมด (รวมพื้นหลังออโรรา) และรอ `document.fonts.ready` + 2 เฟรมก่อนถ่ายทุกภาพ (ตามที่เจ้าของสั่ง)
- **ไม่ใช้** retry หรือเพิ่มค่าคลาดเคลื่อน (`maxDiffPixels` ยัง 0)

## ผลหลังแก้
ภายใต้โหลด CPU หนักเท่ากัน: มืด 120/120 และสว่าง 120/120 ผ่าน (ก่อนแก้ผิดราว 8% ของรอบที่มี select)
