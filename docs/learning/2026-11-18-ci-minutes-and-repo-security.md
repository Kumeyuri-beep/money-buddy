# ลดนาที CI + ตั้งความปลอดภัยของ repo public (18 พ.ย. 2569)

**ตั้งค่า repo (ทำผ่าน `gh api` ไม่มีในโค้ด):** กฎป้องกัน `main` = ห้าม force push · ห้ามลบ branch · ต้องผ่าน PR · ต้องผ่าน check `test` และ `e2e` · ใช้กับแอดมินด้วย (`enforce_admins`) · เปิด secret scanning + push protection · PR จาก fork ต้องรออนุมัติทุกครั้ง (ทุกคนนอกทีม) · สิทธิ์ตั้งต้นของ Actions = อ่านอย่างเดียว

**ตรวจ workflow:** มีไฟล์เดียว (`ci.yml`) ไม่ใช้ `pull_request_target` ไม่มี secrets ไม่มีงานที่ใช้ key (live-contract รันในเครื่องเท่านั้น) · ตั้ง `permissions: contents: read` ชัดเจน · เพิ่มเทสต์กันไม่ให้ใครใส่สิทธิ์เขียน/secrets/live-contract ลง CI โดยไม่ตั้งใจ

**ลดนาที (ข้อ C, D, E ของข้อเสนอ):**
- C: แก้เฉพาะเอกสาร (`docs/`, ไฟล์ `.md` ที่รากโปรเจกต์, `.gitleaksignore`) → ข้าม typecheck/เทสต์/build/e2e แต่ job `test` และ `e2e` ยังรายงาน pass เพื่อให้กติกา merge ใช้ได้เหมือนเดิม (ไม่ใช้ `paths-ignore` เพราะ check จะหาย) · ไม่แน่ใจเรื่องไหน = ถือว่าแก้โค้ดและรันเต็ม
- D: PR เดิม push ซ้ำ → ยกเลิกรอบเก่าที่ยังรัน (เฉพาะ PR · push เข้า main ไม่ยกเลิกกัน)
- E: 5 shard รอ `test` ผ่านก่อน (เทสต์หน่วย/typecheck ล้ม ไม่เปลืองนาทีรัน e2e)
- ไม่เปลี่ยน: จำนวน shard (5) ชุดเทสต์ ชื่อ job ที่คำสั่ง merge ตรวจ

**ทดสอบ:** `ciWorkflow.test.ts` ตรวจโครง workflow + ตัวกรองเอกสาร (ไฟล์อะไรนับเป็นเอกสาร/โค้ด) · ลองตัวกรองกับ 60 merge ล่าสุด: นับเป็นเอกสาร 11 ที่เหลือเป็นโค้ด · ผลจริงของ CI ดูจาก PR ที่เปิด
