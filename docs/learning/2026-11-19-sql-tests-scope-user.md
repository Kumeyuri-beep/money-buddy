# แก้เทสต์ SQL ให้นับเฉพาะผู้ใช้ทดสอบ

**ทำอะไร:** แก้ 4 ไฟล์ใน `supabase/tests/` ให้การนับ/รวมยอดที่รันด้วยสิทธิ์ผู้ดูแล (ข้ามกฎความเป็นส่วนตัวของแถว หรือ RLS) จำกัดเฉพาะผู้ใช้ทดสอบ (`user_id`) แทนที่จะนับทุกคนในฐานข้อมูล

**ทำไม:** เทสต์เดิมสมมติว่าฐานข้อมูลว่าง ตอนนี้ฐานข้อมูลมีข้อมูลผู้ใช้จริงแล้ว จึงมีข้อที่ล้ม (`usd_fx_entry_lock_test` ข้อ T5 นับ `fx_exchanges` ทั้งตาราง) และบางข้อเสี่ยงไปหยิบข้อมูลของผู้ใช้จริง (`invest_schema_test` ดึง `user_id` จาก `assets where id = 'a1' limit 1`) ตรวจแล้วระบบทำงานถูกต้อง ปัญหาอยู่ที่ขอบเขตการนับในเทสต์เท่านั้น

**ข้อกำหนดที่ถือ (เจ้าของสั่ง 19 พ.ย. 2569):** แก้เฉพาะไฟล์เทสต์ ไม่แตะ schema/function/migration · ไม่ลด assertion ไม่ลบข้อตรวจ ไม่เปลี่ยนค่าที่คาดหวัง เปลี่ยนแค่ขอบเขตการนับ · ทุกไฟล์ยัง rollback ไม่ทิ้งข้อมูล

**แก้ไฟล์ไหน บรรทัดไหน**
- `invest_ledger_test.sql` บรรทัด 161, 187: เพิ่ม `and user_id = ua` ในการนับ `trades`/`lines`/`assets`
- `invest_schema_test.sql` บรรทัด 245, 247, 251, 252: ดึง/กรอง `user_id` เฉพาะ `b-inv@...` (ผู้ใช้ทดสอบ B)
- `usd_fx_entry_lock_test.sql` บรรทัด 82, 118: นับ `fx_exchanges`/`trades`/`fx_rates`/`entries`/`lines` เฉพาะ `user_id` ทดสอบ
- `usd_phase_a_test.sql` บรรทัด 174, 204, 206, 207, 218: นับบัญชี `inv-gain-usd`, ยอดเงินสด USD, ยอดสมดุล USD/THB, นับ `trades`/`fx_exchanges` เฉพาะ `ua`

**ทดสอบอย่างไร:** รันทั้ง 24 ไฟล์ใน `supabase/tests/` (บวก `cash_adjustment_test.sql` ที่ยังอยู่ใน branch อื่น) กับฐานข้อมูลจริง ทุกไฟล์ขึ้น `TESTS_PASSED` และ rollback ไม่เหลือข้อมูลทดสอบ จำนวนแถวของผู้ใช้จริงก่อนและหลังเท่าเดิม
