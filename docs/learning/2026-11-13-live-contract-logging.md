# ทำให้ชุดทดสอบจริง (live-contract) วินิจฉัยได้ และนิ่งขึ้น

**ปัญหา:** `admin:live-contract` ล้มเป็นบางครั้งแล้วรันซ้ำผ่าน และบางรอบช้าผิดปกติ (205-226 วินาที จากปกติราว 100-150) แต่ไม่รู้ว่าข้อไหนล้มเพราะอะไร เพราะข้อความ error ถูกทิ้ง

**ทำอะไร**
1. **log เต็มทุกครั้ง** ที่ `.live-logs/live-<เวลา>.log` (อยู่ใน `.gitignore` ไม่เข้า git): ชื่อทุกข้อ ผล เวลาเป็นมิลลิวินาที ข้อความ error เต็ม 10 ข้อที่ช้าที่สุด ปิดบัง key/JWT/token/URL ตามรูปแบบ และซ่อนข้อมูลในวงเล็บของข้อความ assertion (กันแถวข้อมูลจริงหลุดถ้า RLS พัง) · เป็นการจับรูปแบบ จึง **ก่อนแนบ log ให้ผู้ช่วยต้องเปิดอ่านส่วน FAIL เองก่อน** · เก็บ 30 ไฟล์ล่าสุด
2. **บันทึกคำขอที่ช้า/ล้ม** ที่ `.live-logs/live-requests.log` (เฉพาะวิธี + พาธ + เวลา + ผล ไม่มี host/query/header/body)
3. **ข้อความ error ของการล็อกอินครบ** (สถานะ + รหัส + ข้อความ) แทนที่จะเป็นแค่ "ล็อกอินไม่สำเร็จ"
4. **คำขอที่ทำซ้ำได้ปลอดภัย (GET/HEAD/DELETE) มีเพดานเวลา 20 วินาที** ค้างเกินก็ตัดแล้วลองใหม่ (เดิมรอจนข้อทดสอบหมดเวลา) · POST/PATCH/PUT ไม่ตัดเพราะไม่รู้ว่าเซิร์ฟเวอร์ทำไปแล้วหรือยัง
5. **ลดรอบเครือข่ายต่อเนื่อง** ของข้อ RLS ที่ยาวที่สุด (ส่งคำขอที่ไม่ขึ้นต่อกันพร้อมกัน) ผลที่ตรวจเหมือนเดิมทุกข้อ

**หาสาเหตุได้แค่ไหน:** ข้อ "ผ่าน REST ตรง" ของพอร์ตลงทุนใช้เวลา 57.6 วินาทีในรอบที่ช้า (ปกติ 8) ใกล้เพดานของข้อทดสอบ 60 วินาที แปลว่าคำขอเดียวค้างราว 50 วินาทีโดยไม่ error · รอบที่ล้ม ล้มที่ขั้นล็อกอินก่อนเริ่มข้อทดสอบ (ไม่ทราบรหัส error เพราะถูกทิ้ง) · รัน 7 รอบหลังเพิ่ม log ผ่านหมด (56/56) และไม่พบคำขอใดช้าเกิน 3 วินาทีเลยหลังเพิ่มตัวบันทึก **จึงยังไม่ได้พิสูจน์สาเหตุรากของอาการค้าง** (เชื่อว่าเป็นเครือข่ายช้าชั่วคราว) แต่รอบหน้าที่เกิดอีกจะรู้ทันทีว่าคำขอไหนและ error อะไร

**กติกาใหม่:** ถ้า live-contract ล้มแล้วรันซ้ำผ่าน ต้องจดชื่อข้อที่ล้มใน HANDOFF ทุกครั้ง (ไฟล์ log ช่วยให้รู้ชื่อข้อ)
