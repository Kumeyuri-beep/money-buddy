# คำสั่ง admin:sql-tests รันเทสต์ SQL ครบทุกไฟล์

## ทำอะไร
`MONEY_BUDDY_SQL_TESTS=yes npm run admin:sql-tests` อ่านไฟล์ใน `supabase/tests/` แล้วรันกับฐานข้อมูลจริงทีละไฟล์ แต่ละไฟล์อยู่ในธุรกรรมของตัวเองและ **ยกเลิก (ROLLBACK) ทุกครั้ง** สรุปว่าไฟล์ไหน TESTS_PASSED หรือล้ม

## ทำไม
เดิมต้องคัดลอกไฟล์ไปรันทีละไฟล์ (ราว 540 KB) ช้าและคัดลอกพลาดได้

## กันข้อมูลค้างอย่างไร (แก้หลังผู้ตรวจความปลอดภัยไม่ผ่านรอบแรก)
รอบแรกใช้ตัวอ่านข้อความหา COMMIT อย่างเดียว ซึ่งอ่านต่างจากฐานข้อมูลและเลี่ยงได้ ตอนนี้มีหลายชั้น
1. **ฐานข้อมูลปฏิเสธเอง:** ส่งทั้งไฟล์ให้รันด้วย `execute` ในบล็อกเดียว Postgres ไม่ยอมให้ COMMIT/ROLLBACK จากข้างในบล็อก
2. ตั้งจุดพัก (savepoint) ก่อนรัน หลังรันต้องย้อนกลับถึงได้ แปลว่ายังอยู่ในธุรกรรมเดิม ถ้าไม่ได้ให้หยุดทันที
3. **พิสูจน์ก่อนรันทุกครั้ง:** สคริปต์สร้าง temp table แล้วสั่ง COMMIT / END / ROLLBACK จริง ฐานข้อมูลต้องปฏิเสธ ไม่งั้นไม่รันไฟล์ใดเลย
4. ด่านอ่านข้อความ (ชั้นเสริม): ห้าม COMMIT และคำสั่งที่มีผลนอกธุรกรรม เช่น `dblink`, `create extension`, `create server`, `copy`, `setval` และไม่รันถ้าฐานข้อมูลมีส่วนขยายประเภทนั้นติดตั้งอยู่
5. หลังรันเทียบจำนวนแถวและโครงสร้าง (ฟังก์ชัน policy สิทธิ์ trigger ฯลฯ) กับก่อนรัน เป็นการตรวจเสริม จับการแก้ค่าในแถวเดิมไม่ได้

**ข้อจำกัด:** ด่านข้อที่ 4 จับจากข้อความ คนที่ตั้งใจเขียนซ่อนยังเลี่ยงได้ จึงต้องรันเฉพาะไฟล์เทสต์ของโปรเจกต์ที่ตรวจแล้ว (ห้ามรันไฟล์จาก PR ของคนนอก)

## ความลับ
- ค่าเชื่อมต่ออยู่นอกโปรเจกต์ (`admin.env`) ต้องเป็นโปรเจกต์เดียวกับ `SUPABASE_URL` · สคริปต์นี้ไม่โหลดกุญแจผู้ดูแล (service role) ไปใช้
- ไม่พิมพ์ค่าเชื่อมต่อ/รหัสผ่าน · ข้อความ error จากฐานข้อมูลพิมพ์เฉพาะข้อความของไฟล์เทสต์ (`FAIL…`) นอกนั้นพิมพ์แค่รหัส · ตรวจใบรับรอง SSL เสมอ

## ตั้งค่าครั้งเดียว (เจ้าของทำเอง)
1. Supabase Dashboard → ปุ่ม **Connect** → **Session pooler** → คัดลอก URI (ขึ้นต้น `postgresql://postgres.<รหัสโปรเจกต์>:[YOUR-PASSWORD]@...pooler.supabase.com:5432/postgres`)
2. แทน `[YOUR-PASSWORD]` ด้วยรหัสผ่านฐานข้อมูล (อักขระพิเศษต้องเข้ารหัส: `@` = `%40`, `#` = `%23`, `/` = `%2F`, `:` = `%3A`, `?` = `%3F`, `%` = `%25`)
3. เปิดไฟล์ `admin.env` ในโฟลเดอร์ `.money-buddy-admin` ใต้โฟลเดอร์ผู้ใช้ แล้วเพิ่มบรรทัด `SUPABASE_DB_URL=...`
4. Database Settings → **SSL Configuration** → ดาวน์โหลดใบรับรอง บันทึกชื่อ `supabase-ca.crt` ไว้ในโฟลเดอร์เดียวกัน

## ทดสอบอย่างไร
- unit `tests/unit/sqlTests.test.ts` (ด่านปฏิเสธไฟล์ · ลำดับคำสั่งและ ROLLBACK · ข้อพิสูจน์ · ตรวจ URL · ปิดบังความลับ) ใช้ฐานข้อมูลปลอม
- ยังไม่ได้รันกับฐานข้อมูลจริง รอบแรกให้ใช้ `-- --prove-only` ก่อน
