# ลบ 3 ฟังก์ชันที่เจ้าของตัดสิน (outstandingBeforePayday, sumSatang, localDataAccess)

**1) `outstandingBeforePayday`** — ลบแล้ว เทสต์กรณีปกติทั้ง 14 เคสย้ายไปตรวจตัวที่ production ใช้จริง (`buildSafeToSpend` + `buildUpcomingPanel`) โดยตัวเลขที่ตรวจเท่าเดิม (วันเงินเดือนถัดไป รายการ ยอดรวม overdue cycleMonth) และเคส "ครบวงจร" เข้มขึ้น (ตรวจ available/daysLeft/perDay/outstanding/reserve ผ่านการ์ดจริง)
- **ตรวจบิลเสียตามที่สั่ง:** บิลที่ข้อมูลเสีย (ยอด 0/ติดลบ/ทศนิยม, วันครบกำหนด 32, รอบจ่ายผิดรูป) ถูกข้ามและนับเป็น "มีบิล N ใบข้อมูลผิด" ที่การ์ดและแผงบิล ไม่ทำให้หน้าพัง · ยอดค้างนับเฉพาะบิลที่ถูกต้อง
- **ช่องโหว่ที่พบตอนย้ายเทสต์ (แก้แล้ว):** `buildUpcomingPanel` อ่านรายการบิลก่อนเข้า `try` ถ้ารายการมีค่าผิดชนิด (เช่น `null`) จะโยน `TypeError` ทั้งหน้าพัง · ย้ายเข้า `try` แล้ว ได้ข้อความภาษาคน ("คำนวณไม่สำเร็จ ตรวจข้อมูลบิลและค่าตั้งค่า") (ในทางปฏิบัติข้อมูลจากฐานข้อมูลไม่ควรเป็น null แต่ป้องกันไว้)
- **ข้อความผิดพลาดผ่าน `friendlyError`:** `errorMessage` ใน `billsOverview.ts` เดิมใช้ข้อความดิบของ RangeError (เช่น "ยอดรวมบิลใหญ่เกินช่วงที่คำนวณได้อย่างปลอดภัย") ตอนนี้ใช้ `friendlyError` ตัวเดียวกับทั้งแอป → RangeError ทุกชนิดแสดงว่า "ตัวเลขใหญ่เกินไปหรือไม่ถูกต้อง ตรวจจำนวนเงินอีกครั้ง…" (ทั่วไปกว่าเดิมเล็กน้อย แลกกับความสม่ำเสมอ) · ข้อผิดพลาดอื่นใช้ข้อความ "คำนวณไม่สำเร็จ ตรวจข้อมูลบิลและค่าตั้งค่า" เหมือนเดิม
- แก้เอกสารตัดสินใจ 2 ไฟล์ที่อ้างถึงฟังก์ชันนี้

**2) `sumSatang`** — ลบพร้อมเทสต์ (production ใช้ `safeAdd` ทีละตัวอยู่แล้ว) · เจตนา R1 "ไม่มีเศษทศนิยม" ยังมีเทสต์ครอบหลายข้อ และเพิ่มเทสต์ "0.1 + 0.2 บาท = 30 สตางค์เป๊ะ" ผ่าน `safeAdd` ที่ production ใช้ (money-auditor ชี้ว่าความครอบคลุมนี้เคยขาดไป)

**3) `localDataAccess`** — ลบทั้งไฟล์ `src/app/localOwner.ts` พร้อมเทสต์ · `chooseDataSource` ที่ใช้จริงเข้มกว่า (เจ้าของว่าง/คนอื่น → ไม่เสนอข้อมูลเดิมให้ใคร) และมีเทสต์ใน `dataSource.test.ts` ครอบเจตนาเดิม ไม่เปิดช่องข้อมูลรั่วข้ามผู้ใช้ (`storage/localOwner.ts` ที่ใช้ `getLocalOwner` เป็นไฟล์คนละตัว ยังอยู่)

**ความพลาดของผู้ช่วยที่ money-auditor จับได้:** ตอนย้ายเทสต์ผมแทนที่ไฟล์ตั้งแต่กลุ่มเก่าไปจนท้ายไฟล์ ทำให้เทสต์ 4 กลุ่มที่ไม่เกี่ยวข้อง (`addDays`, ปีนอกช่วง 1000-9999, `nextPayday` ก.พ., `computeSafeToSpend -0`) หายไปจากไฟล์ `billsAudit.test.ts` · กู้คืนครบจาก `main` แล้ว (49 เทสต์ในไฟล์ จาก 40 ที่หายไป 9) และตรวจ diff ของเทสต์ทั้งหมดว่าที่ถูกลบมีเฉพาะที่ตั้งใจ
