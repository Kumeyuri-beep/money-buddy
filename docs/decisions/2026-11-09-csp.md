# CSP และส่วนหัวความปลอดภัย (9 พ.ย. 2569)

เจ้าของสั่ง: ทำ CSP ก่อนเชิญผู้ใช้จริง (เป้าหมาย: กัน XSS ซึ่งเป็นทางขโมย session ใน localStorage — ความเสี่ยงที่เจ้าของรับไว้ตอน M2-B)

## นโยบาย (ตั้งใน `vercel.json` ใช้กับทุกเส้นทาง)
| คำสั่ง | ค่า | เหตุผล |
|---|---|---|
| `default-src` | `'none'` | ปฏิเสธทุกอย่างที่ไม่ได้ระบุ |
| `script-src` | `'self' 'wasm-unsafe-eval'` | สคริปต์จากโดเมนเองเท่านั้น ไม่มี inline/eval · `wasm-unsafe-eval` เฉพาะ WebAssembly ของตัวอ่านสลิป (tesseract) |
| `worker-src` | `'self' blob:` | tesseract สร้าง Web Worker (blob) แล้ว importScripts ไฟล์ในโดเมนเอง |
| `style-src` | `'self' https://fonts.googleapis.com` | ไฟล์ CSS ของแอป + CSS ฟอนต์ Google (React ตั้งสไตล์ผ่าน CSSOM ไม่ต้อง `'unsafe-inline'`) |
| `font-src` | `https://fonts.gstatic.com` | ไฟล์ฟอนต์ |
| `img-src` | `'self' data: blob:` | ไอคอน/รูปในแอป และรูปสลิปที่ประมวลผลในเครื่อง |
| `connect-src` | `'self' https://otndefvbosbunonmmuwn.supabase.co` | เรียกเครือข่ายได้เฉพาะโดเมนเอง (ไฟล์ OCR) และ Supabase ของโปรเจกต์นี้ (ไม่ใช้ wildcard) |
| `manifest-src` | `'self'` | |
| `object-src` / `base-uri` | `'none'` | |
| `form-action` | `'self'` | |
| `frame-ancestors` | `'none'` | กันถูกฝังในเว็บอื่น (clickjacking) |
ส่วนหัวอื่น: `Cross-Origin-Opener-Policy: same-origin` (ห้ามใส่ COEP require-corp เพราะบล็อกฟอนต์ Google), `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy` ปิดกล้อง/ไมค์/ตำแหน่ง/จ่ายเงิน/USB (แอปเลือกรูปด้วยตัวเลือกไฟล์ ไม่ใช้กล้อง)

## เทสต์ (`tests/unit/securityHeaders.test.ts`)
นโยบายไม่มี `'unsafe-inline'`/`'unsafe-eval'`/wildcard/http ใน script-src · `connect-src` มีแค่โดเมนเองกับ Supabase ของโปรเจกต์ · index.html ไม่มี inline script/style/on*= · ทุกโดเมนภายนอกใน index.html อยู่ใน CSP · โค้ดไม่ใช้ eval/new Function/innerHTML/dangerouslySetInnerHTML

## ผลตรวจ security-auditor (ผ่านแบบมีข้อแนะนำ · อ่านจากโค้ดจริง ไม่ได้ลองในเบราว์เซอร์)
- ไม่พบฟีเจอร์ที่จะพังเงียบๆ: supabase-js (auth/rest/rpc ไป Supabase ตัวเดียว ไม่มี realtime/storage), tesseract (blob worker + wasm + ไฟล์ภาษาในโดเมนเอง), Google Fonts, ดาวน์โหลดไฟล์ด้วย Blob (CSP ไม่บล็อก)
- รับ: เพิ่ม COOP, หน่วง `revokeObjectURL` 10 วินาทีหลังดาวน์โหลด (กันดาวน์โหลดล้มบางเบราว์เซอร์)
- **ยังไม่รัด (ตั้งใจ ทำหลังเจ้าของลอง Preview):** `img-src` เหลือ `'self'`, `form-action 'none'`, `workerBlobURL:false` + `worker-src 'self'`, ตัด `manifest-src` — ทดสอบในเบราว์เซอร์จริงไม่ได้ จึงไม่รัดโดยไม่มีข้อมูล · Trusted Types ไม่ใส่ (React/tesseract อาจพัง)
- **โดเมน Supabase เขียนตายตัวใน `vercel.json`** ถ้า Preview ตั้ง `VITE_SUPABASE_URL` เป็นโปรเจกต์อื่น ล็อกอินบน Preview จะพัง (Vercel → Settings → Environment Variables ต้องชี้โปรเจกต์เดียวกัน) · เทสต์ใน `securityHeaders.test.ts` ผูกกับโดเมนนี้ด้วย
- Vercel Toolbar/Comments บน Preview โหลดสคริปต์จาก `vercel.live` ซึ่งถูกบล็อก (toolbar ไม่ขึ้น แอปไม่พัง)
- เทสต์ "ไม่มีเครือข่ายไปโดเมนอื่น" ตรวจเฉพาะ URL ที่เขียนตรงๆ ใน `src/` จับ URL ที่สร้างตอนรันไม่ได้ (เช่น ค่าเริ่มต้น CDN ของ tesseract ซึ่งถูกทับด้วยพาธในโดเมนเองแล้ว) อย่าถือว่าครอบคลุมทั้งหมด

## ข้อจำกัดที่ต้องรู้
- **ผมทดสอบ CSP ในเบราว์เซอร์จริงไม่ได้** (ไม่มีเบราว์เซอร์) นโยบายนี้อ่านจากโค้ดและไฟล์ที่ build ไม่ได้รันจริง จึง **ต้องให้เจ้าของลองบน Vercel Preview ก่อน merge**: ล็อกอิน · เปิดแต่ละหน้า (ฟอนต์ไทยขึ้นไหม) · สแกนสลิป (OCR) · ดาวน์โหลดข้อมูลของฉัน · เปิดคอนโซลเบราว์เซอร์ (F12) ดูว่ามีข้อความ "Refused to ..." ไหม
- ถ้า CSP ทำให้ฟีเจอร์พัง ให้ส่งข้อความ "Refused to ..." มา (ระบุคำสั่งที่ถูกบล็อก) ผมจะเปิดเฉพาะที่จำเป็น หรือย้อนกลับโดยลบบล็อก `headers` ออกจาก `vercel.json`
- CSP กันการฉีดสคริปต์ แต่ไม่กันคนที่ได้ session ไปแล้วด้วยวิธีอื่น (เครื่องถูกเข้าถึง, มัลแวร์) · cooldown 24 ชม. หลังเปลี่ยนรหัสเป็นอีกชั้น
- Vercel ใส่ HSTS ให้เองบนโดเมน `*.vercel.app` และโดเมนที่ตั้งเอง (ยืนยันด้วยตา: ดูส่วนหัว Strict-Transport-Security ใน DevTools → Network)
