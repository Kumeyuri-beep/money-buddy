# M2-B1: ล็อกอินฝั่งเว็บ (8 พ.ย. 2569)

แผน `docs/plans/2026-11-08-m2-b1-login.md` · ต่อจาก `2026-11-04-m2-auth.md` และ `2026-11-08-m2-a.md`

| # | เรื่อง | ตัดสินใจ |
|---|---|---|
| 1 | แพ็กเกจ | เพิ่ม `@supabase/supabase-js` ปักเวอร์ชันตรง (`2.119.0`) เป็นการ์ด dependency เดียวของ M2-B |
| 2 | ด่านหน้า | `AuthGate` ครอบทั้งแอปใน `main.tsx` (ใต้ `ErrorBoundary`) · สถานะ: กำลังตรวจ / ไม่ได้ตั้งค่า / ไม่ล็อกอิน / ต้องเปลี่ยนรหัส / บัญชีไม่พร้อม / โหลดไม่ได้ / พร้อม · หน้าจอเป็นแค่การแสดงผลที่ถูกต้อง **ด่านจริงคือ RLS** (ธง `must_change_password` ในตาราง `profiles`) |
| 3 | ปิดไว้ก่อน | ไม่มีแถว `profiles` หรือค่าธงไม่ใช่ boolean → "บัญชีไม่พร้อม" ไม่ใช่ "พร้อม" (เทียบกับ `private.can_use_data()` ฝั่งฐานข้อมูล) |
| 4 | ล็อกอินผิด | ข้อความเดียวกันทุกกรณี (ไม่มีผู้ใช้ / รหัสผิด / ยังไม่ยืนยัน / ชื่อผิดรูปแบบ) · เฉพาะ rate limit, เครือข่าย, เซิร์ฟเวอร์ล่ม ที่แยกข้อความ · ไม่ส่งรายละเอียด error ของเซิร์ฟเวอร์ให้ผู้ใช้ |
| 5 | เปลี่ยนรหัส | ตรวจรหัสใหม่ก่อนยิงเน็ต (≥ 10 ตัว, ≤ 72 ไบต์ เพราะ bcrypt ตัดส่วนเกินเงียบๆ, ไม่เท่ากับ username, ไม่ใช่รหัสยอดนิยม/ซ้ำตัวเดียว/เรียงลำดับ) → ยืนยันรหัสเดิมด้วยการล็อกอินซ้ำ → `updateUser` · Supabase แพ็กเกจฟรีไม่มีตัวตรวจรหัสรั่ว จึงตรวจเองฝั่งเว็บ (ข้ามได้ถ้าเรียก API ตรง ระบุในแผนข้อ 4.6 แล้ว) |
| 6 | ออกจากระบบ | `signOut({ scope: 'local' })` ไม่เตะเครื่องอื่นของผู้ใช้ออก |
| 7 | เมนู | เปิดรายการ "โปรไฟล์" (เดิม "เร็วๆ นี้") เป็นหน้าชื่อผู้ใช้ + เปลี่ยนรหัส + ออกจากระบบ · การ์ดโปรไฟล์ในแถบข้างแสดงชื่อผู้ใช้ |
| 8 | โดเมนอีเมลภายใน | ค่าคงที่ `AUTH_EMAIL_DOMAIN` ตัวเดียว (`users.money-buddy.internal`) **ยังไม่ยืนยันกับ GoTrue จริง** → spike ใน B2 (ต้องใช้ `admin.env`) |
| 9 | **ความเสี่ยงที่รู้ (ส่งต่อ M2-C)** | ข้อมูลยังอยู่ใน Dexie ในเครื่อง (ฐาน `money-buddy` ชื่อเดียว) **ยังไม่ผูกกับผู้ใช้**: ผู้ใช้หลายคนที่ใช้เบราว์เซอร์/เครื่องเดียวกันจะเห็นข้อมูลชุดเดียวกัน และหลังออกจากระบบข้อมูลยังอยู่ในเครื่อง · ยอมรับชั่วคราวเพราะแต่ละคนใช้เครื่องตัวเอง และ M2-C ย้ายข้อมูลขึ้นฐานข้อมูล (แยกตามผู้ใช้ด้วย RLS) · ถ้าจะใช้เครื่องร่วมก่อนนั้น ต้องทำชื่อฐาน Dexie ต่อผู้ใช้หรือล้างข้อมูลตอนออกจากระบบ (รอเจ้าของ) |
| 10 | เทสต์ป้องกัน key (B2) | bundle ของ `supabase-js` มีสตริง `sb_secret_` อยู่เองในโค้ดตรวจ prefix → เทสต์ใน B2 ต้องตรวจ **รูปแบบ key จริง** (`sb_secret_` ตามด้วยอักขระ key ยาว, JWT ที่ payload มี role เป็นระดับผู้ดูแล) ไม่ใช่แค่คำ |

## ผลตรวจ security-auditor / design-critic และสิ่งที่แก้ใน B1

| # | ข้อพบ | ตัดสินใจ |
|---|---|---|
| 11 | ข้อมูล Dexie ไม่ผูกกับผู้ใช้ (ข้อ 9 เดิม) | **แก้ระดับหน้าจอ:** `LocalDataGate` + `localDataAccess` — ผูกข้อมูลในเบราว์เซอร์นี้กับบัญชีเดียว (`meta.ownerUserId`) · ฐานว่าง = ผูกให้อัตโนมัติ · มีข้อมูลเดิมแต่ยังไม่ผูก = ถามก่อน (ไม่ลบ/แก้ข้อมูล) · เป็นของบัญชีอื่น = ไม่แสดง · `resetAll` ล้าง meta จึงผูกใหม่ได้ · **กัน DevTools ไม่ได้** ทางแก้จริงคือ M2-C · หน้าโปรไฟล์เตือนไม่ให้ใช้เครื่องร่วมกัน |
| 12 | เปลี่ยนรหัสแล้ว session อื่นค้าง | `changePassword` เรียก `signOut({ scope: 'others' })` หลัง `updateUser` สำเร็จ (ล้มเหลวไม่ทำให้การเปลี่ยนรหัสล้ม) |
| 13 | AuthGate ฟังแค่ SIGNED_OUT / ผลช้าเขียนทับ | ตัวนับรุ่น (ผลล่าสุดชนะ) · ตรวจซ้ำเมื่อ SIGNED_IN, TOKEN_REFRESHED, USER_UPDATED (รวมจากแท็บอื่น และตรวจธงซ้ำทุกครั้งที่ต่ออายุ token) · เปลี่ยนผู้ใช้ = ทิ้ง state ทั้งแอป (`key={userId}`) |
| 14 | เทสต์กัน key/สมัครเอง | `tests/unit/secretsGuard.test.ts` (ค้นซอร์สจริง): ไม่มีชื่อ/ค่า key ระดับผู้ดูแล, ไม่เรียกฟังก์ชันสมัคร/สร้างผู้ใช้/anonymous/OTP/OAuth/ลืมรหัสทางอีเมล, ใช้ `VITE_*` แค่ 2 ตัว, `vite.config.ts` ไม่มี `envPrefix`/`loadEnv`/`process.env` · ตรวจ `dist/` และสคริปต์อยู่ใน B2 |
| 15 | ชื่อผู้ใช้ Unicode ชนกับ ASCII (U+212A → k) | `usernameToEmail` ปฏิเสธอักขระที่ไม่ใช่ ASCII ก่อนแปลงตัวพิมพ์เล็ก · สคริปต์ B2 ต้องใช้ฟังก์ชันตัวเดียวกัน |
| 16 | รหัสผ่านมีชื่อผู้ใช้อยู่ข้างใน | ปฏิเสธเมื่อชื่อ ≥ 4 ตัวอยู่ในรหัส |
| 17 | หน้าจอ (design-critic) | ปุ่มแสดง/ซ่อนรหัสผ่านทุกช่อง · โฟกัสกลับช่องที่ต้องแก้เมื่อ error · ช่อง `role=alert` ไม่ถูกซ่อน (อ่านออกเสียงได้) · ข้อความยืนยันเมื่อเปลี่ยนรหัสสำเร็จ · หน้าไม่พร้อม/ไม่ได้ตั้งค่าไม่เปิดเผยชื่อตัวแปร · ข้อความติดต่อผู้ดูแลชัดขึ้น · หน้าโปรไฟล์ใช้ h2 (h1 อยู่ที่หัวหน้า) · ซ่อนช่องชื่อผู้ใช้ให้โปรแกรมจัดการรหัสผ่าน |
| 18 | **รอเจ้าของ** | (ก) ตั้งใน Dashboard: รหัสผ่านขั้นต่ำ 10 (เจ้าของแจ้งว่าตั้งแล้ว) เพราะการตรวจฝั่งเว็บข้ามได้ถ้าเรียก API ตรง · (ข) session เก็บใน `localStorage` ถาวร (`persistSession: true`): ลืมออกจากระบบบนเครื่องร่วม คนต่อไปเข้าได้ · ทางเลือก: `sessionStorage` (ออกเมื่อปิดแท็บ) หรือหมดอายุเมื่อไม่ใช้นาน → ตอนนี้คงเดิม · (ค) เพิ่ม CSP ตอน deploy (งานแยก) |
