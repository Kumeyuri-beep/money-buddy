# M2-C2: แก้ผลชุดทดสอบจริงรอบแรก (9 พ.ย. 2569)

ผลที่เจ้าของรัน: 10 ล้ม / 5 ผ่าน / 6 ข้าม + "ลบผู้ใช้ทดสอบไม่สำเร็จ (500)"

## 1. ล้ม 10 ข้อ = ชนเพดานลองรหัสของ `reset_my_ledger`
ชุดทดสอบเรียก `resetAll` ทุกข้อ ชน 5 ครั้ง/15 นาที (ทำงานถูกต้องตามที่ออกแบบ) · **ไม่ลด/ปิด rate limit** · แก้ที่ชุดทดสอบ: ล้างข้อมูลก่อนแต่ละข้อด้วยสิทธิ์ผู้ดูแล (service_role ลบแถวของผู้ใช้ทดสอบ) เฉพาะในชุดทดสอบ · เรียก `resetAll` จริงเพียง 2 ครั้งต่อรอบ (เทสต์สัญญา "ส่งออก/ล้าง" และเทสต์แยกผู้ใช้ "ล้างของ B ไม่กระทบ A") เพื่อทดสอบเส้นทางนั้นเอง

## 2. ลบผู้ใช้ที่มีข้อมูลไม่ได้ (500) = บั๊กจริงของ M2-A
- ต้นเหตุ (ยืนยันจาก log Postgres "permission denied for schema private" และจำลองซ้ำด้วย service_role): ลบ `auth.users` cascade ลบ `entries/lines` → constraint trigger ตรวจสมดุล (SECURITY INVOKER) ทำงานด้วยสิทธิ์ผู้ลบ (`supabase_auth_admin`) ที่ไม่มีสิทธิ์ใช้ schema `private`
- กระทบ: การลบผู้ใช้ที่มีข้อมูลผ่าน Auth Admin API และ Dashboard (ไม่กระทบ `delete_my_account` เพราะเป็น SECURITY DEFINER) · ที่ spike รอบก่อนผ่านเพราะผู้ใช้ spike ไม่มีข้อมูล
- แก้รอบแรก: migration `20261108000700` ให้ trigger ข้ามการตรวจเมื่อ "ลบ" โดยบทบาทระบบ → **security-auditor ชี้ว่ากว้างเกิน** (service_role ลบบรรทัดเดียวของ Entry ให้ไม่สมดุลได้เงียบๆ ละเมิด R16)
- **แก้ที่ต้นเหตุ:** migration `20261108000800` เปลี่ยน `private.check_entry_balance` เป็น `SECURITY DEFINER` (search_path ว่าง, อ่านอย่างเดียว, ใช้ user_id จากแถวเอง) → ตัวลบไม่ต้องมีสิทธิ์ใน schema `private` และ **ไม่มีบทบาทใดข้ามการตรวจสมดุล** (0800 แทนที่ฟังก์ชันของ 0700 ทั้งหมด · ไฟล์ 0700 เก็บไว้เป็นประวัติเพราะใส่ลงฐานข้อมูลไปแล้ว)
- เทสต์ `supabase/tests/m2c_admin_delete_test.sql` TESTS_PASSED: ผู้ใช้ทั่วไปยังถูกตรวจ · service_role ลบบรรทัดเดียวให้ไม่สมดุลไม่ได้ · service_role ลบทั้ง Entry/บิล/บัญชีได้
- ใส่ลงฐานข้อมูลจริงแล้ว (เจ้าของอนุมัติ) · ลบผู้ใช้ `livetest-79f4c4fe-a` ที่ค้างแล้ว (ไม่มีผู้ใช้ทดสอบเหลือ)
- `globalSetup` ตอนปิดงาน: ลบผู้ใช้ทดสอบไม่สำเร็จ = ทำให้การรันล้ม (ไม่ใช่แค่พิมพ์เตือน)

## 3. 6 ข้อที่ถูกข้าม
คือ 6 ข้อของ "แยกข้อมูลระหว่างผู้ใช้ (RLS)" ทั้งหมด: `beforeAll` ล้ม (ชน rate limit ที่ `resetAll`) vitest จึงข้ามทั้งกลุ่ม · แก้แล้วโดยไม่ใช้ `resetAll` ใน `beforeAll` จะรันจริง

## ข้อสังเกต
- spike เดิมไม่เคยทดสอบลบผู้ใช้ที่มีข้อมูล → ชุดจริงนี้จับได้ ควรคง `admin:live-contract` ไว้รันก่อนเชิญผู้ใช้จริงและหลังทุก migration
