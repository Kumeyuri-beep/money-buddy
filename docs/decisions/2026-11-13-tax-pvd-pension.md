## สิ่งที่ตัดสินใจ (ต้องการให้เจ้าของยืนยัน)
1. **ลำดับกลุ่มเกษียณ: กองทุนสำรองเลี้ยงชีพ → RMF → ประกันบำนาญ** (เพดานกลุ่มชนก่อน ตัดตามลำดับคงที่ ตาม R19) · เหตุผล: เอกสารเรียง PVD ก่อน และเป็นเงินที่หักจากเงินเดือนตรง · เอกสารตัวอย่างแบ่งต่างกัน (PVD 40,000 / RMF 360,000 / บำนาญ 100,000) แต่ผลรวมกลุ่ม 500,000 และค่าลดหย่อนรวม 660,000 เท่ากัน เทสต์ยืนยันผลรวมทั้งสองตัว
2. (ถูกแทนที่แล้ว ดูหัวข้ออัปเดตท้ายไฟล์) **"บำนาญล้น" = ส่วนของเบี้ยบำนาญที่เกินเพดานรายตัว (15% ไม่เกิน 200,000)** เติมช่องประกันชีวิตเท่าที่ประกันชีวิตปกติยังไม่เต็ม 100,000 ก่อนที่ประกันสุขภาพจะใช้ส่วนที่เหลือของเพดานรวมชีวิต+สุขภาพ · อีกการตีความหนึ่ง (ล้น = ส่วนที่กลุ่มเกษียณรับไม่ไหว) ให้ผู้ใช้ได้ลดหย่อนมากกว่าในบางกรณี (กลุ่มเต็มแล้วแต่บำนาญยังไม่เกินเพดานรายตัว) ผมเลือกแบบเข้มกว่าเพราะตรงกับลำดับที่เจ้าของเขียน (ชีวิต → บำนาญล้น → กลุ่ม) ถ้าต้องการแบบหลังบอกได้ แก้ที่เดียวใน `salaryTax.ts`
3. **ส่วนที่ได้รับยกเว้นของ PVD หักจากเงินได้เหมือนค่าลดหย่อน** และ **ค่าใช้จ่ายเหมา 50% ยังคิดจากเงินได้ทั้งหมด** (ตาม R19 "ฐานคือเงินได้พึงประเมินรวม") · ผลต่างเกิดเฉพาะเงินได้ต่ำกว่า 200,000 บาท (เพดานค่าใช้จ่ายยังไม่ชน) · ถ้ากฎหมายให้หักส่วนยกเว้นก่อนคิดค่าใช้จ่าย ต้องแก้ R19 (เจ้าของเท่านั้น)
4. ค่าจ้างสำหรับ 15% ของ PVD = เงินได้เงินเดือนทั้งปี (แอปไม่แยกค่าจ้างกับโบนัส)
5. บรรทัดย่อยของหน้าจอ: PVD แสดง "หักลดหย่อน X + ได้รับยกเว้น Y", ส่วนบำนาญล้นแสดงเป็นแถวแยก (ไม่ทำให้เพดานรายตัวของแถวบำนาญเกินเพดาน)

   - **กรณีที่สองแบบให้ผลต่างกัน (money-auditor):** เงินได้ 2,000,000, PVD 300,000, RMF 300,000, บำนาญ 100,000, ชีวิต 0 · แบบที่ทำ: บำนาญถูกกลุ่มตัดเป็น 0 ไม่เติมช่องชีวิต · อีกแบบ: ส่วนที่กลุ่มตัด 100,000 ไปเข้าช่องชีวิต (ภาษีที่แอปคิดจะสูงกว่าอีกแบบราว 25,000 บาทที่เงินได้สุทธิ 1.34 ล้าน) · ตัวอย่างกรมสรรพากรให้ผลเท่ากันทั้งสองแบบ จึงตัดสินจากตัวอย่างไม่ได้ **รอเจ้าของ/ผู้รู้ภาษียืนยันข้อความ 43975** (ถ้อยคำ "ใช้สิทธิได้ไม่เกิน 200,000" ของเอกสารสนับสนุนแบบที่ทำ)

## สิ่งที่ money-auditor เสนอให้เจ้าของพิจารณา (ไม่ได้แก้ money-rules.md)
R19 ยังไม่ระบุ: (1) PVD เป็นสมาชิกกลุ่มเกษียณและมาก่อน RMF (2) คีย์ `pensionToLife` และลำดับ ชีวิต → บำนาญล้น → สุขภาพ → กลุ่ม (3) สถานะ `basis: 'continuing'` · ถ้าเห็นสมควร ให้เสนอเป็นร่างแยกแบบ `docs/money-rules-R16-proposal.md` ผมไม่ได้แก้ไฟล์กฎ
- ส่วนหักลดหย่อน PVD 10,000 ไม่ถูกจำกัดด้วย 15% ของค่าจ้าง (ไม่มีผลต่อภาษี เพราะเงินได้ต่ำระดับนั้นภาษีเป็น 0) · ค่าใช้จ่ายเหมาไม่หักส่วนยกเว้น PVD ไม่มีผลต่อภาษี (เงินได้ ≥ ~235,300 บาทค่าใช้จ่ายชนเพดานอยู่แล้ว ต่ำกว่านั้นภาษี 0) ต่างเฉพาะตัวเลข "ค่าใช้จ่าย/เงินได้สุทธิ" ที่แสดง
- รายการเดิม (ประกันชีวิต สุขภาพ สุขภาพบิดามารดา ดอกเบี้ยบ้าน) ตามที่เจ้าของสั่งให้ใส่ลิงก์อินโฟกราฟิกเป็นแหล่งหลัก · เอกสาร ม.ค. 2568 ที่เคยเป็นแหล่งหลักย้ายไปเป็นแหล่งเพิ่มเติม (ยังอยู่ใน config) ป้ายบนจอเปลี่ยนจาก "อ้างอิง ม.ค. 2568" เป็น "เกณฑ์ที่ใช้ต่อเนื่อง…" ตามข้อความที่เจ้าของกำหนด

## ข้อสังเกตจากแหล่ง (แจ้งเจ้าของ)
- หน้า 59674 (ปี 2560) ระบุ RMF 15% ไม่ใช่ 30% · 30% มาจากอินโฟกราฟิกปี 2565 (ใช้ตามนั้น เหมือนเดิม)
- หน้า 59674 ข้อความเรื่องบำนาญมีวลี "หักลดหย่อนไม่เกิน 10,000" ที่ตำแหน่งกำกวม ไม่ใช้
- ตัวอย่าง 43975 เขียน "500,00" (พิมพ์ผิด) อ่านเป็น 500,000 ตามบริบท
- SSF/กบข./กอช. อยู่ในกลุ่ม 500,000 ตามกฎหมายแต่แอปยังไม่รองรับ (บอกใน config และข้อจำกัดบนจอ)

## อัปเดต 13 พ.ย. 2569 (ค่ำ): เจ้าของตัดสินข้อค้าง
1. **บำนาญล้น → ใช้แบบที่ผู้เสียภาษีได้สิทธิสูงสุด:** เบี้ยบำนาญเติมช่องประกันชีวิตที่ยังเหลือก่อน แล้วส่วนที่เหลือจึงนับเข้ากลุ่มเกษียณ (เพดานรายตัว 15% ไม่เกิน 200,000 และเพดานกลุ่ม 500,000) · ลำดับคงที่ใหม่: ประกันชีวิต → ประกันสุขภาพ → บำนาญเติมช่องชีวิต (เท่าที่ชีวิต+สุขภาพรวม 100,000 ยังเหลือ) → กลุ่มเกษียณ · สุขภาพมาก่อนบำนาญเพราะสุขภาพใช้ได้เฉพาะช่องนี้ ส่วนบำนาญที่เหลือยังไปกลุ่มได้ ผลรวมจึงสูงสุด · ตัวอย่างกรมสรรพากร 43975 ยังได้ตัวเลขเท่าเดิม (ชีวิตรวม 100,000, กลุ่ม 500,000) · กรณีที่ money-auditor ยกมา (เงินได้ 2,000,000 / กองทุนสำรองฯ 300,000 / RMF 300,000 / บำนาญ 100,000): ค่าลดหย่อนรวม 660,000 (เดิม 560,000) เงินได้สุทธิ 1,240,000 ภาษี 175,000 (เทสต์)
2. **กองทุนสำรองเลี้ยงชีพมาก่อน RMF ในกลุ่มเกษียณ:** เจ้าของยืนยัน
3. **ร่างแก้ R19:** เจ้าของอนุมัติให้ money-auditor เขียนร่าง รวม PVD, บำนาญเติมช่องชีวิต และป้ายเกณฑ์ต่อเนื่อง ลง docs/money-rules.md เป็น PR/commit แยก (ทำหลัง PR นี้)
4. แถวบำนาญในตารางนับเฉพาะส่วนที่เข้ากลุ่มเกษียณ (requested = เบี้ยที่กรอกหักส่วนที่เติมช่องชีวิต) มีบรรทัดย่อยบอกยอดที่กรอกทั้งหมดและส่วนที่ย้ายไปช่องชีวิต · แถว pensionToLife แยก ไม่มี "ขอเกิน"
- ผล money-auditor รอบนี้: ไม่พบสูง · กลาง 1 (สิทธิที่ยังใช้ได้ของประกันชีวิตแสดงเกินจริง) แก้แล้วพร้อมเทสต์ · ต่ำ 2 (เทสต์ใช้ float ปัดเศษ → เปลี่ยนเป็นจำนวนเต็ม, แถวบำนาญแสดง "ขอ" เป็นส่วนที่เข้ากลุ่ม มีบรรทัดอธิบายยอดที่กรอกทั้งหมดแล้ว) · ข้อสังเกต: ส่วนบำนาญที่เติมช่องชีวิตไม่ถูกจำกัดด้วยเพดาน 15%/200,000 (ตรงที่เจ้าของเลือก) และแอปไม่ตรวจเงื่อนไขอายุ/ถือครองของบำนาญและกองทุนสำรองฯ (บอกในข้อจำกัดบนจอ)
