# สคริปต์ลบผู้ใช้ `admin:delete-user` (13 พ.ย. 2569)

## เหตุการณ์
ตอนลบบัญชีทดสอบ (testnew) ผ่านหน้า Supabase เจ้าของ **ลบผู้ใช้ทั้งหมดโดยไม่ตั้งใจ** รวมบัญชีของตัวเองด้วย ผมตรวจพบจากการนับแถวแบบอ่านอย่างเดียว (`auth.users` = 0 และทุกตารางข้อมูลว่าง) เจ้าของแก้ด้วยการสร้างบัญชี kumeyuri ใหม่และนำเข้าไฟล์สำรอง (ยังไม่สร้างบัญชีเพื่อน) ข้อมูลกลับมาได้เพราะมีไฟล์สำรองส่งออกไว้ (ข้อมูลเป็นของผู้ใช้และส่งออกได้เสมอ)

สาเหตุที่ป้องกันได้ยากในหน้า Supabase: เลือกหลายแถว/ลบผิดแถวได้ง่าย ไม่มีด่านยืนยันตามชื่อ ไม่มีการเตือนว่าเป็นบัญชีสุดท้าย

## วิธีป้องกัน: `npm run admin:delete-user -- <username> [--force]`
- ลบได้ **ทีละ 1 บัญชีตามชื่อเท่านั้น** ปฏิเสธหลายชื่อ, `*`/`%`/`?`/`,`/ช่องว่าง, ตัวเลือกอื่นนอกจาก `--force`
- แสดงชื่อ + จำนวนแถวต่อตาราง (9 ตารางรวม profiles ไม่แสดงเนื้อหา) แล้วต้อง **พิมพ์ชื่อซ้ำ** ถึงจะลบ (Enter เปล่า = ยกเลิก) ต้องรันใน terminal จริง (ไม่รับ pipe)
- **ปฏิเสธ** ถ้าเป็นบัญชีสุดท้ายในระบบ หรือชื่อ `kumeyuri` เว้นแต่ใส่ `--force` · ถ้าใช้ `--force` กับสองกรณีนี้ ต้องพิมพ์วลี `ลบ <ชื่อ> ถาวร` (ไม่ใช่แค่ชื่อ)
- นับผู้ใช้ซ้ำหลังรอยืนยัน (กันบัญชีเปลี่ยนระหว่างรอ) · นับผู้ใช้วนจนหน้าว่าง เกิน 50 หน้า = ล้ม
- ลบแล้วอ่านกลับยืนยัน: บัญชีหาย (เฉพาะ 404/user_not_found ถ้าเป็น error อื่นจะบอกว่ายืนยันผลไม่ได้) + 9 ตารางข้อมูล 0 แถว

## ผลตรวจ security-auditor และสิ่งที่แก้
ไม่พบระดับสูง · แก้แล้ว: ยืนยันผลหลังลบเข้มขึ้น, นับ profiles, นับซ้ำก่อนลบ, แบ่งหน้าจนหน้าว่าง, วลียืนยันยาวเมื่อ `--force`, เพิ่ม deny สำหรับ npx / npm exec / npm --opt run / yarn / pnpm / winpty / env, เพิ่มเทสต์ deny ให้ครบ
**ช่องที่ยังเหลือ (ยอมรับ):** deny list จับจากข้อความคำสั่ง เลี่ยงได้ด้วยตัวห่อบางแบบ (`bash -c`, `cmd /c`, alias) เหมือน create-user · ด่านที่เหลือจริงคือต้องมี TTY และพิมพ์ยืนยัน ซึ่งผู้ช่วย AI ทำเองไม่ได้ · ไม่ได้ใส่ deny กว้าง `*delete-user*` เพราะจะบล็อก git/grep ปกติ · ไม่ได้ไปแก้ create-user/reset-password (นอกขอบเขต ตั้งเป็นงานถัดไปถ้าต้องการ)
**ไม่ได้นับ:** ตารางใน schema `private` (import_sessions, delete_attempts) — เป็น cascade ถ้าไม่ลบจะไม่เหลือข้อมูลการเงิน
- ใช้ `admin.env` นอกโปรเจกต์ผ่าน `scripts/lib/admin.mjs` เหมือน create-user ไม่รับ key/รหัสทางอาร์กิวเมนต์
- อยู่ใน `permissions.deny` ของ `.claude/settings.json` (Bash + PowerShell): **ผู้ช่วย AI ห้ามรัน เจ้าของรันเองเท่านั้น**
- ตรรกะตัดสินใจอยู่ใน `scripts/lib/deleteUserGuard.mjs` (ล้วน ทดสอบได้) · เทสต์ `tests/unit/deleteUserGuard.test.ts` และ `scriptsGuard.test.ts`

## ข้อควรรู้
- ยังไม่ได้ทดสอบกับ Supabase จริง (ผู้ช่วยรันไม่ได้ตามกติกา) → เจ้าของลองครั้งแรกกับบัญชีทดสอบที่สร้างใหม่เท่านั้น
- การลบยังเป็นถาวร: ก่อนลบบัญชีที่มีข้อมูลจริง ให้ส่งออกไฟล์สำรองก่อนเสมอ
- ไม่ได้ป้องกันการลบในหน้า Supabase โดยตรง (ตัดสิทธิ์หน้านั้นไม่ได้) → ใช้วินัย: ลบผ่านสคริปต์นี้เท่านั้น
