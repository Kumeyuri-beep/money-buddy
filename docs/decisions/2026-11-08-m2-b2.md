## สิ่งที่ต้องทำเมื่อเจ้าของพร้อม (ลำดับ)

1. อนุมัติให้ผมใส่ migration `20261108000400` (หรือวางไฟล์ใน SQL Editor เอง) แล้วรัน `supabase/tests/m2b_admin_sessions_test.sql` ต้องได้ `TESTS_PASSED`
2. ใส่ key ในไฟล์ `.money-buddy-admin/admin.env` (นอกโปรเจกต์) ด้วยตัวเอง: `SUPABASE_URL=...` และ `SUPABASE_SERVICE_ROLE_KEY=...` (ห้ามวางในแชท)
3. รัน `npm run admin:spike` ในเครื่องเจ้าของ แล้วส่งผลลัพธ์ (PASS/FAIL ไม่มีความลับ) ให้ผม · ถ้า `.internal` ไม่ผ่าน ผมเปลี่ยน `AUTH_EMAIL_DOMAIN` ตามผล
4. สร้างบัญชีจริงด้วย `npm run admin:create-user -- <username>` (ส่งรหัสชั่วคราวให้ผู้ใช้ทางช่องส่วนตัว)

## ผลตรวจ security-auditor และสิ่งที่แก้

| # | ข้อพบ | ตัดสินใจ |
|---|---|---|
| 9 | โหลดไฟล์ key ด้วยตัวโหลดของ Node ไม่เขียนทับตัวแปรที่มีอยู่แล้ว (key จาก shell/`.env` ชนะเงียบๆ) และ key ค้างในตัวแปรของ process | **แก้:** `loadAdmin` อ่านไฟล์เองด้วย `parseEnv` (ไม่แตะตัวแปรของ process) · ปฏิเสธถ้า shell มี `SUPABASE_SERVICE_ROLE_KEY`/`SUPABASE_SECRET_KEY` อยู่ก่อน · spike อ่านไฟล์ของโปรเจกต์ด้วย `parseEnv` และ **หยุดทันทีถ้า URL สองไฟล์ไม่ตรงกัน** · เทสต์: ไม่มี `child_process` ในสคริปต์ |
| 10 | reset-password: คนที่รู้รหัสเดิมแทรกล็อกอินระหว่างขั้นได้ แล้วตั้งรหัสของตัวเองหลังเราตั้งรหัส (ผ่านการตรวจทุกขั้นแต่รหัสที่พิมพ์ใช้ไม่ได้) | **แก้:** ระงับบัญชีก่อน (`ban_duration`) ทำทุกขั้น ตรวจ แล้วปลดระงับเป็นขั้นสุดท้าย + อ่านกลับยืนยัน · ล้มกลางทาง = บัญชียังถูกระงับ (ปลอดภัย) รันใหม่หรือปลดใน Dashboard · เทสต์ลำดับขั้นเข้มขึ้น |
| 11 | `.gitignore` ไม่ครอบชื่อ `admin.env` | **แก้:** เพิ่ม `*.env` และ `.money-buddy-admin/` + เทสต์ |
| 12 | `isInsideDir` เทียบข้อความ ไม่ตามลิงก์ | **แก้:** `realpathSync.native` ทั้งไฟล์และโปรเจกต์ · ปฏิเสธ symlink/junction ของไฟล์และโฟลเดอร์ · ปฏิเสธพาธขึ้นต้นด้วยแบ็กสแลชคู่ (UNC) · เตือนถ้าอยู่ในโฟลเดอร์ซิงก์คลาวด์ · POSIX ปฏิเสธสิทธิ์ที่คนอื่นอ่านได้ · (Windows ให้ตรวจ `icacls` เอง) |
| 13 | `admin_revoke_sessions` พึ่ง FK cascade อย่างเดียว | **แก้:** ลบ `auth.refresh_tokens` ของผู้ใช้โดยตรงด้วย · ไม่เพิ่มด่านตรวจ role ในตัวฟังก์ชัน (ด่านจริงคือ grant เฉพาะ service_role · ถ้าเพิ่ม `auth.role()` แล้วคีย์แบบ `sb_secret_` ไม่ถูกแมปเป็น role นี้ เครื่องมือจะใช้ไม่ได้เงียบๆ → spike จะบอกว่าเรียกฟังก์ชันได้ไหม) |

## อัปเดตหลังเจ้าของตอบ (8 พ.ย. 2569)

- **ข้อ 1 ด้านล่าง ทำแล้ว:** เจ้าของอนุญาตให้เพิ่ม deny ใน `.claude/settings.json` — ห้ามผู้ช่วย AI รัน `npm run admin:*`, `node scripts/create-user*`, `reset-password*`, `spike-auth*` (ทั้ง Bash และ PowerShell รวมรูปแบบพาธ Windows, `& node`, `Start-Process`) · เทสต์ใน `scriptsGuard.test.ts` ตรวจว่ากฎอยู่ครบและกฎ `git push` เดิมไม่หาย · ผลข้างเคียง: ผมรันสคริปต์เหล่านี้เพื่อทดสอบเองไม่ได้ (ตั้งใจ)
- **ข้อ 5 ทำแล้ว:** ใส่ migration และรันเทสต์ SQL ผ่าน
- ชื่อตัวแปร key รับทั้ง `SUPABASE_SERVICE_ROLE_KEY` และ `SUPABASE_SECRET_KEY` (key แบบ `sb_secret_`) ตั้งแต่ต้น · เพิ่มเทสต์กันถอยหลัง
- Vercel build command: ไม่มี `vercel.json`/`.vercel` ในโปรเจกต์ (ใช้ค่าที่ตั้งใน Dashboard) · การอ่านการตั้งค่าโปรเจกต์ผ่านการเชื่อมต่อ Vercel ต้องให้เจ้าของอนุญาตสิทธิ์ทีมก่อน (รอ)

## ข้อที่ต้องให้เจ้าของตัดสินใจ/ทำเอง (ผมไม่ได้แก้)

1. **ผู้ช่วย AI ยังรันสคริปต์ผู้ดูแลได้ (เสี่ยงสูงสุดตามผู้ตรวจ):** กฎ deny ใน `.claude/settings.json` กันเฉพาะคำสั่งที่มีข้อความ `.env`/`.money-buddy-admin` ส่วน `npm run admin:*` หรือ `node scripts/create-user.mjs …` ไม่ถูกบล็อก ผลลัพธ์ (รหัสชั่วคราว) จะไปอยู่ในบันทึกการคุย · **ข้อเสนอ:** เพิ่ม deny สำหรับ Bash/PowerShell: `npm run admin:*`, `node scripts/create-user*`, `node scripts/reset-password*`, `node scripts/spike-auth*` (ผมไม่แก้ settings เอง เพราะที่คุณอนุญาตไว้คือกฎอ่านไฟล์ `.env*`/โฟลเดอร์ key) · ไม่ว่าจะเพิ่มหรือไม่ **ให้รันสคริปต์เหล่านี้ใน terminal ของคุณเองเท่านั้น**
2. ตรวจสิทธิ์โฟลเดอร์ `.money-buddy-admin` ด้วย `icacls` ให้เหลือเฉพาะคุณ, SYSTEM, Administrators และไม่อยู่ใต้ OneDrive
3. ยืนยันที่ Vercel ว่า Build Command คือ `npm run build` (ไม่ใช่ `vite build` ตรงๆ ไม่งั้น `postbuild` ไม่ทำงาน) และไม่มี secret ใน Vercel env/GitHub secrets
4. ยืนยันที่ Dashboard: ปิดการสมัครเอง, ปิด Anonymous, ปิด provider อื่น, รหัสขั้นต่ำ 10
5. ตัดสินใจ/อนุมัติให้ใส่ migration `20261108000400` (รอบนี้ `apply_migration` ถูกปฏิเสธ)
