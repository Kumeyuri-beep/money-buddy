# 2026-11-04 สแกนสลิป (M1-B4): การตัดสินใจหลังทดสอบกับสลิปจริง

บริบท: ตัวอ่านข้อความสลิปที่เขียนจากข้อความสมมติสะอาดอ่านสลิป K PLUS จริงไม่ได้ (ยอดว่าง 4/4, วันที่ว่าง 2/4) จึงปรับหลายอย่าง ข้อมูลทดสอบจริงอยู่นอกโปรเจกต์และไม่ถูกคัดลอกเข้ามา ผลวินิจฉัยปิดบังชื่อและเลขยาว

| เรื่อง | ตัดสินใจ | เหตุผล |
|---|---|---|
| ขยายรูปก่อน OCR | ย่อต้นฉบับให้ด้านยาว ≤ 1600 ก่อน แล้วขยายสูงสุด 2 เท่า แต่ด้านยาวหลังขยาย ≤ 2400 (เจ้าของกำหนดเพดาน 2400) | ทดลองแล้วตัวอักษรเล็ก (เดือน "พ.ย.") อ่านได้ชัดขึ้นมาก เพดานกันกินหน่วยความจำ |
| จำนวนรอบ OCR | 2 รอบ: ขยาย+ขาวดำสนิท (Otsu) และขยาย+เทายืดคอนทราสต์+โหมดข้อความกระจาย | ไม่มีวิธีเดียวที่อ่านเดือนและยอดได้ทุกใบ สองรอบรวมกันครอบคลุมสลิปตัวอย่างทั้ง 4 ใบ ใช้เวลา ~3-6 วินาที/ใบ |
| รวมผลสองรอบ | ยอด/วันที่ถ้าสองรอบขัดกัน = ปล่อยว่าง + เตือน (`ocr-disagree`) · ผู้รับเลือกชื่อที่ยาวกว่า · เวลาใช้ค่าแรก | ตามกติกา "ยอดที่ไม่แน่ใจต้องว่าง ห้ามเดา" |
| ตัวอ่านยอด | ค้นเฉพาะหลังป้าย "จำนวน" ไม่เกิน 6 บรรทัด หยุดที่ป้ายค่าธรรมเนียม/เลขที่รายการ/ยอดคงเหลือ ต้องทศนิยม 2 หลัก ไม่ติดตัวเลข/ศูนย์นำหน้า ต้องมีค่าเดียว (หลายค่าต่างกัน = ว่าง) ไม่ใช้ "บาท" ตัดสินเอง | สลิปจริงมีขยะต่อท้ายบรรทัดจึงบังคับ "ทั้งบรรทัด" ไม่ได้ ความปลอดภัยย้ายไปที่กฎตำแหน่ง + ว่างเมื่อกำกวม (ตามผลตรวจ `money-auditor` 4 พ.ย.) |
| กฎสำรอง (หาป้ายไม่เจอ) | ใช้ตัวเลขทศนิยมต้นบรรทัดที่ไม่ใช่ศูนย์ตัวเดียวก่อนป้ายค่าธรรมเนียม ไม่ใช่บรรทัดวันที่/เวลา/ป้ายอ้างอิง และต้องได้ตรงกันทั้งสองรอบ (หรือมีรอบหนึ่งอ่านจากป้ายตรง) | OCR มักอ่านป้าย "จำนวน" และ "บาท" เพี้ยน แต่ตัวเลขถูก กฎสำรองเสี่ยงเดา จึงเข้มและต้องมีหลักฐานจากสองรอบ |
| ผู้รับ | ไม่มีป้าย "ไปยัง" บนสลิปจริง: เลือกบรรทัดที่ดูเป็นชื่อ "สุดท้าย" ก่อนป้ายจำนวน ตัดขยะท้ายบรรทัด/เลขนำหน้า | ลำดับสลิปคือ ผู้โอน → ผู้รับ/ร้านค้า → จำนวน ชื่ออาจผิดได้ ใช้เป็นบันทึกช่วยจำที่ผู้ใช้ตรวจ |
| ยืนยันค่าที่ OCR เติม | ยอดและวันที่ขึ้น "ยังไม่ได้ยืนยัน" (เส้นประส้ม) จนกว่าแก้หรือกด "ตรงกับสลิป" ไม่บล็อกการบันทึก | เจ้าของเลือก (ตัวเลือก ง) ให้เน้นแต่ไม่บล็อก |
| ไฟล์ OCR | เก็บในโปรเจกต์ผ่านสคริปต์คัดลอกจาก `node_modules` ไป `public/ocr/` (ไม่ commit) ไม่ใช้ CDN | ตรงกับหลัก local-first/รูปไม่ออกนอกเครื่อง ทดสอบแล้วใช้งานได้เมื่อบล็อกเว็บภายนอกทั้งหมด |
| เวอร์ชัน Tesseract | `tesseract.js` 7.0.0 (ล่าสุด) แทน v5 | v5 เก่าสองรุ่นหลัก ห่อไว้ที่ `src/ocr/readSlip.ts` ไฟล์เดียว เปลี่ยนได้ง่าย |
| ความปลอดภัยของไฟล์รูป | อ่านความกว้างยาวจากหัวไฟล์ก่อนแตกรูป ปฏิเสธเมื่อด้านใดเกิน 10000px หรือรวมเกิน 40 ล้านพิกเซล หรืออ่านขนาดไม่ได้ · รับเฉพาะ PNG/JPEG/WebP (ไม่รับ GIF/BMP/HEIC/SVG) | กันรูปบอมบ์ (ไฟล์เล็กแต่ภาพใหญ่มหาศาลทำแท็บค้าง) ตามผล security-auditor |
| เวลาหมดอายุ | อ่านแต่ละรอบไม่เกิน 60 วินาที ปิด worker ใน finally โดยไม่ทับ error เดิม ล็อกกันสแกนซ้อนด้วย ref | กันค้างไม่รู้จบและ worker ซ้อน |
| เวอร์ชันแพ็กเกจ OCR | ล็อกตัวเลขตรง (7.0.0 / 1.0.0 ไม่ใช้ ^) | ห่วงโซ่อุปทาน: ข้อมูลที่ใช้กับรูปสลิปไม่ควรเปลี่ยนเงียบๆ ตอน install |
| ข้อมูลในเทสต์ | ยอดและเศษข้อความ OCR ในเทสต์เป็นค่าที่แต่งขึ้น ไม่ตรงสลิปจริง | กติกาห้ามข้อมูลการเงินจริงเข้าโปรเจกต์ |
| เลขไทย | แปลง ๐-๙ เป็นเลขอารบิกก่อนอ่านทุกช่อง | กันยอดผิดแบบผสม (เช่น `๔800.00` ได้ 800.00) |

## ข้อจำกัดที่ยอมรับ
- ผู้รับอาจอ่านได้แค่บางส่วน (OCR อ่านคำแรกของชื่อพลาด) ผู้ใช้ตรวจเอง
- วันที่ผิดหนึ่งหลักที่ยังอยู่ในช่วง 365 วันผ่านเงียบ (ธรรมชาติของการอ่านตัวเลข) ป้าย "ยังไม่ได้ยืนยัน" ที่ช่องวันที่เป็นตาข่ายรองรับ
- ความแม่นกับสลิปรูปแบบอื่นนอกจากตัวอย่าง 4 ใบ (จาก LINE ~1000px) ยังไม่ได้พิสูจน์
- ธนาคารอื่นนอก K PLUS ยังไม่รองรับ
