# การ์ดแชร์สัดส่วน + การ์ดสัดส่วนหน้าภาพรวม: ข้อที่ตัดสิน (11 พ.ย. 2569)

เจ้าของตัดสิน: แชร์เฉพาะสัดส่วน % ไม่มียอดเงิน · ชื่อซ่อนเป็นค่าเริ่มต้น (เปิดเองได้) · สร้างรูปในเครื่อง ผู้ใช้กดแชร์เอง · ห้ามส่งขึ้นเซิร์ฟเวอร์ · การ์ดสัดส่วนหน้าภาพรวมเป็น PR แยก

| # | เรื่อง | ตัดสิน | เหตุผล |
|---|---|---|---|
| 1 | เทคนิคสร้างรูป | canvas 2D ในเบราว์เซอร์ → PNG (`toBlob`) แชร์ด้วย Web Share API ถ้ารองรับ ไม่งั้นดาวน์โหลดไฟล์ | ไม่ต้องเพิ่มไลบรารี · ไม่มีเครือข่าย |
| 2 | ตัววาดรูปเห็นอะไร | รับเฉพาะ `AllocationModel` (ป้าย + bps) กับป้ายวันที่ · เทสต์สแกนว่าไม่อ้าง portfolio/position/totals และไม่ import อย่างอื่น | บังคับด้วยโครงสร้าง ไม่ใช่แค่ตั้งใจ |
| 3 | ป้ายชื่อ | ซ่อน = "สินทรัพย์ 1…" (เรียงตามสัดส่วน) · เปิด = ชื่อจริง · ที่เกิน 7 ชิ้นรวมเป็น "อื่นๆ" | ลดการเดาตัวตนสินทรัพย์ |
| 4 | เกณฑ์สัดส่วน | มูลค่าถ้าทุกสินทรัพย์มีราคา ไม่งั้นต้นทุนและบอกชัด | R17: ไม่ใช้ต้นทุนแทนมูลค่าเงียบๆ · ไม่ผสมสองเกณฑ์ |
| 5 | ปัดเศษ | `allocateBps` BigInt เศษมากสุด รวม 10,000 พอดี · `formatBps` ปัดครึ่งขึ้น 0.1% ด้วยจำนวนเต็ม | R1/R8 |
| 6 | ไม่บันทึก | ไม่เก็บรูป/ตัวเลือกในที่เก็บถาวรใดๆ (เทสต์ห้ามใช้ localStorage/IndexedDB ในไฟล์การ์ด) | ไม่ทิ้งร่องรอย |
