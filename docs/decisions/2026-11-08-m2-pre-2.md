## ข้อสังเกต / ที่ไม่ได้ทำ

- ข้อมูลเดิมในเครื่อง (Dexie) ที่เกินข้อจำกัดจะแก้ไม่ได้จนกว่าจะแก้ให้อยู่ในช่วง และบิลที่ชื่อ/รหัสผิดจะถูกจัดเป็น "บิลเสีย" (ข้ามและแจ้งจำนวน) ความเสี่ยงต่ำ (ชื่อ ≤ 200 ตัวอักษร) · M2-D ต้องตรวจไฟล์สำรองก่อนนำเข้าด้วยฟังก์ชันชุดเดียวกัน
- `runIntegrityCheck` ยังไม่รายงานข้อจำกัดเหล่านี้ (ทำใน M2-C/M2-D ถ้าจำเป็น)
- ข้อ C ของ `2026-11-08-m2-a.md` (DB หลวมกว่าโดเมนด้านกฎบิล) คงเดิมโดยตั้งใจ

## ผลตรวจ money-auditor และสิ่งที่แก้/ยอมรับ

| # | ข้อพบ | ตัดสินใจ |
|---|---|---|
| 1 | เว็บรับ NUL (U+0000) และ surrogate เดี่ยวใน id/ชื่อ/memo แต่ Postgres ปฏิเสธ | **แก้:** `lengthWithin` ปฏิเสธทั้งสอง (`hasDbInvalidChars`) · memo ใช้ `lengthWithin(memo, 0, 2000)` จึงปฏิเสธชนิดที่ไม่ใช่ข้อความ (`LedgerError` ไม่ใช่ `TypeError`) |
| 2 | `lines.idx` เป็น smallint | **แก้:** จำกัด 32767 บรรทัดต่อรายการ (`MAX_LINES_PER_ENTRY`) |
| 3 | `accountProblem` ปฏิเสธ `sortOrder: null` ขณะที่ DB ยอม null | ยอมรับ (type ของเว็บไม่มี null ไม่มีผู้เรียกส่ง null) |
| 4 | เลิกทำ (กู้รายการที่ลบ/ย้อนการแก้ไข) ผ่าน `createEntry` กับข้อมูลเก่าที่ memo > 2000 หรือวันที่นอก 1900-2999 จะล้ม ผู้ใช้ลบได้แต่กู้ไม่ได้ | **ยอมรับ ความเสี่ยงต่ำ:** `run()` แสดงข้อความ error ให้ผู้ใช้เห็น (ไม่ล้มเงียบ) · ข้อมูลเก่าที่เกินช่วงเกิดได้ยาก (memo > 2000 ตัวอักษร) · ถ้าเจอจริงค่อยทำทางกู้คืนที่ข้ามข้อจำกัดเฉพาะ |
| 5 | บิลเก่าที่ชื่อ > 200 หรือ id > 100 กลายเป็น "บิลเสีย" (จ่าย/ยกเลิกไม่ได้ผ่าน `billProblem`) | **ยอมรับ:** ชื่อบิลเก่ายาวเกิน 200 แทบไม่มี · `billForm` ไม่จำกัดความยาวตอนกรอก (ควรเพิ่ม `maxLength` ใน UI เป็นงานแยก) · ข้อความ "บิลไม่ถูกต้อง: ชื่อบิลต้องยาว 1-200 ตัวอักษร" อ่านรู้เรื่อง |
| 6 | ชื่อกระเป๋าเดิมที่ยาวเกิน 200 ไม่ถูกตรวจ (ตรวจเฉพาะ `buildInitialLedger`) | M2-D ต้องตรวจไฟล์สำรองด้วย `accountProblem` ก่อนนำเข้า |
| 7 | ช่องกรอกใน UI ไม่มี `maxLength` | งานแยก: ใส่ `maxLength` (memo 2000, ชื่อ 200) ให้ผู้ใช้เห็นข้อจำกัดก่อนกดบันทึก |

## บทเรียน (ข้อควรระวังสำหรับสคริปต์แก้ไฟล์)

สคริปต์ที่เขียนผ่าน heredoc ของ shell ตีความ `\u0000` ให้เป็นไบต์ NUL ดิบ และ `\uD800` เป็นอักขระแทนที่ (U+FFFD) ทำให้ไฟล์เสียแต่เทสต์ยังผ่าน (เพราะ regex/สตริงยังตรงกัน) ถูกจับได้จากการตรวจไบต์ · ให้เขียนสคริปต์ที่มี escape ผ่านเครื่องมือเขียนไฟล์ ไม่ใช่ heredoc และสแกนไฟล์ที่เปลี่ยนหา NUL/U+FFFD ก่อน commit
