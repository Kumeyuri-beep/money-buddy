## ตัดสินใจ

1. **ล้างข้อมูลทั้งหมดบังคับรหัสผ่าน** (ผล security-auditor): ฟังก์ชัน SECURITY DEFINER เดิมไม่ถามรหัส → session ที่ถูกขโมยล้างสมุดทั้งเล่ม (รวมยอดยกมา ซึ่งทางปกติลบไม่ได้) ได้ในคำขอเดียว · เปลี่ยนเป็น `reset_my_ledger(p_password)` ตรวจรหัส + จำกัด 5 ครั้ง/15 นาที ใช้ตาราง `delete_attempts` ร่วมกับลบบัญชี · `resetAll()` ฝั่ง Supabase ต้องมี `getPasswordForReset` ไม่งั้นล้มทันที
2. **ข้อความ error:** ส่งต่อให้ผู้ใช้เฉพาะข้อความไทยที่มาจากรหัส error ที่เรา raise เอง (กันข้อความ Postgres ที่ปนค่าที่ผู้ใช้กรอก) · unique index รอบบิลซ้ำ → "รอบนี้จ่ายแล้ว" (ไม่ใช่ "รหัสซ้ำ")
3. **อ่านครบจริง** (ผล money-auditor): offset pagination ไม่มี snapshot → ตัดแถวซ้ำด้วย id + เทียบ `count` ของตาราง อ่านใหม่สูงสุด 3 รอบ แล้วปฏิเสธ (ไม่ปล่อยข้อมูลขาดเงียบๆ แม้เพดานแถวของเซิร์ฟเวอร์ต่ำกว่า 1000) · `exportSnapshot` อ่านบิลซ้ำเทียบ ไม่ตรงอ่านใหม่
4. `safeInt` รับสตริงเฉพาะ `^-?[0-9]{1,16}$` (กัน `""`→0, `"1e3"`→1000)
5. `entries_bill_link` ห้ามจ่ายบิลที่เก็บถาวร (เดิมเช็คแค่รอบ)
6. `tests/live` ไม่อยู่ใน `npm test` (ชื่อ `*.live.ts`) และถูกตัดออกจาก `typecheck` เพราะโปรเจกต์ไม่มี `@types/node` · `globalSetup` ปฏิเสธรันถ้าไม่มี `MONEY_BUDDY_LIVE_TESTS=yes`

## ยังไม่ต่อ UI (ตั้งใจ)

`RepositoryProvider` ยังใช้ Dexie จนกว่า **M2-D** (นำเข้า JSON) เสร็จ: ถ้าสลับเป็น Supabase ก่อน ผู้ใช้จะเห็นสมุดว่าง · ตอนต่อ UI ต้องทำด้วย: `downloadBackup` ให้ตามผู้ใช้ที่ล็อกอิน · ช่องกรอกรหัสผ่านตอนล้างข้อมูล (แทน `window.confirm`) · ส่ง `today` เวลาไทยให้ `payBill` ทุกครั้ง (DB ใช้เดือนเวลาไทย)

## ข้อที่ผู้ตรวจชี้และ "ยังไม่ทำ" (จดเป็น backlog)

- **อ่านพร้อมกัน:** `accounts` กับ `entries` เป็นคนละคำขอ (ไม่สอดคล้องแบบ snapshot) ถ้าจะให้เด็ดขาดต้องทำ RPC อ่านทั้งก้อนในธุรกรรมเดียว · ตอนนี้ผู้ใช้ ≤ 20 คน เขียนแทรกน้อย
- **จ่ายบิลด้วยยอดเก่า:** ถ้าอีกแท็บแก้ยอดบิลระหว่างที่แท็บนี้กดจ่าย รายการจ่ายใช้ยอดที่ผู้ใช้เห็นบนหน้าจอ (ตรงกับสิ่งที่ผู้ใช้ยืนยัน) · trigger เทียบยอดไม่ได้เพราะ AFTER INSERT ของ entries ทำงานก่อนบรรทัดถูกใส่
- **`bills.last_paid_month` เขียนตรงผ่าน REST ได้** (ไม่ผ่านการจ่าย): ไม่แย่กว่า Dexie แต่ R15 พูดว่า "ทุกเส้นทาง" → backlog: trigger ห้ามเปลี่ยนค่านี้นอกเส้นทางจ่าย/ยกเลิก
- `update_entry` ไม่เปลี่ยน `source` (Dexie เปลี่ยนได้) — ไม่กระทบยอด
- ชุดทดสอบจริงยังไม่เคยรันกับฐานข้อมูลจริง (ต้องให้เจ้าของรัน) · ผู้ใช้ `livetest-xxxxxxxx` อาจค้างถ้าโปรเซสถูกฆ่า ลบใน Dashboard ได้
- ข้อเสนอ: เพิ่ม deny `Bash(*vitest.live*)` / `PowerShell(*vitest.live*)` กันผู้ช่วย AI สั่ง vitest ตรงๆ (ผมไม่แก้ settings เอง รอเจ้าของอนุญาต) — ตอนนี้ด่าน `MONEY_BUDDY_LIVE_TESTS` กันไว้ชั้นหนึ่งแล้ว
