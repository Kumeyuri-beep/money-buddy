# record_consent รับเฉพาะนโยบายฉบับปัจจุบัน (9 พ.ย. 2569)

ที่มา: ผล security-auditor ตรวจ `record_consent(p_version)` · กฎที่แตะ: PDPA (ไม่แตะ money-rules)

## (ก) การบังคับยอมรับนโยบายกั้นที่หน้าเว็บเท่านั้น — ตั้งใจ
ฐานข้อมูลไม่บังคับให้ยอมรับก่อนใช้ข้อมูล (`can_use_data()` ไม่ตรวจ `consented_at`) ตามที่ตัดสินใจใน `2026-11-09-m2-e.md` ข้อ 1
เหตุผล: ผู้ที่ไม่ยอมรับต้องลบบัญชีตัวเองได้ (PDPA) และถ้าขอยินยอมซ้ำเมื่อนโยบายเปลี่ยน ข้อมูลจะถูกล็อกทันที
ผลที่รับไว้: ผู้ที่เรียก API ตรงหลังเปลี่ยนรหัสผ่านใช้ข้อมูลของตัวเองได้โดยไม่ผ่านหน้ายอมรับ (เป็นข้อมูลที่เจ้าตัวส่งเอง)
เจ้าของเลือกไม่ทำ (ค) บังคับที่ฐานข้อมูล และ (ง) ขึ้นเวอร์ชันใหม่ให้ยอมรับซ้ำตอนนี้

## (ข) ฐานข้อมูลรับเฉพาะฉบับปัจจุบัน
- `private.policy_versions.is_current` + unique partial index → ฉบับปัจจุบันได้แถวเดียว
- `record_consent` ตรวจ `version = p_version and is_current` · ฉบับเก่าเก็บเป็นประวัติแต่ยอมรับไม่ได้
- ผู้ใช้ที่ยอมรับฉบับเก่าไว้ไม่ถูกแตะ เว็บเทียบเวอร์ชันแล้วขอซ้ำเอง
- วิธีขึ้นฉบับใหม่ในอนาคต: migration ที่ (1) ตั้ง `is_current=false` ฉบับเดิม (2) insert ฉบับใหม่ `is_current=true` (3) มีบรรทัด `-- current-policy-version: YYYY-MM-DD` · เทสต์หน่วยเทียบกับ `PRIVACY_POLICY_VERSION`
