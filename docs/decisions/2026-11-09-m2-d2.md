# M2-D2: หน้าย้ายข้อมูลขึ้นบัญชีออนไลน์ + สลับแอปไปใช้ออนไลน์ (9 พ.ย. 2569)

เจ้าของยืนยัน: merge #31, ชุดทดสอบจริงผ่าน 27/27, Exposed schemas ไม่มี `private` · สั่ง "ห้ามลบข้อมูลใน Dexie จนกว่าผมยืนยันว่านำเข้าครบและยอดตรง"

## พฤติกรรมหลังล็อกอิน (`DataSourceGate` แทน `LocalDataGate`)
| สถานการณ์ | ผล |
|---|---|
| ออนไลน์มีข้อมูลแล้ว | ใช้บัญชีออนไลน์ (ข้อมูลเดิมในเครื่องไม่ถูกแตะ) |
| ออนไลน์ว่าง + ข้อมูลเดิมในเครื่องเป็นของบัญชีนี้ | **หน้าย้ายข้อมูล** (สำรอง → ตรวจ → นำเข้า → ตรวจยอด → เจ้าของยืนยัน) |
| ออนไลน์ว่าง + ข้อมูลเดิมยังไม่มีเจ้าของ | ถามก่อนว่าเป็นของฉัน แล้วเข้าหน้าย้ายข้อมูล |
| ออนไลน์ว่าง + ข้อมูลเดิมเป็นของบัญชีอื่น / ไม่มีข้อมูลเดิม | ตั้งต้นสมุดออนไลน์ใหม่ (ไม่เสนอข้อมูลของคนอื่น) |
| นำเข้าแล้วแต่ยังไม่ยืนยัน (ธง `pending`) และเป็นเจ้าของข้อมูลในเครื่อง | กลับมาหน้าตรวจยอด ไม่ข้ามเข้าแอปเงียบๆ |

## ตัดสินใจ
1. **Dexie ไม่ถูกลบโดยโค้ดใดๆ**: ต้นทางอ่านอย่างเดียว (`exportSnapshot`) มีเทสต์ว่าสำเนาต้นทางไม่เปลี่ยนแม้แต่ไบต์เดียวหลังย้าย + เทสต์ค้นโค้ด (`importBoundary.test.ts`) ห้าม `resetAll/clear/delete` กับข้อมูลในเครื่องในโค้ดย้าย/หน้าย้าย · ปุ่มที่ล้างได้ในหน้าย้ายล้าง **เฉพาะข้อมูลออนไลน์** (ต้องใส่รหัสผ่าน จำกัด 5 ครั้ง/15 นาที)
2. **ลำดับบังคับ**: ปุ่มถัดไปเปิดหลังดาวน์โหลดไฟล์สำรองสำเร็จเท่านั้น · ปุ่ม "ใช้งานบัญชีออนไลน์ต่อ" เปิดเมื่อ `verifyImport` ตรงทุกข้อ **และ** เจ้าของติ๊ก "ฉันตรวจยอดแล้ว" · ไม่ตรง = ไม่มีปุ่มไปต่อ
3. **ธงสถานะ** `mb.migration.<userId>` ใน localStorage (`none/pending/confirmed`): ตั้ง `pending` ก่อนนำเข้า, `confirmed` เมื่อเจ้าของยืนยัน · แก้เองได้แต่กระทบแค่ตัวเอง (หน้าจอเท่านั้น ข้อมูลบนเซิร์ฟเวอร์ไม่เปลี่ยน) · `pending` พาไปหน้าตรวจยอดเฉพาะเมื่อเป็นเจ้าของข้อมูลในเครื่อง
4. **ตัวแปรเลือก repository ระดับโมดูล** (`setActiveLedgerRepository`) ให้ปุ่มสำรองของ ErrorBoundary ใช้แหล่งเดียวกับที่ผู้ใช้เห็น · ไม่ล้างตอน unmount (แอปล้ม = subtree ถูกถอด ปุ่มสำรองยังต้องใช้ได้) ล้างตอนออกจากระบบ · ถ้าไม่มี repository ออนไลน์: ดาวน์โหลดข้อมูลในเครื่องได้เมื่อไม่มีใครล็อกอิน / เป็นเจ้าของ / ยังไม่มีเจ้าของ เท่านั้น
5. **ล้างข้อมูลออนไลน์ในแอป** ต้องใส่รหัสผ่านผ่านหน้าต่างเดียวกันทุกที่ (`PasswordPrompt`) แทน `window.confirm` เดิมที่ไม่ถามรหัส · ยกเลิก/รหัสผิดแจ้งทาง toast
6. **นำเข้าไม่สำเร็จ** (ถูกปฏิเสธ/ล้ม และออนไลน์ยังว่าง) → เคลียร์ธง `pending` กันเปิดใหม่แล้วเจอปุ่มล้างข้อมูลออนไลน์ของข้อมูลที่ไม่ได้มาจากการนำเข้านี้ · หน้าตรวจยอดที่ไม่ตรงแสดงจำนวนข้อมูลออนไลน์ที่ปุ่มล้างจะลบก่อนกด (ผล money-auditor)

## ผลตรวจ
- **money-auditor:** Dexie ไม่มีทางเปลี่ยน/หาย ยืนยัน · แก้: ธง pending ค้างหลังนำเข้าล้ม (ข้อ 6) · `money()` เมื่อแสดงไม่ได้ขึ้น "—" ไม่ใช่เลขดิบ · คำเตือนเมื่อค่าตั้งค่าที่ไม่รู้จักถูกข้าม · ข้อเสนอเทียบกับ snapshot ดิบ: ไม่ทำ เพราะ `parseBackup` ปฏิเสธทั้งไฟล์ถ้ารายการใดเสีย จำนวนที่ผ่านการตรวจจึงเท่ากับจำนวนดิบเสมอ
- **security-auditor:** ฝั่งเซิร์ฟเวอร์ไม่มีทางรั่วข้ามผู้ใช้ · แก้: ปุ่มสำรองตอนแอปล้มไม่อ่านข้อมูลในเครื่องของบัญชีอื่น (ข้อ 4) · หน้าตรวจยอดเปิดได้เฉพาะเจ้าของข้อมูลในเครื่อง
- **design-critic:** แก้: ยืนยันซ้อน 2 ชั้นตอนล้าง → ด่านเดียว (หน้าต่างรหัสผ่าน มีปุ่ม "ล้างข้อมูลออนไลน์"), หน้า error บอกว่าข้อมูลเดิมปลอดภัย, ปุ่มที่กดไม่ได้บอกเหตุผล (`aria-describedby`), โฟกัสย้ายไปหัวข้อของขั้นใหม่, ตารางเลื่อนด้วยคีย์บอร์ดได้ + คอลัมน์ชื่อบัญชีตรึง, ข้อความไม่อ้าง "ผู้ดูแลระบบ" (ผู้ใช้คือเจ้าของ), ask-bind ใช้คำว่า "ยืนยันว่าข้อมูลนี้เป็นของฉัน"

## ความเสี่ยงที่ยอมรับชั่วคราว (มีวันเลิกใช้)
- **ask-bind:** ผู้ใช้ B บนเบราว์เซอร์ที่มีข้อมูลเก่าของ A ซึ่งยังไม่เคยมีเจ้าของ กด "เป็นของฉัน" แล้วย้ายขึ้นบัญชีของ B ได้ · เกิดได้เฉพาะเบราว์เซอร์ที่มีข้อมูลเก่าจริง (ของเจ้าของ ซึ่งผูกกับ `kumeyuri` แล้ว จึงไม่เกิดอีก) · **เลิกใช้**: ลบทางนี้หลังเจ้าของยืนยันการย้ายข้อมูลสำเร็จและก่อนเชิญผู้ใช้จริง (M2-F)
- **ปุ่ม "ดาวน์โหลดข้อมูลที่เก็บในเครื่องนี้" หน้าล็อกอิน** (เจ้าของสั่งชั่วคราว): ไม่เช็กเจ้าของ · **เลิกใช้**: ลบพร้อม ask-bind
- บันทึกใน HANDOFF แล้ว

## ยังไม่ทำ
- ปุ่ม "นำเข้าจากไฟล์สำรอง" ให้ผู้ใช้ทั่วไปเลือกไฟล์เอง (ตอนนี้นำเข้าได้เฉพาะจากข้อมูลในเครื่องผ่านหน้าย้ายข้อมูล) · การนำเข้าแบบแบ่งชุดสำหรับไฟล์เกิน 1,500 รายการ
- ทดสอบหน้าจอด้วยเบราว์เซอร์จริง: **เจ้าของต้องลองเอง** ก่อนกดนำเข้า (ผมไม่มีเบราว์เซอร์ทดสอบ)
