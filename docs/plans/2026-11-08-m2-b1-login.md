# แผนสั้น M2-B1: ล็อกอินด้วย username + password (ส่วนที่ไม่ต้องใช้ key)

ต่อจากแผนหลัก `2026-11-04-m2-multi-user.md` ข้อ 4.5 · เจ้าของสั่ง 8 พ.ย. 2569: เริ่ม M2-B ส่วนที่ไม่ต้องใช้ key ถึงขั้นที่ต้องใช้ `admin.env` ให้หยุดรอ · **JWT expiry ตั้งไม่ได้ (ค่าเริ่มต้น 1 ชั่วโมง) → `reset-password.mjs` ต้องลบ session ทั้งหมดของผู้ใช้เสมอ** (ทำใน B2)

## ขอบเขต B1 (PR นี้)

| ส่วน | ไฟล์ | หมายเหตุ |
|---|---|---|
| โดเมน | `src/domain/auth/credentials.ts` | `usernameToEmail` (`<username>@users.money-buddy.internal`), กฎ username, `passwordProblem` (≥ 10, ≤ 72 ไบต์, ไม่เท่า username, ไม่ใช่รหัสยอดนิยม/ซ้ำ/เรียงลำดับ) |
| use case | `src/app/auth.ts` | `signIn`, `changePassword` (ยืนยันรหัสเดิมก่อน), `gateStateFromProfile`, แปลง error เป็นข้อความไทย (ล็อกอินผิดทุกกรณีข้อความเดียวกัน) · รับ API ผ่าน interface ทดสอบได้โดยไม่ต่อเน็ต |
| client | `src/storage/supabase.ts` | อ่านเฉพาะ `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` · ไม่มี `signUp` |
| UI | `src/ui/AuthGate.tsx`, `LoginPage.tsx`, `ChangePasswordForm.tsx`, `AccountView.tsx` | ไม่ล็อกอิน = เห็นแต่หน้าเข้าสู่ระบบ · ธง `must_change_password` = เห็นแต่หน้าเปลี่ยนรหัส · เมนู "โปรไฟล์" (เปลี่ยนรหัส + ออกจากระบบ) |

## ที่ไม่ทำใน B1

- สคริปต์ `create-user.mjs`/`reset-password.mjs`, เทสต์รักษากติกา key, spike โดเมนอีเมลกับ GoTrue จริง → **B2 (ต้องใช้ `admin.env` หยุดรอเจ้าของ)**
- ข้อมูลยังอยู่ใน Dexie ในเครื่อง (M2-C ค่อยย้ายขึ้น Supabase) → ผู้ใช้หลายคนที่ใช้เบราว์เซอร์เดียวกันจะเห็นข้อมูล Dexie ชุดเดียวกัน (ดู decisions)

## ลำดับ

เทสต์ก่อน (credentials, use case ด้วย fake API) → โค้ด → `npm test` + `typecheck` + `build` → `security-auditor` + `design-critic` → PR
