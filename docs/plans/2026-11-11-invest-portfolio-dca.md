# แผน: พอร์ตลงทุน + DCA (ร่าง รอเจ้าของตอบคำถาม)

สถานะ: **แผนเท่านั้น ยังไม่มีโค้ด** · ที่มา: product-advisor + money-auditor (11 พ.ย. 2569) · กฎเงินใหม่เสนออยู่ใน `docs/money-rules-R17-proposal.md` (ยังไม่เป็นกฎ ห้ามเขียนลง `money-rules.md` จนเจ้าของอนุมัติ)

## ข้อจำกัดที่เจ้าของกำหนด
- รุ่นแรกผู้ใช้กรอกราคาเอง ห้ามดึงราคาจากเว็บ (CSP + ไม่มีค่าใช้จ่าย)
- จำนวนหน่วยมีทศนิยม · ข้อมูลแยกต่อผู้ใช้ด้วย RLS · ดีไซน์ Aurora Glass
- เฟสเล็ก merge ได้ทีละอัน · เฟสที่ใช้ migration เปิด PR เป็น draft รอเจ้าของใส่

## สิ่งที่พบที่ทำให้แผนต้องระวัง
1. **R11 บังคับ FIFO** แต่เจ้าของ/โบรกเกอร์ไทยใช้ต้นทุนเฉลี่ย → ตัวเลขกำไรขายต่างกัน ต้องให้เจ้าของเลือก (คำถาม 1)
2. **R9 กำหนดจำนวนหุ้น 10^6** แต่ R17 เสนอ 10^8 (คริปโต/เหรียญราคาสูง) → ต้องมติแก้ R9 เรื่องจำนวนหน่วย
3. **`cashBalance` นับบัญชีสินทรัพย์บาททุกบัญชี** (`src/domain/ledger/overview.ts`) ถ้าเพิ่มบัญชีพอร์ตแบบธรรมดา SAFE-TO-SPEND/RUNWAY จะสูงเกินจริง → บัญชีลงทุนต้องมีป้าย (ต้อง migration) และถูกตัดออกจาก `cashBalance`
4. **ข้อมูลหลักอยู่บน Supabase** เฟสแรกจึง **ห้ามเก็บพอร์ตในเบราว์เซอร์** (จะหลุดจากไฟล์ดาวน์โหลด/การลบบัญชี/ข้ามเครื่อง) → เฟส 1 ไม่บันทึกข้อมูล
5. `mulMicro`/`mulDivRound`/`parseMicro` เดิมใช้กับหน่วย 10^8 ไม่ได้ (ผิดสเกล 100 เท่า, รับเลขลบ, ใช้ number) → ต้องมีฟังก์ชัน bigint ใหม่ ดู R17

## ตารางใหม่ (ร่าง, ยืนยันตอนทำ P2)
- `assets(id, user_id, name, kind, currency='THB', archived, created_at)`
- `trades(id, user_id, asset_id, kind buy|sell|dividend, date, units text, price_micro bigint, amount_satang bigint, fee_satang bigint, entry_id null→P4, memo)`
- `asset_prices(asset_id, user_id, date, price_micro bigint)` (ราคาที่ผู้ใช้กรอก มีวันที่ ไม่ดึงจากเว็บ)
- ทุกตาราง RLS `user_id = auth.uid()` ตามแบบเดิม + จำกัดความยาวชื่อ/หมายเหตุให้ตรง DB (R17/MAX_NAME_LENGTH)

## ความเสี่ยงด้านผลิตภัณฑ์ (ต้องออกแบบหน้าจอรับมือ)
- ทุกมูลค่าต้องบอก "ราคา ณ วันที่…" เก่ากว่า 7 วันเตือน ยังไม่กรอกราคาแสดง "—" ห้ามใช้ราคาทุนแทนเงียบๆ
- ใช้คำ "กำไร/ขาดทุนจากต้นทุน (ยังไม่ขาย / ขายแล้ว)" ไม่ใช้ "ผลตอบแทน %" และไม่แสดงต่อปีรุ่นแรก
- อธิบายวิธีคิดต้นทุนบนหน้าจอ (ตัวเลขอาจต่างจากแอปโบรกเกอร์)
- ปันผลแยกจากกำไรขาย ไม่รวมต้นทุน · ระบุว่ากรอกก่อน/หลังหักภาษี
- DCA: ข้อความ "เครื่องคิดเลข ไม่ใช่คำแนะนำการลงทุน"
- เตือนเมื่อราคาที่กรอกต่างจากครั้งก่อนมากผิดปกติ (กันจุดทศนิยมผิด 100 เท่า)

## ตัดออกจากรุ่นแรก
ดึงราคาเว็บ · สกุลเงินต่างประเทศ/FX (เสนอเป็น R18 ภายหลัง) · ภาษี (R13) · ออปชัน (R12) · ปรับสมดุลพอร์ต · XIRR/CAGR · กราฟมูลค่าย้อนหลัง · แตกพาร์/หุ้นปันผลซับซ้อน · DCA ที่ระบบบันทึกเองอัตโนมัติ · พอร์ตร่วม/แชร์

## คำถามที่ต้องให้เจ้าของตอบ
1. กำไรตอนขายใช้ **FIFO (R11 เดิม)** หรือ **ต้นทุนเฉลี่ย** (ถ้าเฉลี่ย ต้องอนุมัติแก้ R11)
2. ซื้อแล้ว **หักเงินจากกระเป๋า** ไหม: (ก) แยกขาด (ข) ผูกทุกครั้ง ← แนะนำ (ค) เลือกได้ · ของที่ถืออยู่ก่อนใช้แอปบันทึกเป็นยอดยกมา
3. การ์ดมูลค่าสุทธิในหน้าภาพรวมรวมพอร์ตไหม (ราคาทุน หรือราคาที่กรอกล่าสุด)
4. รุ่นแรกรับเฉพาะเงินบาทได้ไหม (แนะนำ ได้)
5. ลงทุนอะไรเป็นหลัก (กองทุน/หุ้นไทย/คริปโต) → ตัดสินจำนวนทศนิยมและคำบนหน้าจอ
6. DCA แค่ตัวเตือน (แนะนำ) หรือให้ระบบสร้างรายการรอยืนยัน
7. (จาก R17) ค่าธรรมเนียมนับเข้าต้นทุนไหม · กำไรขายเป็นรายรับ/ขาดทุนเป็นรายจ่ายหมวดลงทุนแล้วแยกรายงาน หรือไม่รวมในรายรับรายจ่าย
