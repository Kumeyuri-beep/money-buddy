# แผนสั้น: นำเข้าแบบแบ่งก้อนสำหรับไฟล์เกิน 1,500 รายการ (9 พ.ย. 2569)

เป้าหมาย: ไฟล์สำรอง/ข้อมูลในเครื่องที่มีรายการ 1,501-10,000 รายการนำเข้าได้ โดยไม่ชนเพดานเวลาของคำสั่งเดียว (~8 วินาที) · กฎที่แตะ: R1, R15, R16 (ผ่านตัวตรวจ/ทริกเกอร์เดิม) และ PDPA

แนวทาง (แนะนำ): เซสชันนำเข้าในฐานข้อมูล
- `import_ledger_begin` (บัญชี บิล ตั้งค่า + ก้อนแรก + จำนวนรายการทั้งหมด) · `import_ledger_append` (ก้อนถัดไป) · ครบพอดีจึงปิดเซสชัน
- ขณะเซสชันเปิด: เขียนทางอื่นถูกบล็อกด้วย RLS restrictive · `import_ledger_abort` ล้างส่วนที่ค้างโดยไม่ถามรหัสผ่าน (ใช้ได้เฉพาะขณะเซสชันเปิด) · `import_ledger_status` ให้แอปพาไปหน้าล้างถ้าค้าง
- ไฟล์ ≤ 1,500 รายการและ ≤ 20,000 บรรทัดใช้ `import_ledger` อะตอมมิกเดิมไม่เปลี่ยน
ทางเลือกที่ไม่เอา: ฝากก้อนใน staging แล้ว commit ครั้งเดียว (ช้าเท่าเดิม ชนเพดานเวลาเหมือนกัน) · แบ่งก้อนที่ฝั่งเว็บอย่างเดียวโดยไม่มีเซสชัน (ปล่อยข้อมูลครึ่งเดียวได้ ไม่มีทางรู้ว่าค้าง)

ขั้นตอน: เทสต์ก่อน (chunker, repository, parseBackup constants) → migration + เทสต์ SQL (รอเจ้าของอนุมัติก่อนใส่) → แอป (repository, ด่านเลือกแหล่งข้อมูล, หน้าล้างส่วนค้าง, ความคืบหน้า) → ผู้ช่วยตรวจ security/money/design
