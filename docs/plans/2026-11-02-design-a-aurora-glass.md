# แผน: เปลี่ยนหน้าตาเป็นดีไซน์ A "Aurora Glass" (Ticket A1-A5)

> สถานะ: **เจ้าของอนุมัติแผนแล้ว** (2 พ.ย. 2569) · เริ่ม A1
> อ้างอิงดีไซน์: `docs/design/A-aurora-glass.dc.html` · token สีและโครงหน้า: `docs/HANDOFF.md` ข้อ 7
> กฎที่เกี่ยว: `docs/money-rules.md` (R16 และการตีความ `roundHalfUp` ย้ายเข้าแล้ว) · SAFE-TO-SPEND ยึด R15 (ดูข้อ 7)

## 1. เป้าหมาย / ไม่ใช่เป้าหมาย

**เป้าหมาย**
- หน้า "ภาพรวม" (แทนหน้า "วันนี้") หน้าตาตามดีไซน์ A ใช้ข้อมูลจริงจากสมุดบัญชีเท่าที่มี
- การ์ดไหนยังไม่มีข้อมูลจริง แสดง **สถานะว่าง** ห้ามใส่ตัวเลขปลอม
- แบ่งส่งงานเป็น 5 Ticket ทีละชิ้น รอเจ้าของยืนยันก่อนไปชิ้นต่อไป

**ไม่ใช่เป้าหมาย (ไม่ทำในแผนนี้)**
- ฟีเจอร์บิลประจำ, เป้าออม, เป้างบเดือน, พอร์ตลงทุน, เป้าเกษียณ → แสดงสถานะว่างเท่านั้น
- SAFE-TO-SPEND ที่คำนวณจริง (ยึดสูตร R15 ตามข้อ 7 ทำใน Ticket บิล/เป้าออมภายหลัง)
- สแกนสลิป (M1-B4), แถบเมนูล่างมือถือ, ชื่อผู้ใช้ (รอ M2)
- ไม่แก้ `db.ts` / ไม่เปลี่ยน schema จึง **ไม่ต้องทำ Snapshot/Migration**

**ข้อห้าม (anti-goals):** ตัวเลขปลอมบนหน้าจอ · สูตรเงินใน React · `Math.round` / float กับยอดเงิน · กระจกแท้เกิน 8 ใบ

## 2. การตัดสินใจของเจ้าของ (ตอบในการซักครั้งนี้)

| # | เรื่อง | คำตอบ |
|---|---|---|
| 1 | ชนิดพื้นผิว | กระจกแท้ (`backdrop-filter`) เฉพาะการ์ดสรุป 8 ใบ · **glass-lite** (โปร่งแสง+ไล่เฉด+ขอบไฮไลต์ ไม่มี blur) สำหรับแถบเมนู หัวหน้า Sankey กระเป๋า บิล เป้าเกษียณ · รายการล่าสุดพื้นทึบ · ทั้งหมดกลายเป็นพื้นทึบเมื่อ `prefers-reduced-transparency` (บันทึกใน CLAUDE.md แล้ว) |
| 2 | การ์ดข้อมูลไม่ครบ | คำนวณจากสมุดบัญชีเมื่อพอ · ว่างสองแบบ: **"ตั้งค่า… →"** (ต้องมีฟีเจอร์/การตั้งค่า) กับ **"รอข้อมูลเดือนหน้า"** (รอข้อมูลสะสม) |
| 3 | Sankey | 3 คอลัมน์ ไม่มีโหนด "บิลประจำ" ก่อน · หมวด < 4% ของรายรับรวมเป็น "อื่นๆ" · ใช้เกินรายรับ → "ใช้เกินรายรับ" สีส้ม |
| 4 | เมนู/หัวหน้า | เมนูครบตามดีไซน์ A หน้าที่ยังไม่มี = disabled "เร็วๆ นี้" · ไม่ใส่ชื่อ ไม่มี badge · ซ่อนปุ่มสแกนสลิป · การ์ดโปรไฟล์เขียน "บัญชีในเครื่องนี้" |
| 5 | Ticket | 5 Ticket · `money-auditor` เฉพาะ A2, A4 · `design-critic` เฉพาะ A3, A5 · A1 เจ้าของตรวจด้วยตา · จบทุก Ticket ด้วย `/ship` แล้วรอยืนยันก่อน push |
| 6 | Integrity Check | ท้ายแถบเมนูซ้าย (แทน "บันทึกอัตโนมัติแล้ว") จุดเขียว/แดง + แถบเตือนบนหน้าเมื่อพบปัญหา |

**ค่าเริ่มต้นที่ผมตั้งเอง (ค้านได้ตอนอ่าน)**
- A. เลิกใช้ฟอนต์ Fraunces ใช้ IBM Plex Sans Thai อย่างเดียว ตัวเลข `tabular-nums` (ตัดออกจากลิงก์ใน `index.html`)
- B. ยังใช้ id หน้า `today` ในโค้ดเดิม เปลี่ยนแค่ป้ายเมนูเป็น "ภาพรวม" (ลดการแก้นอกขอบเขต)
- C. เป้าอัตราออม 20% และเป้า runway 6 เดือน เป็นค่าคงที่เริ่มต้นใน config กลาง (ตามดีไซน์) แสดงเป็น "เป้าเริ่มต้น" ยังไม่ให้ผู้ใช้แก้
- D. "ออม+ลงทุนรวม" ในดีไซน์ ใช้เป็น "คงเหลือสุทธิ" (รายรับ − รายจ่าย) เพราะยังไม่มีบัญชีออม/ลงทุนแยก
- E. RUNWAY: เงินสด = ผลรวมบัญชี `asset` สกุล THB ที่ไม่ถูกเก็บถาวร (ยังไม่มีธงแยก "พอร์ต" จึงไม่เขียนว่า "ไม่รวมพอร์ต") ÷ ค่าใช้จ่ายเฉลี่ยของเดือนที่ครบสมบูรณ์ล่าสุดไม่เกิน 3 เดือนที่มีรายจ่าย
- F. หน้าไม่มี badge, ไม่มีชื่อผู้ใช้, ไม่มีรูปโปรไฟล์ปลอม

## 4. Tickets

### A1 — โทเคน + พื้นผิว + โครงหน้า + เมนู + หัวหน้า  *(ไม่มีสูตรเงิน · เจ้าของตรวจด้วยตา)*
**ขอบเขต:** `styles.css`, `Shell.tsx`, `App.tsx`, `index.html`, ส่วนหัวใน `Today.tsx`
- โทเคนสี/ระยะ/รัศมีจากดีไซน์ A; ก้อนแสงเบลอ 4 สี; class `glass` (blur 32px) / `glass-lite` / `solid`; fallback `prefers-reduced-transparency` และ `@supports not (backdrop-filter)` → พื้นทึบ `#171a26`
- แถบเมนู: โลโก้ MB, คำขวัญ, การ์ดโปรไฟล์ "บัญชีในเครื่องนี้", เมนูหลัก 5 + เครื่องมือ 4 (ไอคอนเส้น SVG), เฉพาะ "ภาพรวม" กับ "รายรับ-รายจ่าย" ใช้งานได้ ที่เหลือ disabled "เร็วๆ นี้" ไม่มี badge
- ท้ายเมนู: สถานะ Integrity Check จริง (จุดเขียว/แดง) + แถบเตือนบนหน้าเมื่อพบปัญหา (ใช้ `runIntegrityCheck` เดิม)
- หัวหน้า (glass-lite ทรงแคปซูล): ทักทายตามเวลา (เช้า/บ่าย/เย็น) + วันที่ไทย, ช่องพิมพ์จดด่วน (ใช้ `QuickAdd` เดิม), ปุ่ม "เพิ่มรายการ" สีทอง · ไม่มีปุ่มสแกนสลิป
- ปุ่ม/เป้าสัมผัส ≥ 44px, โฟกัสคีย์บอร์ดเห็นชัด, ตัดฟอนต์ Fraunces
**เทสต์:** เทสต์ฟังก์ชันทักทายตามเวลา (ขอบ 04:59/05:00, 11:59/12:00, 16:59/17:00 ฯลฯ) และวันที่ไทย · typecheck/build ผ่าน · เทสต์เดิม 170 ตัวต้องยังผ่าน
**ตรวจ:** เจ้าของตรวจด้วยตา + เช็คคอนทราสต์ WCAG AA ของข้อความบนกระจก (ผมตรวจค่าสีให้ในสรุป) · ไม่เรียกผู้ช่วย
**Commit:** `[UI] A1 โทเคนดีไซน์ A + เมนู + หัวหน้า` (ไม่แตะกฎเงิน)

### A2 — ฟังก์ชัน domain ของการ์ดสรุป  *(ไม่มี UI · `money-auditor`)*
**ขอบเขต:** `src/domain/ledger/overview.ts`, `src/app/overview.ts`, `tests/unit/overview.test.ts`
ฟังก์ชัน (ทุกตัวรับ `accounts`, `entries`, วันที่อ้างอิง; สกุล THB):
1. `netWorthAt(accounts, entries, date)` = Σ ยอดธรรมชาติ `asset` − Σ `liability` ณ สิ้นวัน
2. `netWorthMonthlySeries(...)` จุดสิ้นเดือนย้อนหลังสูงสุด 12 จุด เริ่มตั้งแต่เดือนที่มีรายการแรก
3. `monthOverMonth(accounts, entries, month)` รายจ่ายเดือนนี้เทียบเดือนก่อน → basis points (ว่างเมื่อเดือนก่อนไม่มีรายจ่าย)
4. `savingsRate(income, net)` → basis points (ว่างเมื่อรายรับ = 0; ค่าติดลบได้)
5. `runwayTenths(cash, expenseHistory)` → จำนวนเดือน ×10 จำนวนเต็ม (ว่างเมื่อไม่มีเดือนที่ครบสมบูรณ์ที่มีรายจ่าย)
6. `incomeChannels(...)` จำนวนบัญชีรายรับที่มียอดในเดือน + กระเป๋าที่รับเงินมากสุด
7. ตัวประกอบสถานะการ์ด (`value` / `needs-setup` / `waiting-data`) ใน `src/app/overview.ts`
**เทสต์ขอบเขต (R14):** ยอด 0 · สมุดบัญชีว่าง · รายการเดียว · น้อยมาก (1 สตางค์) · วันสิ้นเดือน/สิ้นปี/ปีอธิกสุรทิน (29 ก.พ.) · เดือนแรกที่ไม่มีเดือนก่อน · หารด้วยศูนย์ · ปัดครึ่ง (ค่าบวก/ลบ) · ยอดใหญ่ใกล้ `MAX_SAFE_INTEGER` · ค่าติดลบ (ใช้เกินรายรับ, หนี้มากกว่าทรัพย์สิน) · รายการ `system` (ยอดยกมา) ไม่ถูกนับเป็นรายรับ · Transfer/จ่ายเงินต้นหนี้ไม่ถูกนับเป็นรายรับรายจ่าย (R4)
**ตรวจ:** `money-auditor` (R1, R2, R4, R8, R14, R16) · พร้อมสรุปและวิธีทดสอบ
**Commit:** `[R1,R2,R4,R8,R14,R16] A2 ฟังก์ชันสรุปภาพรวม`

### A3 — การ์ดสรุป 8 ใบ  *(`design-critic`)*
**ขอบเขต:** `src/ui/Today.tsx` (แยกคอมโพเนนต์ย่อยใหม่ใน `src/ui/overview/`), `styles.css`
- แถวที่ 1: NET WORTH (+ เส้นแนวโน้ม SVG, ส่วนต่างเทียบเดือนก่อน) · INCOME · OUTGOING (ยอดรวมจริง ส่วนแยกบิล/ใช้จ่ายเป็น "ตั้งค่า…") · SURPLUS
- แถวที่ 2: SAFE-TO-SPEND (**ว่างทั้งใบ** "ตั้งค่าบิลและเป้าออม →") · SAVINGS RATE · VS LAST MONTH · RUNWAY
- กระจกแท้ครบ 8 ใบพอดี ห้ามเกิน · การ์ดว่างแสดงข้อความสองแบบตามข้อ 2 · ไม่มีตัวเลขปลอม
- ตัวเลขสีตามความหมาย (รายรับเขียว รายจ่ายแดง เตือนส้ม) ไม่พึ่งสีอย่างเดียว (มีป้ายข้อความ/เครื่องหมาย)
- ลิงก์ "ดู… →" เฉพาะที่มีหน้าปลายทางจริง
**เทสต์:** เทสต์ฟังก์ชันจัดรูปแบบ (ร้อยละจาก basis points, "4.3 เดือน") · เทสต์ว่าสถานะการ์ดมาจาก `src/app/overview.ts` ตามกรณีต่างๆ · typecheck/build
**ตรวจ:** `design-critic` (สไตล์, WCAG AA, คีย์บอร์ด, จำนวนกระจก)
**Commit:** `[R1,R2,R4,R16] A3 การ์ดสรุป 8 ใบ`

### A4 — Sankey Cash Flow  *(`money-auditor` + ตรวจหน้าจอด้วยตา)*
**ขอบเขต:** `src/domain/ledger/sankey.ts`, `src/ui/overview/CashFlowSankey.tsx`, `tests/unit/sankey.test.ts`
- `buildCashFlow(accounts, entries, month)` → โหนด/ลิงก์เป็นสตางค์จำนวนเต็ม: แหล่งรายรับ → งบรวม → หมวดรายจ่าย + "เหลือเก็บ" (หรือ "ใช้เกินรายรับ")
- รวมหมวด < 4% ของรายรับเป็น "อื่นๆ" โดย **ผลรวมทุกลิงก์ต้องเท่ากับยอดรวมพอดี ไม่คลาดเคลื่อนแม้ปัดเศษ** (ร้อยละใช้แสดงเท่านั้น คำนวณจากสตางค์ด้วย `roundHalfUp`; ไม่ใช้ร้อยละคำนวณยอด)
- ความสูงโหนดคำนวณจากสัดส่วนสตางค์ด้วยจำนวนเต็ม แปลงเป็นพิกเซลที่ชั้น UI เท่านั้น; ลิงก์เล็กมากมีความสูงขั้นต่ำเพื่อมองเห็น
- ตัวเลือกเดือน (เฉพาะเดือนที่มีรายการ) + ชิปสรุป · เดือนไม่มีข้อมูล = สถานะว่าง · หมวดมากสุด 5 หมวด + อื่นๆ
- ป้ายชื่อ/ยอดอยู่ข้างแท่ง ตัวหนังสือ ≥ 13px สีคอนทราสต์ผ่าน AA ไม่ซ้อนบนแถบสี; `role="img"` + `aria-label` สรุปเป็นข้อความ + ตารางข้อความสำรองสำหรับโปรแกรมอ่านหน้าจอ
- glass-lite (ไม่มี blur)
**เทสต์ขอบเขต (R14):** เดือนว่าง · รายรับ 0 แต่มีรายจ่าย · รายจ่ายเท่ารายรับพอดี (เหลือเก็บ 0) · เกินรายรับ · หมวดเดียว · หมวดทั้งหมด < 4% · หมวดตรง 4% พอดี · ผลรวมลิงก์ = ยอดรวม (property test หลายชุดสุ่มแบบกำหนด seed) · หลายแหล่งรายรับ · Transfer ไม่โผล่ใน Sankey (R4) · วันสิ้นเดือน/ขอบเดือน
**ตรวจ:** `money-auditor` (R1, R2, R4, R8, R14, R16) + เจ้าของตรวจความอ่านง่ายด้วยตา (ไม่เรียก `design-critic` ตามที่ตกลง)
**Commit:** `[R1,R2,R4,R8,R14,R16] A4 Cash Flow Sankey`

### A5 — กระเป๋า + รายการล่าสุด + การ์ดสถานะว่าง  *(`design-critic`)*
**ขอบเขต:** `src/ui/overview/*`, `styles.css`
- กระเป๋าเงิน (glass-lite): ชื่อ + ยอดคงเหลือจริง + แถบสัดส่วน % ของทั้งหมด (คำนวณใน domain/app ไม่ใช่ UI; กระเป๋าติดลบ/ยอดรวม 0 ไม่ทำให้หารด้วยศูนย์)
- รายการล่าสุด (พื้นทึบ): จัดกลุ่ม "วันนี้ / เมื่อวาน / วันที่" ไอคอนตามประเภท (รายรับ/รายจ่าย/โอน) สี+เครื่องหมาย +/− ไม่ใช้สีอย่างเดียว · ใช้ `describeEntry` เดิม
- บิลที่จะถึง (glass-lite): **สถานะว่าง** "ตั้งค่าบิลประจำ →" (ยังไม่มีฟีเจอร์)
- เป้าเกษียณปีนี้ + สัดส่วนพอร์ต (glass-lite): **สถานะว่าง** "ตั้งค่าเป้าเกษียณ →" / "ยังไม่มีพอร์ต"
- ลิงก์ "ดูสมุดบัญชี →" ไปหน้ารายรับ-รายจ่ายเดิม
**เทสต์:** ฟังก์ชันสัดส่วนกระเป๋า (ยอด 0, ติดลบ, กระเป๋าเดียว, ปัดเศษรวมได้ 100% เมื่อแสดง) · การจัดกลุ่มวันที่ (ขอบเที่ยงคืน, สิ้นเดือน, ข้ามเดือน/ปี) · typecheck/build
**ตรวจ:** `design-critic`

## 5. วิธีทำงานทุก Ticket

Spec สั้น → เขียนเทสต์ (TDD) → โค้ด → `npm test` + `npm run typecheck` + `npm run build` → สรุปผลและวิธีทดสอบ → (ผู้ช่วยตามที่ระบุ) → `/ship` → **หยุดรอเจ้าของยืนยัน** ก่อน push และก่อนไป Ticket ถัดไป · ทำใน session นี้เอง ไม่ใช้ subagent-driven / parallel agents · ทำบน `main` ไม่มี worktree · ไม่ push/merge/เปิด PR เอง
เกณฑ์เสร็จของทุก Ticket: เทสต์เดิม (170 ตัว) ผ่านหมด + เทสต์ใหม่ผ่าน + `verification-before-completion` ก่อนรายงานว่าเสร็จ

## 8. เรื่องที่ยังเปิดอยู่ (ไม่บล็อกแผนนี้)

**ผลการตัดสินใจหลัง A2 (เจ้าของ 3 พ.ย. 2569)**
- VS LAST MONTH เทียบ "ช่วงเดียวกัน": วันที่ 1 ถึงวันนี้ ของเดือนนี้ vs เดือนก่อนช่วงวันเดียวกัน (เดือนก่อนสั้นกว่าตัดที่วันสุดท้าย) · A3 ต้องติดป้ายการ์ดว่า **"เทียบช่วงเดียวกันเดือนก่อน"** (ไม่ต้องมีป้าย "เดือนนี้ยังไม่จบ" แล้ว) · ทำใน A2 แล้ว (`monthOverMonth(accounts, entries, asOf)`)

**งานค้าง (backlog)**
- **Entry ผสม:** Entry เดียวที่มีทั้งบรรทัดรายรับและการโอน อาจทำให้ `incomeChannels` นับยอดฝั่งโอนเป็น "รับจากรายรับ" ตอนนี้ระบบสร้าง Entry แบบนี้เองไม่ได้ จึงปล่อยไว้ · ต้องแก้ก่อนมีฟีเจอร์ที่สร้าง Entry ผสม (นำเข้า/แยกรายการ)
- **ยอดใหญ่:** `ratioBps`/`runwayTenths` throw `RangeError` เมื่อยอดเกินช่วงปลอดภัย (ส่วนต่าง ≳ 9×10⁹ บาท) และ `buildOverview` ไม่ดักข้อผิดพลาด · ยอมรับไว้ก่อน
