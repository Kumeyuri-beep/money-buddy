# แผน: กู้ไฟล์สำรองเมื่อมีหมวดค้างอยู่ (backlog ข้อ 1 · security-auditor ต2) — รอเจ้าของอนุมัติ ยังไม่ลงมือ

## ปัญหา (อ่านจากไฟล์ migration และ src/ · ยังไม่ได้ทำซ้ำบนฐานข้อมูล)
- `import_ledger` และ `import_ledger_begin` ปฏิเสธเมื่อมี accounts / entries / bills / settings (หรือเซสชันค้าง) แต่ **ไม่นับ `asset_categories`** ซึ่งไม่ผูกกับ accounts
- ถ้ามีหมวดค้างโดยไม่มีบัญชี:
  1. สมุดบัญชีนำเข้าสำเร็จ แล้ว `import_ledger_investments` ปฏิเสธ (23505) → **กู้ได้ครึ่งเดียว** (ทั้งทางครั้งเดียวและทางแบ่งก้อน เมื่อไฟล์มีข้อมูลลงทุน)
  2. ทางแบ่งก้อน: ถ้าล้มกลางทาง `import_ledger_abort` ลบ `asset_categories` ทั้งหมด → **ลบหมวดที่มีก่อนการนำเข้า**
- โอกาสเกิดต่ำ: หน้า Categories เข้าได้หลังมีบัญชีแล้ว จึงต้องมาจากแท็บค้างหลังล้างข้อมูล หรือเรียก RPC `save_categories` ตรงๆ (ฟังก์ชันไม่บังคับว่าต้องมีบัญชี)

## ทางแก้
### 1) ฐานข้อมูล: migration ใหม่ (แบบ "เพิ่ม": create or replace function เท่านั้น)
`20261127000100_import_refuses_categories.sql`
- `import_ledger` และ `import_ledger_begin`: เพิ่ม `or exists (select 1 from public.asset_categories where user_id = v_user)` ในด่าน "มีข้อมูลอยู่แล้ว" (23505) **ก่อนเขียนอะไรทั้งสิ้น**
- ถือล็อก `categories:<user>` ต่อจากล็อก `import_ledger:<user>` (ลำดับเดียวกับ `import_ledger_investments`) กันบันทึกหมวดแทรกระหว่างตรวจ
- นิยามส่วนอื่นคงเดิมทุกบรรทัด ดึงจากฐานข้อมูลจริง (`pg_get_functiondef` อ่านอย่างเดียว) · ลายเซ็น/security invoker ไม่เปลี่ยน · **ไม่มี GRANT/REVOKE** (create or replace คงสิทธิ์เดิม ตรวจใน dry-run ว่าสิทธิ์ไม่เปลี่ยน)
- ผลต่อ abort: เซสชันเปิดไม่ได้ถ้ามีหมวดเดิม และระหว่างเซสชัน RLS ห้ามเขียนหมวดอยู่แล้ว จึงไม่แก้ `import_ledger_abort`

### 2) หน้าเว็บ: ทางออกให้ผู้ใช้ (ต้องเลือก)
ถ้าแก้แค่ฐานข้อมูล ผู้ใช้ที่มีหมวดค้างแต่ไม่มีบัญชีจะนำเข้าไม่ได้และไม่มีปุ่มล้าง
- **ก (แนะนำ):** ก่อนนำเข้า ถ้าพบหมวดค้าง แสดง "พบหมวดเดิม N หมวด" ให้ยืนยันว่าจะลบก่อนนำเข้า (เรียก `saveCategories([], [])`) ไม่ยืนยัน = ไม่ทำอะไร · ผู้ใช้เป็นคนสั่งลบเอง
- ข: ปฏิเสธพร้อมข้อความอย่างเดียว (ง่ายกว่า แต่ผู้ใช้ติด)

## เทสต์ (เขียนก่อน)
- SQL ใหม่ `supabase/tests/import_categories_guard_test.sql`: มีหมวดค้าง → import_ledger และ begin ได้ 23505, ไม่มีแถวใดถูกเขียน, ไม่มีเซสชันเปิด, หมวดยังอยู่ · หมวดของผู้ใช้อื่นไม่ขวาง · ไม่มีหมวด → นำเข้าได้เหมือนเดิม (ทั้งสองทาง) · สิทธิ์ฟังก์ชันเท่าเดิม
- unit: repository / หน้าจอนำเข้า (พบหมวด → ถามก่อน · ยกเลิก = ไม่ลบ)
- live: เพิ่มหนึ่งข้อใน live-contract
- **เทสต์ SQL ที่จะรัน:** ตามกฎ migration ที่ไม่แตะ GRANT/RLS/trigger = ไฟล์ใหม่ + ทุกไฟล์ที่เรียกฟังก์ชัน/ตารางเดียวกัน (grep `import_ledger`, `asset_categories` · ตอนนี้ 11 ไฟล์ที่พบ import_ledger รวม categories) · ถ้าเจ้าของต้องการรันครบทุกไฟล์ จะรันครบ

## ลำดับ
เทสต์ → migration → dry-run rollback → ใส่จริง → เทสต์ SQL → เว็บ → money-auditor + security-auditor (+ design-critic ถ้าเลือก ก) → live-contract บน branch → PR → merge → live-contract บน main

## เหลือไว้ (ไม่อยู่ในงานนี้)
