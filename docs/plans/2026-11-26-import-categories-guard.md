# แผน (ฉบับ 2): นำเข้าไฟล์สำรองเมื่อมีหมวดเดิมค้าง — รอเจ้าของอนุมัติ ยังไม่ลงมือ

แทนฉบับ 1 (ด่านปฏิเสธใน `import_ledger`/`begin`) ตามข้อเสนอเจ้าของ 26 พ.ย. 2569: รายการบัญชีนำเข้าหลายธุรกรรมเหมือนเดิม ส่วนหมวดทำเป็นขั้นสุดท้ายใน RPC เดียว

## ปัญหา (อ่านจากโค้ด ยังไม่ได้ทำซ้ำบนฐานข้อมูล · โอกาสเกิดต่ำ)
มีหมวดค้างโดยไม่มีบัญชี (แท็บค้างหลังล้างข้อมูล หรือเรียก `save_categories` ตรงๆ):
1. สมุดนำเข้าได้ แต่ `import_ledger_investments` ปฏิเสธเพราะมีหมวด → กู้ครึ่งเดียว
2. ทางแบ่งก้อนล้มกลางทาง: `import_ledger_abort` ลบหมวดเดิมทิ้ง

## ผลตรวจความเป็นไปได้: ทำได้ โดยมีเงื่อนไข 3 ข้อ
1. **ลำดับสินทรัพย์กับหมวด:** `assets.category_id` มี FK ไป `asset_categories` (ไม่ deferrable) → หมวดต้องเข้า **ก่อน** สินทรัพย์ จะเก็บหมวดเป็น RPC แยกหลังสินทรัพย์ไม่ได้ (ต้องนำเข้าสินทรัพย์แบบไม่มีหมวดแล้วมาอัปเดตทีหลัง ซึ่งแตกเป็นสองธุรกรรม) · **ขั้นสุดท้ายจึงคือ RPC ข้อมูลลงทุนทั้งก้อน** (หมวด → สินทรัพย์ → ราคา → รายการ → อัตรา → แลกเงิน) ซึ่งเป็นธุรกรรมเดียวอยู่แล้ว เพิ่มแค่ "ลบหมวดเดิม" ไว้หน้าสุดในธุรกรรมเดียวกัน
2. **ต้องแก้ `import_ledger_abort`:** เอาบรรทัดลบ `asset_categories` ออก ไม่งั้นล้มก่อนขั้นสุดท้ายหมวดเดิมก็หาย · ปลอดภัยเพราะระหว่างเซสชันนำเข้าเขียนหมวดไม่ได้ (RLS import_lock + `save_categories` ปฏิเสธ) และ RPC ข้อมูลลงทุนรันไม่ได้ขณะมีเซสชัน หมวดที่เห็นตอน abort จึงเป็นของเดิมเสมอ · การล้างข้อมูลทั้งบัญชี (`reset_my_ledger*`) ยังลบหมวดเหมือนเดิม
3. **ไฟล์สำรองที่ไม่มีข้อมูลลงทุน:** ตอนนี้เว็บข้ามขั้นนี้ · เมื่อผู้ใช้ยืนยันลบหมวดแล้วต้องเรียกเสมอ (หมวดเดิมหาย ไม่มีหมวดใหม่ ข้อความใน dialog ต้องบอก)

## ฐานข้อมูล: migration ใหม่ `20261127000100_import_replace_categories.sql`
- ฟังก์ชันใหม่ `import_ledger_investments_replacing_categories(p_data jsonb, p_expected_categories integer)` · `security invoker`
  1. ตรวจล็อกอิน/`can_use_data` · ล็อก `import_ledger:<user>` แล้ว `categories:<user>` (ลำดับเดียวกับ `import_ledger_investments`)
  2. ปฏิเสธถ้ามีเซสชันนำเข้าค้าง (55000)
  3. นับหมวดเดิม ไม่เท่า `p_expected_categories` → `PT409` (ข้อมูลเปลี่ยนหลังผู้ใช้กดยืนยัน · ไม่ใช้ 40001)
  4. `delete from public.asset_categories where user_id = auth.uid()`
  5. เรียก `public.import_ledger_investments(p_data)` เดิม (ไม่แก้ตัวฟังก์ชัน) · ล้มตรงไหน รวมถึงด่านเป้า 100% ตอน commit → rollback ทั้งธุรกรรม หมวดเดิมกลับครบ
- `create or replace function public.import_ledger_abort()` ตัดบรรทัดลบหมวด (ดึงนิยามจริงด้วย `pg_get_functiondef` ก่อน)
- `revoke`/`grant execute ... to authenticated` ของฟังก์ชันใหม่

### ข้อจำกัดตามกติกา (ต้องรู้ก่อนอนุมัติ)
- migration มีคำสั่ง **`delete`** (ในตัวฟังก์ชันใหม่) → ผู้ช่วย **ไม่ใส่เอง** เปิด PR draft แล้วรอเจ้าของ
- มี **GRANT/REVOKE** → ต้องรันเทสต์ SQL **ครบทุกไฟล์** ใน `supabase/tests/` (ตอนนี้ 30 + ไฟล์ใหม่) หลังใส่ ไม่มีข้อยกเว้น
- `categories_test.sql` ข้อ **T11b ต้องเปลี่ยนความคาดหวัง** (เดิม: abort ต้องล้างหมวด → ใหม่: หมวดต้องยังอยู่) เป็นการเปลี่ยนพฤติกรรมที่ตั้งใจ ขออนุญาตแก้เทสต์ข้อนี้

## เว็บ
- ก่อนเริ่มนำเข้า (ทั้งหน้านำเข้าไฟล์และตัวย้ายข้อมูล) นับหมวดเดิม · > 0 → dialog: "พบหมวดเดิม N หมวด จะถูกลบและแทนด้วยหมวดจากไฟล์สำรอง M หมวด" (M = 0 บอกว่าจะไม่มีหมวด) · ปุ่มเริ่มต้น **Cancel** (โฟกัสเริ่มต้น · Esc = Cancel) · Cancel = ไม่นำเข้าอะไรเลย
- ยืนยันแล้ว: นำเข้าสมุดทางเดิม → ขั้นสุดท้ายเรียก RPC ใหม่พร้อม N (แม้ไฟล์ไม่มีข้อมูลลงทุน) · ไม่มีหมวดเดิม = ทางเดิมทุกอย่าง
- PT409 → ข้อความ "ข้อมูลเปลี่ยน โหลดใหม่แล้วลองอีกครั้ง" · ข้อความล้มต้องบอกว่าหมวดเดิมยังอยู่

## เทสต์ (เขียนก่อน)
- SQL ใหม่ `import_replace_categories_test.sql`
  - สำเร็จ: หมวดเดิมหาย หมวดจากไฟล์เข้า สินทรัพย์ผูกถูก (รวมรหัส/ชื่อหมวดซ้ำกับของเดิม)
  - **ล้มแล้วหมวดเดิมยังอยู่ครบทุกคอลัมน์:** เป้ารวมไม่ 100% (ล้มตอน commit) · สินทรัพย์ชี้หมวดที่ไม่มี · รายการลงทุนผิด · มีสินทรัพย์อยู่แล้ว · และไม่มีแถวลงทุนใดเข้า
  - นับไม่ตรง → PT409 ไม่ลบ · มีเซสชันค้าง → ปฏิเสธ · หมวดผู้ใช้อื่นไม่ถูกแตะ · anon เรียกไม่ได้
  - abort ทางแบ่งก้อน: สมุดค้างถูกล้าง หมวดเดิมยังอยู่
- unit: repository (ลำดับการเรียก, เรียกแม้ไฟล์ไม่มีข้อมูลลงทุน) · UI dialog (ค่าเริ่มต้น Cancel, จำนวนถูก) · e2e คอม + มือถือไม่พัง
- live-contract: เพิ่มหนึ่งข้อ

## ที่ยังเหลือหลังแผนนี้ (ไม่อยู่ในขอบเขต)
- ถ้าขั้นสุดท้ายล้ม: สมุดเข้าแล้ว ข้อมูลลงทุนไม่เข้า หมวดเดิมยังอยู่ · **ยังไม่มีปุ่มลองนำเข้าข้อมูลลงทุนใหม่** (ข้อจำกัดเดิม) ต้องล้างข้อมูลแล้วนำเข้าใหม่ ซึ่งการล้างจะลบหมวดด้วย · ถ้าต้องการปุ่มลองใหม่ เสนอเป็นงานถัดไป
- หมวดที่ถูกสร้างหลังเว็บตรวจ (ตอนนั้นไม่มีหมวด) ยังทำให้กู้ครึ่งเดียวได้ (ช่วงสั้นมาก)

## ลำดับงาน
เทสต์ → migration → dry-run rollback → PR draft → **เจ้าของอนุมัติการใส่** → ใส่จริง → เทสต์ SQL ครบทุกไฟล์ → เว็บ → money-auditor + security-auditor + design-critic → live-contract บน branch → merge → live-contract บน main
