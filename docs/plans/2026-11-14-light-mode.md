# แผน: โหมดสว่าง (เจ้าของสั่ง 14 พ.ย. 2569)

เป้าหมาย: เพิ่มโหมดสว่างโทนเดียวกับ Aurora Glass (พื้นสว่าง) · ผู้ใช้เลือกได้ 3 ทาง: ตามเครื่อง (ค่าเริ่มต้น) / มืด / สว่าง · **โหมดมืดต้องเหมือนเดิมทุกจุด** · ไม่มี migration · ห้ามแตะสูตรเงินหรือฐานข้อมูล · แต่ละเฟสเป็น PR แยก

## ข้อมูลที่ต้องรู้ก่อน
- **ต้นแบบ "แบบ B (Light)" ไม่อยู่ในโปรเจกต์** (มีเฉพาะ `docs/design/A-aurora-glass.dc.html`) → ผมจะออกแบบชุดสีสว่างเองจากโทนของ A (ทอง `--gold`, มิ้นต์ `--income`, ฟ้า `--transfer`, ชมพู/ส้ม `--expense`/`--warn`) แล้วให้ `design-critic` ตัดสินรายละเอียด · ถ้าเจ้าของมีไฟล์แบบ B ให้วางที่ `docs/design/` แล้วบอก ผมจะปรับตาม
- **CSP ห้ามสคริปต์อินไลน์** (`script-src 'self'`): สคริปต์กันหน้ากะพริบตอนเปิดต้องเป็นไฟล์แยก `public/theme-init.js` โหลดแบบบล็อกใน `<head>` (ไม่ผ่อน CSP)
- สีฝังอยู่ใน 3 ที่: `src/ui/styles.css` (ราว 100 จุด), `CashFlowSankey.tsx` (สีหมวด), `shareCardCanvas.ts` (วาดการ์ดแชร์ด้วย canvas) + ไอคอน/ธีมสีแถบมือถือ (`index.html`, `manifest`)

## เฟส 1 — ย้ายสีเป็น design tokens (ไม่เปลี่ยนหน้าตา)
- ตัวแปรเชิงความหมายใน `:root` (เช่น `--surface-solid`, `--field-bg`, `--glow-violet`, `--on-gold` ...) ค่าโหมดมืด = ค่าเดิมทุกตัวอักษร
- สีใน TS ของ Sankey/การ์ดแชร์อ่านจาก token ผ่านตัวช่วยกลาง (ยังไม่เปลี่ยนค่า)
- **ตรวจ:** Playwright เทียบภาพก่อน/หลังที่ 360, 390, 1280 ทุกหน้า + เมนู pop up (เวลาแช่แข็ง ข้อมูลสมมติ) ต้องตรงกัน 100% · เครื่องมือเทียบภาพ `tests/e2e/visual.spec.ts` (รันเมื่อตั้ง `VISUAL=1` ภาพฐานเก็บใน `.visual/` ไม่เข้า git เพราะภาพต่าง OS ไม่ตรงกัน)
## เฟส 2 — ชุดสีสว่าง
- `[data-theme='light']` ทับ token ทั้งชุด: พื้น ตัวหนังสือ muted ขอบ กระจก/glass-lite/พื้นทึบ ก้อนแสง สีรายรับ/รายจ่าย/โอน/เตือน ไอคอน `color-scheme`
- ครอบ: Sankey + กราฟแท่ง (สีหมวดต้องแยกกันออกบนพื้นสว่าง) การ์ดแชร์พอร์ต (canvas) เมนู pop up ไอคอน dialog ทุกตัว (เพิ่มรายการ, บิล, จ่ายบิล, ถามรหัสผ่าน, ยืนยัน) toast แถบเตือน
- **contrast ผ่าน WCAG AA** ทุกคู่สีข้อความ (≥ 4.5:1 ปกติ, ≥ 3:1 ข้อความใหญ่/ส่วนประกอบ UI) ตรวจด้วยเทสต์คำนวณจาก token จริง
## เฟส 3 — ปุ่มเลือกธีม
- หน้าโปรไฟล์: 3 ทาง ตามเครื่อง (ค่าเริ่มต้น) / มืด / สว่าง
- เก็บใน settings คีย์ `theme` ผ่าน `merge_settings` (CAS เดิม ไม่มี migration) + `localStorage` (`mb.theme`) ให้ `public/theme-init.js` ตั้ง `data-theme` ก่อนวาดหน้าแรก (ไม่กะพริบสีผิด)
- `<meta name="theme-color">` ตามโหมดจริง (อัปเดตตอนสลับและตอนเครื่องเปลี่ยนโหมด) · `manifest` คงสีมืด (ค่าสถิต)
## เฟส 4 — Playwright ทุกหน้า × 2 โหมด
- ขยาย `tests/e2e/layout.spec.ts` ให้รันทั้ง `dark` และ `light` ที่ 360/390/1280 + ตรวจ "ตัวหนังสือมองไม่เห็น/contrast ต่ำ" ด้วยการคำนวณ contrast จริงของข้อความที่แสดงบนหน้า (สีตัวหนังสือเทียบสีพื้นที่ยึดจริงตามชั้นพื้นหลัง) ห้ามมีข้อความต่ำกว่าเกณฑ์

## หลักการร่วม
- ทุกเฟส: เทสต์ก่อน → `npm test`/`typecheck`/`build` → `design-critic` → CI (`test`+`e2e`) → merge ตามกติกา → บันทึก `docs/learning/` → HANDOFF
- เฟสที่แตะ settings (3): รัน `admin:live-contract` เพราะแตะ repository contract; ไม่มี migration
- ถ้า contrast ของเฉดใดผ่านไม่ได้ ปรับสีให้ผ่าน (ไม่ผ่อนเกณฑ์)
- โหมดลดความโปร่งใส (`prefers-reduced-transparency`) ต้องกลายเป็นพื้นทึบทั้ง 2 โหมด
