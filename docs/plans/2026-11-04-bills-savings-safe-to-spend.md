# แผน: บิลประจำ + เป้าออม + วันเงินเดือนเข้า → SAFE-TO-SPEND

> สถานะ: เขียนในโหมดทำงานเอง (4 พ.ย. 2569) ตามลำดับงานข้อ 2 ของเจ้าของ · การตัดสินใจและเหตุผลอยู่ที่ `docs/decisions/2026-11-04-bills-safe-to-spend.md`
> กฎที่เกี่ยว: R1 (สตางค์) · R2 (ขอบเขตแปลงหน่วย) · R4 (จ่ายบิลคือรายจ่าย โอน/เงินต้นหนี้ไม่ใช่) · R6 (เปลี่ยน schema ต้อง `version(n)` + migration + Snapshot) · R8 (ปัดเศษ) · R14 (เทสต์ขอบเขต) · **R15 (บิลประจำจ่ายได้ครั้งเดียวต่อรอบด้วย `lastPaidMonth` · สูตร safe-to-spend)**

## 1. เป้าหมาย / ไม่ใช่เป้าหมาย

**เป้าหมาย**
- การ์ด SAFE-TO-SPEND, แผง "บิลที่จะถึง", ส่วนแยก "บิล/ใช้จ่าย" ในการ์ด OUTGOING, โหนดบิลใน Sankey และเป้างบเดือน มี **ตัวเลขจริง** แทนสถานะว่าง
- ตั้งค่าได้: บิลประจำ (ชื่อ ยอด วันครบกำหนด กระเป๋า/หมวดที่จ่าย), วันเงินเดือนเข้า, เป้าออมรายเดือน, เป้างบรายจ่ายรายเดือน
- จ่ายบิลได้ครั้งเดียวต่อรอบ (R15) และสร้างรายการรายจ่ายจริงในสมุดบัญชี

**ไม่ใช่เป้าหมาย (รอบนี้)**
- งวดหนี้/บัตรเครดิต (รอ M4 — สูตร R15 เผื่อรับยอดเพิ่มไว้แล้ว) · บิลรายสัปดาห์/รายปี · ยอดบิลที่ไม่คงที่ · เตือนผ่านแจ้งเตือนเครื่อง · ส่วนอื่นของ M2 (ล็อกอิน)

**ข้อห้าม:** ตัวเลขปลอมบนหน้าจอ · สูตรเงินใน React · float กับยอดเงิน · แก้ `docs/money-rules.md` · เปลี่ยน schema โดยไม่ทำ Snapshot

## 3. B1 — ขอบเขตละเอียด (Ticket ที่ทำใน PR นี้)

ไฟล์ใหม่ใน `src/domain/bills/` (ไม่แตะ DOM/ฐานข้อมูล/React):
- `types.ts` — `Bill`, `UpcomingBill`
- `calendar.ts` — `daysInMonth`, `dueDateIn(cycleMonth, day)` (วันที่ 29-31 ถูกบีบเป็นวันสุดท้ายของเดือน), `addMonths`, `daysBetween`, `nextPayday(payDay, today)`
- `schedule.ts` — `isBillPaid`, `payableCycle`, `markBillPaid` (โยนข้อผิดพลาดถ้าจ่ายซ้ำรอบเดิม), `upcomingBills(bills, today, endDate)`
- `safeToSpend.ts` — `computeSafeToSpend({ spendable, outstanding, reserve, today, payDay })` → `{ kind: 'ok' | 'shortfall', perDay, available, shortfall, daysLeft, nextPayday }`

**เทสต์ขอบเขต (R14):** ยอด 0 · น้อยมาก (1 สตางค์) · วันสิ้นเดือน (28/29/30/31, ปีอธิกสุรทิน 2024/2000, ปีศตวรรษไม่อธิกสุรทิน 2100) · ข้ามปี · วันเงินเดือนตรงกับวันนี้ · วันเงินเดือน 31 ในเดือนสั้น · ปัดเศษหารวัน (ครึ่ง) · ผลติดลบ → 0 + คำเตือน · ยอดใกล้ `MAX_SAFE_INTEGER` · ข้อมูลเข้าผิดรูป (ไม่ใช่จำนวนเต็ม ติดลบ วันที่ไม่จริง) · บิลที่เก็บถาวร · จ่ายซ้ำรอบเดิม · บิลเลยกำหนด
