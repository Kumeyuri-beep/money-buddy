# แผน: สแกนสลิป (M1-B4)

> สถานะ: **เจ้าของอนุมัติแผนแล้ว** (3 พ.ย. 2569) · เริ่มงานย่อย 1
> กฎที่เกี่ยว: R1 (สตางค์) · R2 (OCR เป็นขอบรับข้อมูลเข้า ใช้ `parseBahtToSatang` ที่นี่ที่เดียว) · R8 · R14 (เทสต์ขอบเขต)
> ไม่เปลี่ยน schema จึงไม่ต้อง Migration/Snapshot

## 1. เป้าหมาย

หลังโอน/สแกนจ่ายในแอปธนาคาร เจ้าของแคปสลิปไว้ แล้วนำรูปเข้าแอปเพื่อเติมฟอร์มรายจ่ายให้ตรวจก่อนบันทึก แทนการพิมพ์เอง

- สลิปที่รองรับรอบนี้: **K PLUS** ที่เป็นรูปภาพ (SCB EASY, Krungthai NEXT ไว้รอบหลัง) · ยังไม่รองรับใบเสร็จกระดาษ
- ข้อมูลที่ดึง: ยอดเงิน, วันที่-เวลา, ชื่อผู้รับ (ใส่บันทึกช่วยจำและใช้เดาหมวด)
- นำรูปเข้า: เลือกไฟล์ + วางด้วย Ctrl+V + ลากมาวาง
- ผลลัพธ์: เปิดฟอร์ม "บันทึกรายการ" เดิมพร้อมค่าที่เติม · `source = 'ocr'` · **ไม่บันทึกอัตโนมัติ**

## 2. ไม่ใช่เป้าหมาย / ข้อห้าม

- ไม่รองรับสลิปเงินเข้า (เฉพาะรายจ่าย) · ไม่รองรับธนาคารอื่นนอก K PLUS รอบนี้
- **ห้ามส่งรูปออกนอกเครื่อง** · **ห้ามเก็บรูปหลังอ่านเสร็จ** (ปล่อยออกจากหน่วยความจำทันที)
- **ห้ามเอาสลิปจริงหรือข้อมูลการเงินจริงเข้าโปรเจกต์** เทสต์ใช้ข้อความ OCR สมมติเท่านั้น
- ห้ามเดามั่ว: อ่านยอด/วันที่ไม่ได้ให้เว้นว่าง แล้วบอกผู้ใช้
- ไม่มีสูตรเงินใน React

## 3. การตัดสินใจของเจ้าของ

| เรื่อง | คำตอบ |
|---|---|
| ตัวอ่าน | Tesseract.js v5 ไทย+อังกฤษ โหลดเฉพาะตอนกดสแกน |
| ไฟล์ภาษา/ตัวอ่าน | เก็บในโปรเจกต์เอง ไม่โหลดจาก CDN |
| นำรูปเข้า | เลือกไฟล์ + Ctrl+V + ลากมาวาง |
| ย่อรูป | ด้านยาวไม่เกิน 1600px ก่อนส่งให้ Tesseract |
| ตรวจไฟล์ | แจ้งผู้ใช้ถ้าไม่ใช่รูป หรือใหญ่เกิน 15MB |
| สลิปซ้ำ | เตือนในฟอร์ม แต่ยังบันทึกได้ |
| ผู้ช่วย | `money-auditor` หลังงานย่อย 1 · `design-critic` หลังงานย่อย 3 |
| การส่งงาน | จบทุกงานย่อยแล้วหยุดรอเจ้าของ **ยังไม่ push** |

ตัดสินหลัง `money-auditor` ตรวจ B4-1 (3 พ.ย. 2569): เพดานยอด 10,000,000 บาท เกินให้ปล่อยว่าง+เตือน · วันที่ในอนาคตหรือเก่ากว่า 365 วันให้ปล่อยว่าง+เตือน · สลิปที่อาจไม่ใช่รายจ่าย (โอนกระเป๋าตัวเอง/จ่ายบัตร/เงินต้นหนี้) ทำใน B4-3: เตือน + ปุ่มสลับเป็น "โอนเงิน" · ยอดต้องมีทศนิยม 2 หลักและเป็นทั้งบรรทัด ไม่ตรงรูปแบบให้ปล่อยว่าง

การตัดสินใจของผม (เจ้าของยังไม่ได้ยืนยันรายข้อ แต่เห็นด้วยกับแผนรวม): เวลาในสลิปเก็บใน memo เพราะฟอร์มไม่มีช่องเวลา · หมวดเดาด้วยตัวเดียวกับพิมพ์จดด่วน · กระเป๋าใช้ที่ใช้ล่าสุด

## 4. งานย่อย

### B4-1 ตัวอ่านข้อความสลิป (ฟังก์ชันล้วน ไม่แตะ DOM/DB)
- `src/app/slipParser.ts`: `parseSlipText(text)` -> `{ amount?, date?, time?, recipient? }` และ `slipToDraft(fields, ctx)` -> ร่างฟอร์ม + `missing`
- ยอดผ่าน `parseBahtToSatang` แล้วแสดงด้วย `toBahtString` · ไม่ใช้ค่าธรรมเนียมเป็นยอด
- วันที่: ปี พ.ศ. 2 หลัก/4 หลัก -> ค.ศ. ตรวจวันสิ้นเดือน/29 ก.พ. ด้วย `isValidIsoDate`
- ทนข้อความเพี้ยนจาก OCR (ช่องว่างเกิน, สระ ำ เพี้ยน, จุดท้ายเดือนหาย)
- เทสต์: `tests/unit/slipParser.test.ts` (ข้อความสมมติ) · เรียก `money-auditor` เมื่อจบ

### B4-2 ตัวห่อ Tesseract + ตรวจไฟล์
- ตรวจชนิด/ขนาดไฟล์ (รูป, ≤ 15MB) · คำนวณขนาดย่อ (ด้านยาว ≤ 1600px) เป็นฟังก์ชันล้วนพร้อมเทสต์
- โหลด Tesseract แบบ dynamic import เฉพาะตอนสแกน · ไฟล์ภาษาอยู่ในโปรเจกต์ · ปิด worker และปล่อยรูปหลังอ่าน

### B4-3 หน้าจอ
- ปุ่ม "สแกนสลิป" ที่หัวหน้า · เลือกไฟล์/วาง/ลาก · สถานะกำลังอ่าน · ข้อความผิดพลาดภาษาไทย
- `AddEntryDialog` รับค่าตั้งต้น + `source: 'ocr'` · เตือนสลิปซ้ำ (ยอด+วันที่+ผู้รับ) ในฟอร์ม
- เรียก `design-critic` เมื่อจบ

## 4.1 ปรับหลังทดสอบกับสลิปจริง 4 ใบ (4 พ.ย. 2569)

ตัวอ่านข้อความที่เขียนจากข้อความสมมติสะอาดอ่านสลิปจริงไม่ได้ (ยอดว่าง 4/4, วันที่ว่าง 2/4) สาเหตุและวิธีแก้ (ลำดับ ค → ก → ข → ง ตามที่เจ้าของเลือก):
- **ค OCR:** ทดลองวิธีเตรียมรูป พบว่าไม่มีวิธีเดียวที่อ่านเดือน/ยอดได้ทุกใบ จึงอ่าน 2 รอบ (ขยาย 2 เท่า + ขาวดำสนิท Otsu · ขยาย 2 เท่า + เทายืดคอนทราสต์ + โหมดข้อความกระจาย) แล้วรวมผลทีละช่อง: ยอด/วันที่ถ้าสองรอบขัดกันปล่อยว่างและเตือน (`ocr-disagree`) · **หมายเหตุ:** กติกา "ย่อด้านยาวไม่เกิน 1600px" ยังใช้กับต้นฉบับก่อน แล้วค่อยขยายสูงสุด 2 เท่า แต่ด้านยาวหลังขยายไม่เกิน 2400px (เจ้าของกำหนด 4 พ.ย.) เพราะทดลองแล้วตัวอักษรเล็กอย่างเดือน "พ.ย." อ่านได้ชัดขึ้นมาก
- **ก ยอด:** ยอดไม่ต้องเป็นทั้งบรรทัดอีกต่อไป (สลิปจริงมีลายน้ำทำให้มีขยะต่อท้ายบรรทัด) ใช้กฎตำแหน่ง: ค้นเฉพาะหลังป้าย "จำนวน" ไม่เกิน 6 บรรทัด หยุดที่ป้ายค่าธรรมเนียม/เลขที่รายการ ยังต้องทศนิยม 2 หลักและไม่ติดตัวเลขอื่น มีหลายค่าที่ต่างกันปล่อยว่าง · หาป้าย "จำนวน" ไม่เจอใช้ตัวเลขทศนิยมที่ไม่ใช่ศูนย์ตัวเดียวก่อนป้ายค่าธรรมเนียม
- **ข ผู้รับ:** สลิปจริงไม่มีป้าย "ไปยัง" ใช้บรรทัดที่ดูเป็นชื่อ "สุดท้าย" ก่อนป้ายจำนวน (ไม่นับธนาคาร/สาขา/เลขบัญชี/วันที่) ตัดขยะท้ายบรรทัดและตัวเลขนำหน้า รวมผลสองรอบเลือกชื่อที่ยาวกว่า ชื่ออาจผิดได้ ใช้เป็นบันทึกช่วยจำที่ผู้ใช้ตรวจ
- **ง ยืนยัน:** ยอดและวันที่ที่ OCR เติมให้ขึ้น "ยังไม่ได้ยืนยัน" (เส้นประสีส้ม) จนกว่าผู้ใช้แก้หรือกด "ตรงกับสลิป" ไม่บล็อกการบันทึก
- ผลกับสลิปจริง: ยอด/วันที่/เวลาถูก 4/4 · ผู้รับได้ครบถ้วน 2/4 (ชื่อบริษัท, ชื่อร้าน) อีก 2 ใบได้บางส่วน/มีขยะ (OCR อ่านคำแรกของชื่อพลาด)

## 4.2 ผลตรวจก่อนเปิด PR (4 พ.ย. 2569)
- **money-auditor:** พบยอดผิดที่ผ่านเงียบได้ 3 ช่อง + กฎสำรองที่เดา แก้แล้ว: "บาท" ไม่ใช้ตัดสินยอด (หลายค่าต่างกัน = ว่าง) · ช่วงค้นหยุดที่ยอดคงเหลือ/ยอดรวม · กันเลขนำหน้าที่คั่นด้วยช่องว่างกี่ช่องก็ได้ · แปลงเลขไทย · ไม่รับศูนย์นำหน้า · กฎสำรองรับเฉพาะเลขต้นบรรทัดและต้องตรงกันทั้งสองรอบ
- **design-critic (2 รอบ):** แก้โฟกัส/live region/ปุ่ม 44px/ข้อความกำกับ/วงโฟกัสไม่ชนเส้นประ · กดบันทึกครั้งแรกโดยยังไม่ยืนยันจะเตือนก่อน 1 ครั้ง (ไม่บล็อก) · ปิด blur ฉากหลังเมื่อลดความโปร่งใส
- **security-auditor:** รูปและข้อความไม่ออกนอกเครื่อง ไม่มีรูปค้าง ไม่มี XSS/ReDoS · แก้รูปบอมบ์ (อ่านขนาดจากหัวไฟล์ก่อนแตกรูป เพดาน 10000px/40 ล้านพิกเซล รับเฉพาะ PNG/JPEG/WebP) · เวลาหมดอายุ 60 วินาทีและปิด worker ไม่ทับ error · ล็อกกันสแกนซ้อน · ล็อกเวอร์ชันแพ็กเกจ OCR · เปลี่ยนยอด/เศษข้อความในเทสต์ที่คล้ายสลิปจริงเป็นค่าที่แต่งขึ้น
- **เรื่องที่ต้องให้เจ้าของตัดสิน (ไม่ได้ทำเอง):** กฎ deny ใน `.claude/settings.json` ยังมีช่อง (`push origin x:main`, `refs/heads/main`, `push -u origin` บน main, `git -c ... push`, `gh pr merge`, `gh api`, PowerShell) · ควรเปิด branch protection บน GitHub สำหรับ main · กติกา "ปิดบังตัวเลขยาว ยกเว้นยอดเงินและวันที่" ทำให้ยอด/วันที่จริงหลุดลงเอกสารได้ · ฟอนต์ Google ภายนอกและไม่มี CSP (มีมาก่อนงานนี้)

## 5. วิธีทดสอบสุดท้าย (เจ้าของทำเอง)
