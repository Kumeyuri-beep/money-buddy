# ข้อเสนอ: แก้ไขรายการลงทุนที่บันทึกแล้ว (Edit) — ไว้ทำรอบที่ 2

สถานะ: **เจ้าของตัดสินคำถามทั้ง 2 ข้อแล้ว (20 พ.ย. 2569 ดูข้อ 7) · เก็บไว้ทำรอบที่ 2 · ยังไม่ได้แก้โค้ด ฐานข้อมูล หรือ `docs/money-rules.md`**
งานนี้แตะฐานข้อมูล (RPC ใหม่) จึงเป็นงานของ GM ตามกติกา GM/ลูกน้อง

## 1. ปัญหา
ตอนนี้ปุ่ม Edit ในหน้า Holdings เปิดได้แค่ฟอร์มราคา+เรตล่าสุด และหน้า Transactions ขึ้นข้อความ "Editing is not available yet. Delete and add it again." เพราะระบบไม่มีทางแก้รายการซื้อ/ขาย/ปันผลที่บันทึกแล้ว ผู้ใช้ต้องลบแล้วลงใหม่เอง ซึ่งลบไม่ได้เมื่อมีรายการขายหลังจากนั้น (R17)

## 2. หลักการ: "กลับรายการเดิม + ลงรายการใหม่" ในธุรกรรมเดียว
ไม่แก้บรรทัดในสมุดบัญชีเดิม (R16: สมุดคู่ ยอดคำนวณจากบรรทัด ไม่เก็บยอด) แก้ = ทำสองอย่างพร้อมกันแบบทั้งหมดหรือไม่เลย:
1. **กลับรายการเดิม:** ลบรายการลงทุนเดิมและ Entry ที่ผูก (เหมือน `deleteTrade` ที่ใช้อยู่ ซึ่งลบ Entry แล้วฐานข้อมูลลบรายการลงทุนตาม)
2. **ลงรายการใหม่:** สร้างรายการลงทุนใหม่ + Entry ใหม่ที่สมดุล (ผลรวมต่อสกุล = 0) ด้วยตัวสร้าง Entry เดิม (`ledgerLink`/`ledgerLinkFx`) ค่าที่แก้แล้วใส่ครบ
3. ทั้งสองขั้นอยู่ใน RPC เดียว (`replace_trade`) ในธุรกรรมฐานข้อมูลเดียว ล้มที่ขั้นใด = ย้อนทั้งหมด ไม่มีสถานะครึ่งๆ กลางๆ

ทางเลือกที่ไม่เลือก: (ก) UPDATE แถวเดิมแล้วคำนวณบรรทัดใหม่ทับ: ละเมิดแนวคิดสมุดที่ไม่แก้ย้อนหลัง และตรวจสมดุลยากกว่า (ข) ให้ผู้ใช้ลบแล้วลงเองต่อไป: ลบไม่ได้เมื่อมีรายการขายตามหลัง

ลำดับเวลา: รายการใหม่ใช้ `createdAt` ใหม่ แต่ลำดับคิดตาม (date, createdAt, id) (R17) ถ้าวันที่ไม่เปลี่ยน รายการอาจเรียงหลังรายการวันเดียวกันที่เคยอยู่หลังมัน ต้องบอกผู้ใช้ หรือคงลำดับเดิมด้วยการเก็บ `createdAt` เดิม (แนะนำ: คงเดิมเมื่อวันที่ไม่เปลี่ยน)

## 3. ผลต่อ R11/R17 (ต้นทุนเฉลี่ย)
ต้นทุนเฉลี่ยคำนวณจากการเล่นซ้ำรายการเรียงตามเวลา ไม่เก็บยอด ดังนั้นการแก้รายการหนึ่ง **เปลี่ยนต้นทุนที่ตัดออก (costOut) และกำไรขายของรายการขายทุกตัวที่ตามหลังโดยอัตโนมัติ** ไม่มีค่าที่ต้อง "แก้ตาม" ที่ตาราง แต่มีข้อมูลที่ **บันทึกไว้ใน Entry ของรายการขาย** (บรรทัดกำไร/ขาดทุนจากการลงทุน และ asset costOut) ซึ่งอาจเปลี่ยนตาม

ข้อจำกัดที่เสนอ (เข้มกว่าเดิมเล็กน้อย เพื่อไม่ให้สมุดขัดกับต้นทุนที่เล่นซ้ำ):
- **ห้ามแก้รายการซื้อ/ปันผลลงทุนต่อ ที่มีวันที่ ณ หรือก่อนรายการขายล่าสุดของสินทรัพย์เดียวกัน** (ตรงกับกฎ R17 เดิมที่ห้ามเพิ่ม/แก้/ลบ) ผู้ใช้ต้องลบรายการขายหลังจากนั้นก่อน
- รายการ **ขาย** ที่เป็นรายการล่าสุด แก้ได้ (จำนวน ราคา ค่าธรรมเนียม วันที่ ตราบที่ยังไม่ไปก่อนรายการอื่นที่ถูกล็อก) เพราะไม่มีรายการใดตามหลัง
- รายการ **ปันผลเงินสด** แก้ได้เสมอ ไม่กระทบต้นทุน (R17) ยกเว้นผลต่อเรตและภาษีด้านล่าง
- ผลตรวจหลังแก้: เล่นซ้ำทั้งสินทรัพย์ต้องผ่านเดิม: U ≥ 0, ขายไม่เกินที่ถือ, C = C' + costOut, Entry ผูกครบ (Integrity Check R17) ไม่ผ่าน = ปฏิเสธทั้งรายการ ไม่แก้

## 4. ผลต่อ R20 (ต้นทุนบาทอัตราวันเกิดรายการ)
- ต้นทุนบาท `Cthb` ใช้อัตราวันซื้อของแต่ละรายการ การแก้ **อัตรา** หรือ **วันที่** ของรายการซื้อ เปลี่ยน `Cthb` ตามสูตร R20.3 อัตโนมัติจากการเล่นซ้ำ
- กฎ "ปฏิเสธรายการซื้อที่ต้นทุนบาทของรายการนั้นปัดเป็น 0 สตางค์" ต้องตรวจกับค่าใหม่ด้วย
- แหล่งกำไรหกแหล่ง (R24) ใช้ "ส่วนที่เหลือ" ของค่าเงิน จึงยังรวมตรงเป๊ะหลังแก้ ต้องมีเทสต์ยืนยัน
- อัตราแลกเปลี่ยนรายวัน (`fx_rates`) ไม่ถูกแก้โดยการแก้รายการ (ผู้ใช้แก้ในหน้าอัตราเอง)
- เงินสด USD: แก้รายการซื้อ/ขายเปลี่ยนเงินสดที่หัก/รับ ต้องไม่ทำให้เงินสดติดลบโดยไม่เตือน (ตรงกับข้อตัดสิน "ติดลบได้แต่ต้องเตือน" ใน HANDOFF §94)

## 5. ขอบเขตที่เสนอ (รอบที่ 2)
| รายการ | แก้ได้ | หมายเหตุ |
|---|---|---|
| ซื้อ (Buy) | จำนวน ราคา วันที่ ค่าธรรมเนียม อัตรา | เฉพาะที่ไม่ถูกล็อกด้วยการขายหลังวันนั้น |
| ขาย (Sell) | จำนวน ราคา วันที่ ค่าธรรมเนียม อัตรา | เฉพาะรายการขายล่าสุดของหุ้นนั้น |
| ปันผล | จำนวนเงิน ภาษีหัก วันที่ อัตรา | ไม่กระทบต้นทุน |
| แลกเงิน (FX) | ไม่ทำรอบนี้ | ผูกกับอัตราเรต R20.2 ให้ลบแล้วลงใหม่ต่อไป |
| ฝาก/ถอนเงินสด | ไม่ทำรอบนี้ | ลบแล้วลงใหม่ (ไม่มีผลต่อผลตอบแทน R25.4) |

## 6. งานที่ต้องทำ (สรุป)
1. **เจ้าของอนุมัติแนวทางข้อ 2-4 และตาราง 5 ก่อนเริ่มทำรอบที่ 2** (ข้อ 7 ตัดสินแล้ว: ไม่ต้องแก้ R17 เพราะคงการห้ามแก้รายการที่ถูกล็อกด้วยการขาย)
2. Migration แบบ "เพิ่ม" (`create or replace function replace_trade`) ตรวจสิทธิ์/RLS แบบเดียวกับ `deleteTrade`, ตรวจผลรวมศูนย์ฝั่งเซิร์ฟเวอร์ (R16) · มี GRANT → ต้องรันเทสต์ SQL ครบทุกไฟล์ + dry-run rollback + `admin:live-contract` บน branch และบน `main`
3. `repository.replaceTrade(oldId, input)` + หน้าจอฟอร์มแก้ (ใช้ฟอร์มเดิมของรายการ) + ปุ่ม Edit ในตาราง Transactions และเมนู ⋯ ของ Holdings
4. เทสต์: แก้ซื้อแล้วต้นทุนเฉลี่ยของขายหลังเปลี่ยนตามการเล่นซ้ำ · ถูกล็อกด้วยรายการขาย = ปฏิเสธ · ล้มกลางทาง = ไม่เปลี่ยนอะไร · สมดุลทุก Entry · ผล R24 หกแหล่งรวมตรงเป๊ะหลังแก้ · เงินสด USD ติดลบมีคำเตือน
5. money-auditor + security-auditor ตรวจ (แตะเงิน/RLS)

## 7. ข้อตัดสินของเจ้าของ (20 พ.ย. 2569) — เก็บไว้ทำรอบที่ 2 ยังไม่เขียนโค้ด
1. **แก้รายการซื้อ (หรือปันผลลงทุนต่อ) ที่มีรายการขายตามหลัง: ห้ามแก้ ต้องลบรายการขายก่อน** ตามกฎ R17 เดิม · ไม่ต้องแก้ `docs/money-rules.md` เรื่องนี้ · ระบบต้องแจ้งผู้ใช้ว่า "ลบรายการขายหลังจากนั้นก่อน" (ตรงกับข้อความปฏิเสธของการลบเดิม)
2. **แก้แล้ววันที่ไม่เปลี่ยน: คงลำดับเดิมในวันนั้น** (เก็บ `createdAt` เดิมของรายการ) ต้นทุนเฉลี่ยของรายการวันเดียวกันจึงไม่เปลี่ยนจากการเรียงใหม่ · ถ้าวันที่เปลี่ยน รายการใหม่ใช้ลำดับตาม (date, createdAt, id) ตามปกติ
ผลต่อตารางข้อ 5: รายการซื้อ/ปันผลลงทุนต่อที่ถูกล็อกด้วยการขายหลังวันนั้น = แก้ไม่ได้ · รายการขายแก้ได้เฉพาะรายการขายล่าสุดของหุ้นนั้น · ปันผลเงินสดแก้ได้เสมอ
