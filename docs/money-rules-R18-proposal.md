# ร่างกฎ R18: เครื่องคิดเลขเป้าเกษียณ (Retirement Estimate)

**สถานะ: เจ้าของอนุมัติแล้ว 12 พ.ย. 2569 · กฎฉบับที่ใช้จริงอยู่ที่ `docs/money-rules.md` ข้อ 18** (ไฟล์นี้เก็บไว้เป็นเหตุผลและตัวอย่างตรวจมือ)

> **มติเจ้าของที่ต่างจากร่างข้างล่าง (ให้ถือตามนี้):** (1) `ceilDivBig` ใช้เฉพาะ "เงินเก็บต่อเดือน" ส่วนเงินที่ต้องมี N ใช้ปัดครึ่งขึ้น (ตัวเลข N ในตัวอย่างชุด A ไม่เปลี่ยนเพราะหารลงตัว) (2) ช่วงค่า: เงินเฟ้อ 0-10% · ผลตอบแทนก่อน/หลังเกษียณ −5 ถึง 15% (ติดลบได้ ไม่มีค่าเริ่มต้น) · อายุเกษียณ ≤ 80 · อายุคาดการณ์ ≤ 110 · อายุปัจจุบัน 18-79 (3) ยอมรับความคลาดเคลื่อนตามเดิม และหน้าจอแสดงผลปัดเป็นหลักร้อยบาท (เงินเก็บต่อเดือนปัดขึ้น ค่าอื่นปัดใกล้สุด) พร้อมคำเตือน (4) เพิ่ม "วางแผนเกษียณ" เป็นรายการที่ 7 ในเมนูมือถือ · ตัวเลขช่วงในตารางข้อ 18.2 และข้อความ "ปัดขึ้นเฉพาะ N และ PMT" ในข้อ 18.3 ที่อยู่ข้างล่างเป็นของร่างเดิม
ผู้เสนอ: money-auditor (12 พ.ย. 2569) · โค้ดเฟส 1 ทำตามร่างนี้อยู่ (แบบเดียวกับ R16/R17 ที่โค้ดทำตามก่อนอนุมัติ) ถ้าเจ้าของแก้ร่าง ต้องปรับโค้ดและเทสต์ตาม

## 18.1 สถานะของตัวเลข: ประมาณการ ไม่ใช่ยอดบัญชี
- ผลลัพธ์ทุกค่า (เงินที่ต้องมี, เงินเก็บต่อเดือน, ค่าใช้จ่าย ณ วันเกษียณ, มูลค่าปัจจุบัน, ความคืบหน้า) เป็น "ประมาณการ" คำนวณสดจากข้อมูลเข้า **ห้ามสร้าง `Entry`/`Line` ห้ามเก็บเป็นยอดตายตัว (R16)**
- ห้ามปนกับ SAFE-TO-SPEND, `cashBalance`, RUNWAY, รายรับ, รายจ่าย และห้ามนับ "เงินที่ต้องเก็บต่อเดือน" เป็นบิลหรืองวดค้างของ R15
- บันทึกได้เฉพาะข้อมูลเข้า (อายุ, bps, สตางค์) ไม่บันทึกผลลัพธ์
- ฟังก์ชันอยู่ใน `src/domain/retirement/` ไม่แตะ DOM/ฐานข้อมูล · UI เรียก domain เท่านั้น
- ต้องแสดงข้อความนี้ (หรือความหมายเทียบเท่า) ติดกับผลลัพธ์ทุกครั้งในหน้าจอและการส่งออก:
  > ตัวเลขนี้เป็นประมาณการจากสมมติฐานที่คุณกรอก ไม่ใช่ยอดในบัญชีของคุณ ผลตอบแทน เงินเฟ้อ และอายุขัยจริงอาจต่างจากที่ตั้งไว้ ไม่ใช่คำแนะนำการลงทุนและไม่ใช่การรับประกันผลลัพธ์
- ต้องแสดงสมมติฐานที่ใช้ทุกตัวคู่กับผลลัพธ์ และติดป้าย "ประมาณการ" ที่ตัวเลขทุกตัว
- ห้ามใช้คำที่สื่อว่ารับประกัน เช่น "รับประกัน", "การันตี", "แน่นอน", "ปลอดภัยแน่", "จะได้", "เกษียณสบาย" ให้ใช้ "ควรมีโดยประมาณ", "หากเป็นไปตามสมมติฐาน"
- ผลตอบแทนไม่มีค่าเริ่มต้นที่ดูเหมือนคำสัญญา (ผู้ใช้กรอกเอง) · เงินเฟ้อ 3% และอายุเกษียณ 60 มีค่าเริ่มต้นได้
- ต้องบอกข้อจำกัด: ไม่รวมภาษี ค่าธรรมเนียม บำนาญ/ประกันสังคม และความเสี่ยงอายุยืนกว่าที่ตั้ง

## 18.2 ชนิดข้อมูลและช่วงค่า (นอกช่วง = `RangeError` ข้อความไทย ห้ามปัด/ตัดค่าเงียบๆ)
| ค่า | ชนิด | ช่วง |
|---|---|---|
| อายุปัจจุบัน | จำนวนเต็ม (ปีเต็ม) | 18–100 |
| อายุเกษียณ | จำนวนเต็ม | 30–100 และ > อายุปัจจุบัน (ค่าเริ่มต้น 60) |
| อายุคาดการณ์ที่จะอยู่ถึง | จำนวนเต็ม | > อายุเกษียณ และ ≤ 120 |
| ค่าใช้จ่ายต่อเดือน (มูลค่าวันนี้) | สตางค์ | 1–100,000,000 (1 ล้านบาท) |
| เงินเฟ้อต่อปี | bps จำนวนเต็ม | 0–1,500 (ค่าเริ่มต้น 300) |
| ผลตอบแทนก่อนเกษียณ | bps | 0–2,000 |
| ผลตอบแทนหลังเกษียณ | bps | 0–1,500 |
| เงินออมปัจจุบัน (ไม่บังคับ) | สตางค์ | 0–100,000,000,000 (ไม่กรอก = 0) |

- bps = 1/10,000 ต่อปี (3% = 300) เป็นจำนวนเต็มล้วน ไม่ใช่เงิน · ห้าม `NaN`, `Infinity`, ทศนิยม, `-0`
- เดือนช่วงสะสม n = (อายุเกษียณ − อายุปัจจุบัน) x 12 · เดือนช่วงเกษียณ M = (อายุคาดการณ์ − อายุเกษียณ) x 12 (n ≤ 984, M ≤ 1,080 ตามช่วงข้างบน)
- ผลลัพธ์ทุกค่าต้องเป็นจำนวนเต็มในช่วงปลอดภัย ไม่ใช่ = `RangeError` ("ค่าสมมติฐานทำให้ตัวเลขใหญ่เกินกว่าจะคำนวณได้") ไม่ตัดค่าให้

## 18.3 สูตรและลำดับการปัดเศษ (ตายตัว เปลี่ยนต้องเทียบ golden)
คำนวณด้วย `bigint` ทั้งหมด ห้าม `Math.pow`, `**` กับ number, `parseFloat`, `toFixed`
สเกลตัวคูณอัตรา `S = 10^18` (ตัวคูณไม่มีหน่วย) · ตัวคูณโตรายเดือนของอัตรา b bps: `G(b) = roundHalfUp(S x (120000 + b), 120000)`

1. ค่าใช้จ่าย ณ วันเกษียณ (Y = n/12 ปี, เงินเฟ้อ i): `E_ret = roundHalfUp(E0 x (10000+i)^Y, 10000^Y)` สตางค์ (เศษส่วนจำนวนเต็มตรงตัว ปัดครั้งเดียว) ถือเป็นจำนวนเต็มตั้งต้นของขั้นถัดไป (หลักเดียวกับ R17)
2. เงินถอนรายเดือนของปีเกษียณที่ k: `W_k = roundHalfUp(E_ret x (10000+i)^k, 10000^k)` สตางค์ ใช้เท่ากันทั้ง 12 เดือนของปีนั้น
3. เงินที่ต้องมี ณ วันเกษียณ (ถอนต้นเดือน ลดค่าด้วยอัตราหลังเกษียณ b₂): `D_0 = S`, `D_(m+1) = roundHalfUp(D_m x S, G(b₂))` · `PV = Σ W_floor(m/12) x D_m` (สะสมตรงตัวไม่ปัดระหว่างบวก) · **`N = ceilDiv(PV, S)`** (ปัดขึ้น)
4. ช่วงสะสม (ผลตอบแทนก่อนเกษียณ b₁, ฝากปลายเดือน): `P_0 = S`, `P_(t+1) = roundHalfUp(P_t x G(b₁), S)` · `A = Σ_(t=0..n−1) P_t` · `FVsav = roundHalfUp(Sav x P_n, S)` · `gap = N − FVsav`
5. เงินเก็บต่อเดือน: `gap ≤ 0` → 0 · ไม่งั้น **`PMT = ceilDiv(gap x S, A)`** (ปัดขึ้น) · A ≥ n x S > 0 เสมอ จึงไม่หารศูนย์
6. ค่าเสริม (แสดงอย่างเดียว ไม่ป้อนกลับ): `N_today = roundHalfUp(N x 10000^Y, (10000+i)^Y)`

เหตุผลการปัด: ปัดครึ่งขึ้นระหว่างทาง (เป็นกลาง ตรง R8 เพราะทุกค่าเป็นบวก) · ปัดขึ้นเฉพาะ N และ PMT ปลายทาง เพราะเป็นตัวเลขวางแผน ประเมินต่ำอันตรายกว่าประเมินสูง · N ที่ปัดขึ้นแล้วเป็นตัวตั้งต้นของขั้น 4–5 (ไม่ปัดซ้อน) จึง PMT อาจสูงกว่าค่าคณิตศาสตร์แท้ราว 1–2 สตางค์ ยอมรับได้ · **ความคลาดเคลื่อนจากค่าคณิตศาสตร์แท้ (ไม่ปัดระหว่างทาง):** เงินถอนรายเดือนถูกปัดเป็นสตางค์จริง ตัวขยายหลักคือการปัด E_ret (≤ 0.5 สตางค์) ที่ถูกคูณด้วยตัวคูณเงินเฟ้อ f_k ในทุกปีเกษียณ (ส่วนการปัด W_k เองไม่ถูกขยาย) จึงคลาดได้ ≤ (0.5 x f_k + 0.5) สตางค์ ต่อเดือน รวมทุกเดือนของช่วงเกษียณ (ขอบบน ≈ 6 x Σ(f_k + 1) สตางค์ เมื่อ f_k = (1 + เงินเฟ้อ)^k) ตัวอย่างจริงในเทสต์คลาดได้หลักสิบถึงร้อยสตางค์ (ไม่เกินสองสามบาท) เมื่อเงินที่ต้องมีเป็นล้านบาท ซึ่งน้อยมากเมื่อเทียบกับความไม่แน่นอนของสมมติฐาน · เมื่อไม่มีเงินเฟ้อ (เงินถอนเป็นสตางค์เต็มอยู่แล้ว) ต่างได้ไม่เกิน 2 สตางค์ · (ร่างแรกของผู้ตรวจระบุ "≤ 1–2 สตางค์" ซึ่งผิดเมื่อมีเงินเฟ้อ แก้แล้วหลังเทียบกับตัวอ้างอิงเศษส่วนแท้ในเทสต์)
`ceilDivBig` เพิ่มที่ `src/domain/money/round.ts` ที่เดียว (**ข้อยกเว้นของ R8 ต้องเจ้าของอนุมัติ**) ห้ามปัดขึ้นที่อื่น ห้าม `Math.ceil`

## 18.4 อัตรา 0% และ real return ต่ำกว่า 0
- ไม่มีการหารด้วย (อัตรา − เงินเฟ้อ) หรือ (G − S) ที่ไหนในโค้ด (วนลูปรายเดือนแทนสูตรปิด) ตัวหารมีแค่ `G(b)` ≥ S > 0 จึงเป็นศูนย์ไม่ได้ · อัตรา 0 ทั้งสองช่วงได้ผลจำนวนเต็มตรงๆ ไม่มีเศษ ceiling เกินมา
- หลังเกษียณต่ำกว่าเงินเฟ้อ (b₂ < i) เป็นกรณีปกติ ไม่ใช่ข้อผิดพลาด แต่ต้องแสดงคำเตือน "ผลตอบแทนหลังเกษียณต่ำกว่าเงินเฟ้อ เงินจะหมดเร็วกว่าที่รู้สึก"
- ห้ามคืน `Infinity`/`NaN` หรือเงียบเมื่อเกินช่วง ต้อง `RangeError`

## 18.5 เงินออมปัจจุบันเกินเงินที่ต้องมี
`FVsav ≥ N` → `PMT = 0` และแสดง "เงินออมปัจจุบันถึงเป้าตามสมมติฐานแล้ว" ห้ามแสดงตัวเลขติดลบ · ยังแสดง N และค่าอื่นตามปกติ

## 18.6 แปลงข้อความอัตราเป็น bps (ขอบ UI เท่านั้น)
- ฟังก์ชันเดียว `parseRateToBps(text)` ใน `src/domain/money/` · รับเฉพาะ `^\d{1,3}(\.\d{1,2})?$` หลัง trim: "3"→300, "3.5"→350, "3.55"→355, "0"→0 · คำนวณ `int x 100 + frac padEnd 2` ด้วยจำนวนเต็ม ห้าม `parseFloat`/`toFixed`
- ปฏิเสธ (ไม่ปัดเงียบ): ทศนิยมเกิน 2 ตำแหน่ง, ว่าง, ติดลบ, `1e2`, `3.`, `.5`, `abc`, `NaN`, มี `%`/ลูกน้ำ/ช่องว่างกลาง
- ค่าใช้จ่ายและเงินออมใช้ `parseBahtToSatang` ตามเดิม (R2)

## 18.7 เทสต์ที่ต้องมีอย่างน้อย
อัตรา 0% ทั้งหมดผลจำนวนเต็มตรงตัว · เงินออม 0/ไม่กรอก/พอดี/เกิน (PMT = 0) · ค่า 0/ติดลบ/NaN/Infinity และค่าสุดช่วง (min, max, min−1, max+1) ของทุกช่วง · อายุเกษียณ ≤ อายุปัจจุบัน และอายุคาดการณ์ ≤ อายุเกษียณ ถูกปฏิเสธ · เกษียณปีเดียว / ช่วงยาวสุด (n=984, M=1,080) · real return ติดลบ/เท่ากับ/บวก · ตัวเลขใหญ่ต้อง `RangeError` ไม่ใช่ค่าผิด · .5 สตางค์ปัดขึ้น · ceiling หารลงตัวไม่ +1 และเหลือเศษ +1, `ceilDiv` เลขใหญ่เกิน 2^53 · `parseRateToBps` ทุกตัวอย่าง · ค่า golden จากตัวอ้างอิงอิสระ (เศษส่วนแท้ไม่ปัดระหว่างทาง) ≥ 5 ชุด ต่างไม่เกินขอบจากการปัดเงินถอนรายเดือนเป็นสตางค์ (ดู 18.3) และไม่เกิน 2 สตางค์เมื่อไม่มีเงินเฟ้อ · deterministic และความสัมพันธ์ทิศทาง · ฟังก์ชันไม่ import `ledger` · คำเตือน 18.1 ครบและไม่มีคำต้องห้าม (เทสต์สแกนข้อความ) · ไม่มี float ในโค้ดโดเมน

## 18.8 เฟส 2: ผูกกับพอร์ตจริงและแผน DCA
- มูลค่าพอร์ตต้องคำนวณตาม R17 ด้วยราคาที่ผู้ใช้ป้อนพร้อมวันที่ของราคา · **ห้ามใช้ราคาทุนแทนมูลค่าเงียบๆ** สินทรัพย์ไม่มีราคา = "ยังไม่มีราคา" และบอกว่ามูลค่ารวมไม่ครบ (ไม่นับเป็น 0) · ถ้าจะใช้ต้นทุนเป็นค่าประมาณต้องเป็นปุ่มที่ผู้ใช้เลือกเอง ติดป้าย "ราคาทุน ไม่ใช่มูลค่าตลาด" · ราคาเก่ากว่าเกณฑ์ (เสนอ 30 วัน เวลาไทย) ต้องเตือน
- ผู้ใช้เลือกเองว่าบัญชีลงทุน/สินทรัพย์ไหนนับเป็นเงินเกษียณ ค่าเริ่มต้นไม่เลือกสักบัญชี · THB เท่านั้น (R3, R10)
- เมื่อผูกพอร์ต "เงินออมปัจจุบัน" ใช้มูลค่าพอร์ตแทน ห้ามบวกซ้ำกับค่าที่กรอกเอง และต้องบอกที่มา ("จากพอร์ต ณ วันที่ …" หรือ "กรอกเอง")
- ความคืบหน้า = `roundHalfUp(มูลค่าพอร์ตสตางค์ x 10000, N)` เป็น bps แสดงผลอย่างเดียว ห้ามป้อนกลับเข้าสูตร · ห้ามแสดง 100% ถ้ายังน้อยกว่า N (ปัดได้ 10000 ให้แสดง 99.99%) · แสดงเกิน 100% ได้เมื่อมูลค่า ≥ N · ต้องมีเทสต์ N = 0
- แผน DCA เป็นตัวเตือนเปิดฟอร์ม ไม่ใช่เงินที่ผูกพัน: เทียบ "แผน DCA ต่อเดือน กับ PMT" ต้องติดป้าย "แผนที่ตั้งไว้ ไม่ได้การันตีว่าจะทำตามจริง" · ห้ามนับ DCA ที่ยังไม่ยืนยันเป็นเงินออม
