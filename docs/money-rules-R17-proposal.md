# ข้อเสนอกฎ R17: ความละเอียดของหน่วยลงทุนและราคา (เจ้าของอนุมัติ 11 พ.ย. 2569 พร้อมเงื่อนไข: ระบุวิธีปัดเศษ · ตรวจข้อมูลสเกล R9 เดิม (ไม่พบ) · บัญชีลงทุนไม่นับใน SAFE-TO-SPEND ตั้งแต่ P2)

**สถานะ: อนุมัติและเขียนลง `docs/money-rules.md` แล้ว (R3/R9 สเกลหน่วย, R11 ต้นทุนเฉลี่ย, R17) เมื่อ 11 พ.ย. 2569** ไฟล์นี้เก็บเหตุผลและตัวอย่างประกอบ ถ้าขัดกับ `money-rules.md` ให้ถือ `money-rules.md`

## สิ่งที่ชนกับกฎเดิม (ต้องมติ)
1. **R9** กำหนดจำนวนหุ้น 10^6 แต่ข้อเสนอใช้ 10^8 → แก้ R9 เฉพาะจำนวนหน่วย (ราคายัง 10^6)
2. **R11** บังคับ FIFO แต่ขอให้ใช้ต้นทุนเฉลี่ย → (ก) แก้ R11 ให้วิธีต้นทุนตั้งต่อพอร์ต ค่าตั้งต้นเฉลี่ย หรือ (ข) FIFO อย่างเดียว (invariant ด้านล่างใช้ได้ทั้งสอง)
3. **R3/R10/R11 FX และ FX Gain** ไม่รวมรุ่นแรก → แยกเป็น R18 ภายหลัง

## 1. หน่วย ราคา สกุลเงิน
- **จำนวนหน่วย** = จำนวนเต็ม × 10^8 (`UNIT_SCALE`) สเกลเดียวทุกสินทรัพย์ (6 ตำแหน่งหยาบเกินสำหรับเหรียญราคาสูง: 1 step ≈ 3 บาท ที่ราคา 3,000,000/หน่วย) ข้อมูลเกิน 8 ตำแหน่งปัดครึ่งออกจากศูนย์ (R8)
- **ราคาต่อ 1 หน่วย** = micro-baht (× 10^6) จำนวนเต็มบวกเท่านั้น (NAV 4 ตำแหน่งเก็บไม่เพี้ยน) ราคาต่ำกว่า 0.000001 บาทปฏิเสธพร้อมคำอธิบาย
- **สกุลเงิน** รุ่นแรก THB เท่านั้น เก็บฟิลด์ `currency` (R3) แต่ปฏิเสธสกุลอื่น
- **ชนิดข้อมูล** `Units` = `bigint`, `PriceMicro` = จำนวนเต็มปลอดภัย (branded type กันสลับสเกล) · DB เก็บ text/numeric ไม่ใช้ JSON number (เกิน 2^53 เพี้ยนเงียบ)

## 2. มูลค่า = หน่วย × ราคา
- `satang = roundHalfUp(units × priceMicro / 10^12)` ปัดครั้งเดียว BigInt ตลอด ห้ามปัดเป็น micro ก่อนแล้วปัดสตางค์อีกที
- ผลเกินช่วงปลอดภัย → `RangeError` · ไม่เป็น -0
- ตัวอย่าง: 1.5 หน่วย × 100.333333 บาท = 15,049.99995 สตางค์ → 15,050 สตางค์ (150.50 บาท)
- **ห้ามใช้ `mulMicro` ซ้ำ** (หาร 10^6 ผิดสเกล 100 เท่าโดยไม่ error) ใช้ `valueInSatang(units, priceMicro)` ใหม่
- มูลค่าพอร์ต: คิดต่อสินทรัพย์ครั้งเดียวจากหน่วยรวม แล้วรวมมูลค่าที่ปัดแล้วต่อสินทรัพย์ · มูลค่าตลาดเป็นค่าแสดงผล ไม่ลงสมุดบัญชี

## 3. ต้นทุนเฉลี่ยและกำไรขาดทุนที่รับรู้ (เจ้าของอนุมัติต้นทุนเฉลี่ย 11 พ.ย. 2569) · **ค่าธรรมเนียมซื้อรวมเข้าต้นทุน**
- เก็บต่อสินทรัพย์ (U หน่วย, C ต้นทุนรวมสตางค์ **รวมค่าธรรมเนียมซื้อแล้ว**) ไม่เก็บราคาเฉลี่ย (ค่าแสดงผลเท่านั้น)
- ซื้อ: U += u, C += (A + F) โดย A = มูลค่าซื้อสตางค์ F = ค่าธรรมเนียมสตางค์ (ตรงกับเงินที่ออกจากกระเป๋าเป๊ะ)
- ขาย u หน่วย: `gross = valueInSatang(u, sellPrice)` · `net = gross − F` (ค่าธรรมเนียมขายหักจากเงินที่ได้ ไม่เข้าต้นทุน) · ถ้า u = U → `costOut = C` ตรงๆ ไม่งั้น `costOut = roundHalfUp(C × u / U)` · `gain = net − costOut` (ลบ ไม่ปัด) · `U' = U − u`, `C' = C − costOut`
- **วิธีปัดเศษ (ชัดเจน):** ค่าเงินแต่ละตัว (gross, costOut, units ของ DCA) คำนวณด้วย BigInt จากจำนวนเต็มตั้งต้นแล้ว `roundHalfUp` (ปัดครึ่งออกจากศูนย์ R8) **ครั้งเดียว ตอนแปลงเป็นสตางค์** ห้ามนำค่าที่ปัดแล้วไปคำนวณปัดซ้ำต่อ (เช่น ราคาเฉลี่ย × หน่วย) ส่วนการบวก/ลบสตางค์ไม่ปัด
- ห้ามคิดกำไรเป็น (ราคาขาย − ราคาเฉลี่ย) × u
- **Invariant:** `C = C' + costOut` ตรงเป๊ะ · Σ(A+F ของการซื้อ) = ΣcostOut + C เหลือ · U' = 0 ⇔ C' = 0 · 0 ≤ C' ≤ C · gain + costOut = net
- ขายเกินที่ถือ → ปฏิเสธทั้งรายการ ไม่รองรับ short · ขายหมด → ต้นทุนเหลือ 0 ตรงเป๊ะ
- WHT ปันผลแยกช่อง (R11) เป็นรายจ่ายหมวด "ภาษีหัก ณ ที่จ่าย" (ค่าตั้งต้น รอเจ้าของยืนยันถ้าต้องการเป็นเครดิตภาษี) ไม่เข้าต้นทุน
- **ลำดับมีผล:** เรียงตาม (date, createdAt) · แก้/ลบรายการซื้อในอดีตทำให้ costOut ของการขายหลังจากนั้นเปลี่ยน แต่ Entry เดิมเก็บค่าเก่า → รุ่นแรก **บล็อกการแก้/ลบรายการซื้อ/ขายที่มีรายการขายตามหลัง** (ต้องลบรายการขายก่อน) และ Integrity Check ต้องจับความเพี้ยนได้

## 4. DCA: ซื้อด้วยเงินคงที่ A สตางค์ (ไม่รวมค่าธรรมเนียม F)
- เงินที่ออกจากกระเป๋า = A + F · **ต้นทุนที่บันทึก = A + F** ไม่คำนวณกลับจาก units × price
- `units = roundHalfUp(A × 10^12 / priceMicro)` ที่สเกล 10^8 (R8) · ไม่มี "เศษเงินเหลือ" ส่วนต่างอยู่ในราคาเฉลี่ยจริง
- ผู้ใช้กรอก units จากโบรกเกอร์ → ใช้ค่าที่กรอก
- units = 0 หรือราคา = 0 → ปฏิเสธ
- ตัวอย่าง (สมมติ): A = 100,000 สตางค์, F = 0, ราคา 333.3333 บาท → 3.0000003 หน่วย ต้นทุนบันทึก 100,000 สตางค์
- แผน DCA เป็นเพียงตัวเตือน: ถึงกำหนดเปิดฟอร์มซื้อที่กรอกค่าไว้ให้ ผู้ใช้ยืนยันเอง **ห้ามสร้างรายการรอยืนยันในฐานข้อมูล**

## 5. สมุดบัญชีคู่ (R16)
บัญชี `asset` ต่อสินทรัพย์เก็บ **ต้นทุนสตางค์** · หน่วยอยู่ในตารางรายการลงทุนที่ชี้ `entryId` · ยอดหน่วย/ต้นทุนคำนวณจากการเล่นซ้ำ ไม่เก็บยอดตายตัว · ซื้อ/ขายผูกกระเป๋าทุกครั้ง (เจ้าของอนุมัติ)

| เหตุการณ์ | Lines (+เดบิต / −เครดิต) |
|---|---|
| ซื้อ | +asset (A+F), −กระเป๋า (A+F) |
| ขายกำไร | +กระเป๋า net, −asset costOut, −income "กำไรจากการลงทุน" (net−costOut) |
| ขายขาดทุน | +กระเป๋า net, +expense "ขาดทุนจากการลงทุน" (costOut−net), −asset costOut |
| ปันผล | +กระเป๋า (D−W), +expense "ภาษีหัก ณ ที่จ่าย" W, −income "ปันผล" D |
| ปันผลลงทุนต่อ | +asset D, −income "ปันผล" D (หน่วยเพิ่ม ไม่มีเงินสด) |

- กำไรจากการลงทุนและปันผลเป็นหมวดรายรับแยกของตัวเอง **ไม่ปนกับรายรับเงินเดือน** (หน้ารายงาน/ภาพรวมต้องแสดงแยก) ผลต่างที่เป็น 0 ไม่สร้าง Line
- Line เป็น 0 ห้ามสร้าง (R16) · Entry เหลือ <2 บรรทัด → ปฏิเสธ
- R6: ต้นทุนซื้อ/ขายออกเป็นสินทรัพย์ ไม่ใช่รายรับรายจ่าย
- **บัญชีลงทุนไม่นับใน `cashBalance`/SAFE-TO-SPEND/RUNWAY ตั้งแต่วันแรกที่มีบัญชีลงทุน** ผ่านป้ายประเภทบัญชี (`kind: 'investment'`) ที่ใส่ตั้งแต่ P2 · ต้องมีเทสต์ว่ายอดเหล่านี้ไม่เปลี่ยนเมื่อเพิ่มบัญชีลงทุนที่มียอด
- **Integrity Check ใหม่:** ต้นทุนในสมุดต่อสินทรัพย์ = C ที่เล่นซ้ำ · U ไม่ติดลบ และ U=0 ⇔ C=0 · ทุกรายการมี Entry ผูกและค่าตรงกัน · หน่วย/ราคาเป็นจำนวนเต็ม ราคา>0 หน่วย>0 ในช่วงปลอดภัย · ทุกรายการ THB · Σ(A+F) = ΣcostOut + C เหลือ

## 6. เทสต์ขอบเขตที่ต้องมี
- **parse:** "0", "0.00000001" (=1), "0.000000005" (ปัด 1), "0.000000004" (ปัด 0 → ปฏิเสธ), "-1", "-0", "1e-7", "1,000.5", ว่าง, "abc", "1.2.3"
- **valueInSatang:** units 0, ราคา 0 (ปฏิเสธ), ผล .5 สตางค์พอดี, ต่ำกว่า .5 นิดเดียว, 1 step × 1 micro (=0 สตางค์ → ปฏิเสธระดับรายการ), units×price เกิน 2^53 แต่ผลปลอดภัย, ผลเกินช่วง (RangeError), ไม่เป็น -0
- **ต้นทุนเฉลี่ย:** ซื้อ 3 ขาย 2 ขายหมด ตรวจ invariant ทุกขั้น · ขายหมดเหลือ 0 เป๊ะ · u = U−1 step · 1 step · เกิน 1 step (ปฏิเสธ) · ขายขาดทุน · กำไร 0 พอดี · C = 1 สตางค์ขายบางส่วน · สุ่มซื้อขาย 1,000 รอบ (seed คงที่) ตรวจ Σต้นทุนซื้อ = ΣcostOut + C
- **DCA:** A เล็กจน units=0 · ราคา 0 · ราคาเศษ 1/3 · A = 1 สตางค์ · หลายงวด Σเงินที่หัก = ΣA
- **ลงสมุดบัญชี:** ทุกประเภทสมดุล · ข้าม Line 0 แล้วยัง ≥2 บรรทัด · WHT=0 · กำไร=0 · รายการลงทุนไม่นับเป็นรายรับ/จ่ายใน `overview` (R6)
- **Integrity:** แก้ซื้อย้อนหลังแล้วต้นทุนขายไม่ตรง (ต้องจับได้) · U ติดลบ · U=0 แต่ C≠0 · สกุลไม่ใช่ THB
- **round-trip:** units เกิน 2^53 เก็บ/อ่านกลับเท่าเดิมใน Dexie และ Supabase ไม่ผ่าน float
- **สแกนโค้ด:** ไม่มี `parseFloat`/`toFixed`/`* 100` ในโฟลเดอร์ลงทุน

## 7. ความเสี่ยงที่พบ
1. `mulDivRound` ใน `micro.ts` รับ number: units 8 ตำแหน่งเกินช่วงปลอดภัยที่ ~90 ล้านหน่วย → ต้องมีเวอร์ชัน bigint และ RangeError ตอนแปลงกลับ
2. `mulMicro` ผิดสเกล 100 เท่า (ข้อ 2) → ฟังก์ชัน+branded type แยก
3. `parseMicro` ยอมรับเลขลบ → ต้องมี parser ใหม่ปฏิเสธลบ/ศูนย์
4. ราคา/หน่วย 0: หารด้วยศูนย์ใน DCA ต้องเป็นข้อความที่ผู้ใช้เข้าใจ · รายการมูลค่า 0 สตางค์ผ่าน R16 ไม่ได้
5. ติดลบ: ขายเกิน (ปฏิเสธ) · C' ติดลบจากปัดผิดทิศ (ทางลัดขายหมด + ตรวจใน Integrity Check)
6. ทศนิยมหลุดเข้า float: `parseFloat`/`Number()` จาก CSV/ช่องกรอก · JSON number จาก Supabase · `toFixed` แล้วคำนวณต่อ · scientific notation
7. ลำดับ/แก้ย้อนหลัง (ข้อ 3)
8. ราคาต่ำกว่า 0.000001 บาท → ปฏิเสธพร้อมคำอธิบาย ไม่ปัดเป็น 0
9. ราคากรอกเองไม่มีที่มา → เตือนเมื่อต่างจากครั้งก่อนมากผิดปกติ
