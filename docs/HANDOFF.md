## 2. กติกาการทำงาน (สำคัญ ห้ามข้าม)

1. ทำ **ทีละ Ticket**: Spec → เขียนเทสต์ → เขียนโค้ด → รันเทสต์/typecheck/build → สรุป + วิธีทดสอบ → รอเจ้าของยืนยันก่อนไป Ticket ถัดไป

## 7. การตัดสินใจ: ดีไซน์ = แบบ A "Aurora Glass" (Liquid Glass มืด)

ไฟล์อ้างอิงอยู่ใน zip: `design/A-aurora-glass.dc.html` (เปิดอ่านโค้ด HTML/CSS ได้ตรงๆ) · canvas: https://claude.ai/artifact/2iVXe5btY1vPDyUS5puqYu

**โครงหน้า** (ยึดไฟล์ `index2.html` เก่าของเจ้าของ)
- แถบซ้ายกระจก: โลโก้ MB + "Money Buddy / เกษียณเป็นเรื่องของคนวางแผน" · การ์ดโปรไฟล์
- เมนูหลัก: **ภาพรวม (หน้าแรก)**, รายรับ-รายจ่าย, พอร์ตการลงทุน, แผนลงทุน, ปรับสมดุลพอร์ต (badge)
- เครื่องมือ: วางแผนเกษียณ, คำนวณภาษี (2569), ถัวเฉลี่ยต้นทุน, โปรไฟล์ · ล่างสุด "บันทึกอัตโนมัติแล้ว"
- หัวหน้า: ทักทาย + วันที่ · ช่องพิมพ์จดด่วน · ปุ่มสแกนสลิป · ปุ่มเพิ่มรายการ (ทอง)

**หน้าภาพรวม เรียงจากบนลงล่าง**
1. แถว 4 การ์ด: NET WORTH (+ เส้นแนวโน้ม, เทียบเดือนก่อน) · INCOME (จำนวนช่องทาง, เข้ากระเป๋าไหน) · OUTGOING (บิล vs ใช้จ่าย, บิลค้างจ่าย) · SURPLUS (% ของรายรับ)
2. แถว 4 การ์ด: **SAFE-TO-SPEND** ฿/วัน + สถานะ (= (คงเหลือ − บิลค้าง − เป้าออม) ÷ วันที่เหลือรวมวันนี้) · SAVINGS RATE (+ เส้นเป้า 20%) · VS LAST MONTH (+ เป้างบเดือน) · RUNWAY (เงินสดไม่รวมพอร์ต ÷ ค่าครองชีพ, เป้า 6 เดือน)
3. **Cash Flow แบบ Sankey** เต็มความกว้าง: รายรับ → งบรายเดือนรวม → หมวด (เหลือเก็บ, บิล, อาหาร, ...) ความหนา = สัดส่วนเงิน · มีเลือกเดือน + ชิปสรุป · หมวดเล็กรวมเป็น "อื่นๆ"
4. กระเป๋าเงิน (แถบ % ของทั้งหมด) | บิลที่จะถึง
5. รายการล่าสุด (พื้นทึบ, จัดกลุ่มตามวัน) | เป้าเกษียณปีนี้ + สัดส่วนพอร์ต
- ทุกการ์ดมีลิงก์ "ดู… →" ไปหน้าย่อย

**Token**
- พื้น `#07080d` + ก้อนแสงเบลอ (ม่วง `#3b2bd6`, เขียวน้ำทะเล `#0fa3a3`, ทอง `#c9871a`, ชมพู `#b0306e`)
- กระจก: `linear-gradient(140deg, rgba(255,255,255,.14), rgba(255,255,255,.035))` + `backdrop-filter: blur(32px) saturate(180%)` + ขอบ `rgba(255,255,255,.16)` + เงาใน `inset 0 1px 0 rgba(255,255,255,.4)` + radius 28px · fallback `prefers-reduced-transparency` = พื้นทึบ `#171a26`
- รายการ/ตาราง: พื้นทึบ `rgba(12,14,21,.9)` radius 24px
- สี: ทอง `#F2D06B` · รายรับ `#6FD9A8` · รายจ่าย `#FF8F82` · โอน `#8FB8FF` · เตือน `#FFB86B` · ข้อความ `#F4F5FA` · รอง `rgba(244,245,250,.66)`
- หมวดใน Sankey: บิล `#A99BFF` อาหาร `#FF8F82` เดินทาง `#FFB86B` ช้อปปิ้ง `#FF7EB6` อื่นๆ `#9AA0B4` เหลือเก็บ `#6FD9A8`
- ฟอนต์: IBM Plex Sans Thai (400–700) · ตัวเลข `tabular-nums` · ปุ่มสูง ≥ 44px · ไอคอนเส้น SVG ไม่ใช้อีโมจิ

**ฟีเจอร์ที่หน้าใหม่ต้องการแต่โค้ดยังไม่มี** (ต้องเพิ่มใน domain ก่อนโชว์ได้จริง)
บิลประจำ/บิลค้างจ่าย, เป้าออมรายเดือน, เป้างบรายเดือน, ประวัติเดือนก่อน, มูลค่าพอร์ต/สัดส่วน, เป้าเกษียณ, ยอดสุทธิย้อนหลัง (เส้นแนวโน้ม) → การ์ดไหนข้อมูลยังไม่มีให้แสดงสถานะว่าง "ตั้งค่า…" แทนตัวเลขปลอม

- เขียนทับข้ามแท็บยังเหลือ 3 จุด (กระทบเฉพาะค่าตั้งค่าของตัวเอง ไม่ใช่ยอดเงิน): แผน DCA (ทั้งก้อน `dcaPlans`), ป้ายภาษี (ส่งทั้งสองอาร์เรย์), ฟอร์มค่าตั้งค่าหน้าบิล (ส่งคีย์ของฟอร์มครบชุด) · ปิดจริงต้องมี RPC เพิ่ม/ลบทีละรหัส หรือส่งค่าเดิมที่คาดไว้ (`p_expect`)
- RPC `merge_settings` ไม่กรองคีย์นอกรายการ 6→8 ตัวฝั่ง SQL (ใส่ allowlist ต้องมี migration ทุกครั้งที่เพิ่มคีย์)
- รหัสสินทรัพย์ในป้ายภาษีกันอักขระควบคุมเฉพาะ `\u0000` และ surrogate ไม่คู่ (ใช้ `hasDbInvalidChars` เดิม) ไม่แสดงบนจอ จึงไม่อันตราย

**คำถามรวมให้เจ้าของ (ถามทีเดียว)**
1. อนุมัติ migration แก้ check ของ `settings` เป็นวัดขนาดแบบไม่บีบอัดไหม (ข้างบน)
2. อยากปิดช่องเขียนทับข้ามแท็บของแผน DCA/ป้ายภาษีจริงไหม (ต้องมี RPC ใหม่ ตอนนี้ยอมรับได้)
3. ลองบนอุปกรณ์จริงแล้วแจ้งผล: ตารางภาษีบนมือถือ 360px, การ์ดเครื่องมือวางแผนหน้าภาพรวม, ส่วนดึงยอดซื้อจากพอร์ตในเครื่องคิดภาษี (ต้องออนไลน์และมีสินทรัพย์)
4. ยังรอเรื่องภาษีตามหัวข้อ 30 (ต้นฉบับที่อ่านไม่ออก: PVD, Thai ESG/ThaiESGX, ประกาศ 462, ประกันสังคมทางการ, E-Receipt/Solar/e-Donation/SSF)

## 43. เหตุการณ์ลบผู้ใช้ทั้งหมดโดยไม่ตั้งใจ + สคริปต์ `admin:delete-user` (13 พ.ย. 2569)

**เหตุการณ์:** ตอนลบบัญชีทดสอบ (testnew) ในหน้า Supabase เจ้าของลบผู้ใช้ทั้งหมดโดยไม่ตั้งใจ (รวมบัญชีตัวเอง) · พบจากการนับแถวแบบอ่านอย่างเดียว (หัวข้อ 42: `auth.users` = 0, ทุกตารางข้อมูลว่าง) · **ผลกระทบ:** ข้อมูลผู้ใช้หายจากฐานข้อมูล · **การกู้:** เจ้าของสร้างบัญชี kumeyuri ใหม่และนำเข้าไฟล์สำรอง (ยังไม่สร้างบัญชีเพื่อน) → กู้ได้เพราะมีไฟล์สำรองส่งออกไว้ · ตัวผู้ช่วยไม่ได้ตรวจเนื้อหาข้อมูลหลังนำเข้า

**วิธีป้องกัน (ทำใน PR นี้):**
1. สคริปต์ `npm run admin:delete-user -- <username> [--force]` (เจ้าของรันเองเท่านั้น): ทีละ 1 บัญชีตามชื่อ ไม่รับหลายชื่อ/wildcard · แสดงชื่อ + จำนวนแถวต่อตาราง แล้วต้องพิมพ์ชื่อซ้ำ · ปฏิเสธบัญชีสุดท้าย/ชื่อ kumeyuri เว้นแต่ `--force` · ลบแล้วอ่านกลับยืนยันไม่มีข้อมูลค้าง · ใช้ `admin.env` เหมือน create-user
2. เพิ่มคำสั่งนี้ใน `permissions.deny` (Bash + PowerShell) → ผู้ช่วย AI รันไม่ได้
3. วินัย: **ห้ามลบผู้ใช้ในหน้า Supabase** ใช้สคริปต์นี้เท่านั้น · **ส่งออกไฟล์สำรองก่อนลบบัญชีที่มีข้อมูลจริงเสมอ** · เช็กจำนวนผู้ใช้ก่อน/หลัง
4. รายละเอียด: `docs/decisions/2026-11-13-admin-delete-user.md`

**รอเจ้าของ:** ลองสคริปต์ครั้งแรกกับบัญชีทดสอบที่สร้างใหม่ (ผู้ช่วยรันไม่ได้ จึงยังไม่เคยลองกับ Supabase จริง ทดสอบแล้วเฉพาะตรรกะ+โครงสร้าง) · ตรวจว่าข้อมูลหลังนำเข้าไฟล์สำรองครบ · เรื่องเดิม: ตรวจตารางภาษีด้วย screen reader, ต้นฉบับภาษีหัวข้อ 30, backlog

ผลตรวจ security-auditor: ไม่พบระดับสูง · แก้ตามข้อกลาง/ต่ำแล้ว (ยืนยันผลหลังลบเข้มขึ้น, นับ profiles, นับซ้ำก่อนลบ, วลียืนยันยาวเมื่อ --force, deny เพิ่ม) · ช่องที่ยอมรับ: deny list จับจากข้อความ เลี่ยงได้ด้วยตัวห่อบางแบบ (เหมือน create-user) ด่านจริงคือ TTY + พิมพ์ยืนยัน · create-user/reset-password ยังใช้ deny ชุดเดิม (ถ้าต้องการเสริมให้บอก)

### ผลลองสคริปต์ `admin:delete-user` จริง (13 พ.ย. 2569)
เจ้าของลองกับ Supabase จริง **ผ่าน:**
- ลบบัญชีทดสอบ `testdel` ได้ · ระบบถามให้พิมพ์ชื่อยืนยันก่อนลบ · อ่านกลับแล้วเป็น 0 แถว
- ลองลบ `kumeyuri` โดยไม่ใส่ `--force` → **ถูกปฏิเสธทันที ไม่ถามยืนยัน**
- ปิดข้อ "รอเจ้าของ: ลองสคริปต์ครั้งแรก" ของหัวข้อ 43 (ส่วนที่ผู้ช่วยทดสอบเองไม่ได้ ตอนนี้ยืนยันกับของจริงแล้ว) · ยังรอ: ตรวจว่าข้อมูลหลังนำเข้าไฟล์สำรองครบ

### ตรวจฐานข้อมูลหลังลองสคริปต์ลบ + เทียบข้อมูลที่นำเข้า (13 พ.ย. 2569, SQL อ่านอย่างเดียว นับแถวเท่านั้น)
- **testdel: ยังมีอยู่ใน `auth.users` (1 แถว)** ← ไม่ตรงกับที่เจ้าของแจ้งว่าลบแล้ว (อาจสร้างใหม่ภายหลัง หรือการลบไม่สำเร็จ ต้องตรวจ) · `auth.users` ทั้งระบบ = 2 บัญชี (testdel + kumeyuri)
- แถวกำพร้า (user_id ที่ไม่มีใน `auth.users`) ครบ 21 ตาราง = **0 ทุกตาราง** (ไม่มีข้อมูลค้างจากบัญชีที่ลบไปแล้ว)
- kumeyuri มีอยู่ 1 บัญชี · จำนวนแถว: accounts **13** (asset 3, equity 1, expense 7, income 2, ไม่มีที่เก็บถาวร) · entries **5** (source system 3, ocr 2) · lines 10 · profiles 1 · bills/settings/assets/trades/asset_prices 0
- **เทียบไฟล์สำรอง (13 บัญชี 3 รายการ):** บัญชี 13 = ตรง · รายการ: system 3 ตรงกับ "3 รายการ" แต่มี ocr เพิ่มอีก 2 (ที่มาไม่ทราบ อาจเป็นรายการจากสแกนสลิปที่เจ้าของเพิ่มหลังนำเข้า → เจ้าของต้องยืนยัน) · ไม่มีบิล/ตั้งค่า ตามไฟล์ถ้าไฟล์ไม่มี
- **รอเจ้าของ:** ตรวจ testdel (สร้างใหม่หรือลบไม่สำเร็จ) และยืนยันที่มาของรายการ ocr 2 รายการ
