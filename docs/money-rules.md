# Money Rules & Architecture Guidelines

> กฎเหล็กของ Money Buddy Pro
> Claude Code / Cowork ต้องอ่านไฟล์นี้ให้ครบก่อนเริ่มทุกงาน
> ห้ามแก้ไฟล์นี้โดยไม่ได้รับอนุมัติจากเจ้าของโปรเจกต์ หากพบว่ากฎขัดกับงานที่สั่ง ให้หยุดและถามก่อน

---

## A. กฎหลักด้านเงินและข้อมูล

1. **Satang Rule:** ทุกยอดเงินใน `state.transactions` และ `state.wallets` ต้องเป็น "สตางค์" (จำนวนเต็ม) เสมอ
2. **Input/Output Boundary:**
   - `toSatang()` ทำเฉพาะตอนรับข้อมูลเข้า (Form, CSV, OCR, Quick Text)
   - `toBaht()` ทำเฉพาะตอนแสดงผลหรือส่งออก (UI, CSV Export, Vaulta, API Display)
   - ฟังก์ชัน validate, load, migrate, integrity ห้ามแปลงหน่วยเงินซ้ำซ้อน
3. **Multi-Currency (Investment):** ยอดเงินลงทุนต้องมีสกุลเงินกำกับ เก็บราคาเป็นจำนวนเต็มคูณ 10^6 (Micro-units) และจำนวนหน่วยเป็นจำนวนเต็มคูณ 10^8 (ดู R17) ห้ามบวกต่างสกุลเงินกันตรงๆ
4. **Transfer & Debt Rule:** การโอนเงินระหว่างกระเป๋าและการจ่ายเงินต้นหนี้/บัตรเครดิตต้องบันทึกเป็น `Transfer` **ห้าม**นับเป็นรายรับหรือรายจ่าย ดอกเบี้ยหนี้เท่านั้นที่เป็นรายจ่าย
5. **Security:** ห้ามใช้ innerHTML กับข้อมูลที่ผู้ใช้พิมพ์เข้ามาโดยตรง ต้องผ่านการ sanitize หรือใช้ textContent
6. **Schema & Migration:** ทุกครั้งที่เปลี่ยนโครงสร้างข้อมูล ต้องเพิ่ม `schemaVersion` และเขียนฟังก์ชัน `migrateData()` รองรับข้อมูลเก่า
16. **Ledger Rule:**
    - ทุกเหตุการณ์ทางเงินเป็น `Entry` ที่มี `Line` ตั้งแต่ 2 บรรทัดขึ้นไป
    - `amount` ของ Line เป็นจำนวนเต็มมีเครื่องหมาย: บวก = เดบิต, ลบ = เครดิต ห้ามเป็น 0
    - ผลรวมของทุก Line ใน Entry ต้องเป็น 0 แยกตามสกุลเงิน การโอนข้ามสกุลเงินต้องมีบัญชีพักอัตราแลกเปลี่ยน (`equity`) ฝั่งละสกุลเงิน
    - ยอดบัญชีเป็นค่าที่คำนวณจากผลรวม Line เสมอ ห้ามเก็บยอดคงเหลือแยกต่างหาก
    - รายรับ = เครดิตในบัญชีประเภท `income`, รายจ่าย = เดบิตในบัญชีประเภท `expense` (ทำให้กฎ R4 และ R7 เป็นจริงโดยโครงสร้าง)

## B. กฎด้านหนี้และเงินผ่อน

7. **Debt Rule:**
   - `state.debts` เก็บยอดคงเหลือและยอดต้นเป็นสตางค์ (integer)
   - การ "จ่ายงวดนี้" ต้องสร้างรายการเป็นชุดเดียวกัน คือ `Transfer` (ส่วนเงินต้น) + `Expense` (ส่วนดอกเบี้ย หมวด "ดอกเบี้ย")
   - ห้ามบันทึกค่างวดเป็นรายจ่ายก้อนเดียว เพราะจะทำให้รายจ่ายถูกนับซ้ำเมื่อรวมกับยอดหนี้ที่ลดลง
   - ลูกหนี้ (เงินที่คนอื่นยืมเรา) เมื่อได้รับคืนให้เป็น `Transfer` ไม่ใช่รายรับ
   - ต้องมีกลไกกันจ่ายซ้ำงวดเดียวกัน และรองรับ Undo
8. **Rounding Rule:**
   - ใช้ฟังก์ชันปัดเศษกลางตัวเดียว (`roundHalfUp`) ทุกที่ ห้ามใช้ `Math.round` กระจายในโค้ด
   - `roundHalfUp` ปัดครึ่งออกจากศูนย์ (2.5 -> 3, -2.5 -> -3) แก้ที่ `src/domain/money/round.ts` ที่เดียวเท่านั้น
   - งวดสุดท้ายของตารางผ่อนต้องปรับให้ยอดคงเหลือ = 0 พอดี
   - ผลรวมต้น + ดอกของทุกงวดต้องเท่ากับยอดที่ต้องจ่ายทั้งหมดเสมอ

## C. กฎด้านการลงทุนและภาษีต่างประเทศ

9. **Micro-units:**
   - ราคาเก็บเป็น integer × 10^6 และจำนวนหน่วย (หุ้น/กองทุน) เก็บเป็น integer × 10^8 (เจ้าของอนุมัติ 11 พ.ย. 2569 · ตรวจแล้วไม่มีข้อมูลเดิมใช้สเกลหน่วย 10^6) ห้ามใช้ float คำนวณเงิน
   - การคูณ micro-units กับ micro-units อาจเกิน `Number.MAX_SAFE_INTEGER` (เช่น ราคา $500 × 100 หุ้น) ให้ใช้ `BigInt` ในขั้นคูณ แล้วแปลงกลับเมื่อผลลัพธ์อยู่ในช่วงปลอดภัย
10. **FX Rule:**
    - ทุกรายการลงทุนเก็บสกุลเงินและ `fxRate` (บาทต่อ 1 หน่วยสกุลต่างประเทศ เป็น micro-units) ณ วันที่ทำรายการ
    - ห้ามบวก/ลบยอดต่างสกุลเงินโดยตรง ต้องแปลงผ่าน `fxRate` ที่ระบุชัดเจนเสมอ
11. **Cost Basis Rule (ต้นทุนเฉลี่ย):** (เจ้าของอนุมัติ 11 พ.ย. 2569 แทน FIFO เดิม)
    - การขายตัดต้นทุนตามสัดส่วนต้นทุนเฉลี่ยถ่วงน้ำหนักของสินทรัพย์นั้น รายละเอียดการคำนวณและปัดเศษดู R17
    - รองรับเงินบาท (THB) และสกุลต่างประเทศตาม R20 (ปัจจุบัน USD) · กำไรจากอัตราแลกเปลี่ยนแยกตาม R20 (เดิม: รุ่นแรกเฉพาะ THB รอกฎแยก)
    - ค่าธรรมเนียมและ WHT ต้องเก็บเป็นช่องของตัวเอง ห้ามรวมเข้า "ราคาต่อหน่วย" · ค่าธรรมเนียมซื้อรวมเข้าต้นทุนรวม ค่าธรรมเนียมขายหักจากเงินที่ได้ (net) และกำไรขาย = net − ต้นทุนที่ตัดออก
12. **Options Rule:**
    - 1 สัญญา = 100 หุ้น (ปรับได้ใน config ต่อสัญญา)
    - รองรับสถานะ: เปิด, ปิด, หมดอายุ, ถูกใช้สิทธิ (Assignment/Exercise)
    - Assignment/Exercise ต้องสร้างรายการ BUY/SELL หุ้นอัตโนมัติที่ราคา Strike และเชื่อมโยงกลับไปยังสัญญาต้นทาง
    - วิธีจัดการ premium ต่อต้นทุนหุ้นให้กำหนดไว้ใน Spec และต้องเป็น config ที่แก้ได้
13. **Tax Rule:**
    - ตัวเลขภาษีทั้งหมดเป็น "ประมาณการ" ต้องติดป้ายนี้ในทุกหน้าจอและทุกการส่งออก
    - อัตราภาษีและเงื่อนไขตามคำสั่งกรมสรรพากร (ป.161/2566 และ ป.162/2566) ต้องอยู่ใน config กลางที่แก้ได้ ห้าม hard-code กระจายหลายที่
    - Remittance Ledger ต้องเก็บ: วันที่โอนกลับ, จำนวนเงินสกุลต่างประเทศ, อัตราแลกเปลี่ยน, แหล่งที่มาของเงิน (เงินต้น/กำไร/ปันผล) และปีที่เงินได้เกิดขึ้น
    - Foreign Tax Credit ต้องไม่เกินภาษีไทยที่เกี่ยวข้องกับเงินได้ก้อนนั้น

17. **Investment Units & Cost Basis (R17):** (เจ้าของอนุมัติ 11 พ.ย. 2569 · ที่มา `docs/money-rules-R17-proposal.md`)
    - จำนวนหน่วย = จำนวนเต็ม × 10^8 (`bigint`) · ราคาต่อหน่วย = micro ของสกุลสินทรัพย์ (× 10^6 · THB = micro-baht, USD = micro-USD ตาม R20) จำนวนเต็มบวก · สกุลที่รองรับ THB และ USD (R20) · ห้ามใช้ `mulMicro`/`parseMicro` เดิมกับหน่วย (ผิดสเกล/รับเลขลบ) ต้องใช้ฟังก์ชันเฉพาะที่ใช้ BigInt และปฏิเสธค่าลบ ศูนย์ และรูปแบบ scientific
    - มูลค่า = `roundHalfUp(units × priceMicro / 10^12)` เป็นสตางค์ **ปัดครั้งเดียวตอนแปลงเป็นสตางค์ ปัดครึ่งขึ้น (ออกจากศูนย์ตาม R8)** ใช้ `roundHalfUp` ตัวกลาง ห้ามปัดเป็น micro ก่อนแล้วปัดสตางค์ซ้ำ ผลเกินช่วงปลอดภัยโยน RangeError
    - ต้นทุนเฉลี่ย: คำนวณต่อสินทรัพย์ (U หน่วย, C ต้นทุนรวมสตางค์รวมค่าธรรมเนียมซื้อ) จากการเล่นซ้ำรายการ ไม่เก็บเป็นยอดตายตัว (R16) · ซื้อ: C += A+F · ขาย u หน่วย: net = gross − F, ถ้า u = U ให้ costOut = C ตรงๆ ไม่งั้น costOut = min(roundHalfUp(C×u/U), C−1) (ให้ U'>0 ⇒ C'≥1) · gain = net − costOut · C' = C − costOut · สตางค์ที่บันทึกแล้วถือเป็นจำนวนเต็มตั้งต้นของขั้นถัดไป ไม่ปัดซ้อนในขั้นเดียวกัน
    - Invariant: C = C' + costOut · Σ(ต้นทุนซื้อและปันผลลงทุนต่อ) = ΣcostOut + C เหลือ · U' = 0 ⇔ C' = 0 · 0 ≤ C' ≤ C · ขายเกินที่ถือปฏิเสธทั้งรายการ · ค่าธรรมเนียมขายเกินเงินที่ขายได้ (F > gross) ปฏิเสธ
    - DCA: units = `roundHalfUp(A × 10^12 / priceMicro)` เงินที่ออกจากกระเป๋าและต้นทุนที่บันทึก = A+F ไม่คำนวณกลับจาก units × price · units หรือราคาเป็น 0 ปฏิเสธ · แผน DCA เป็นเพียงตัวเตือนเปิดฟอร์มให้ผู้ใช้ยืนยันเอง ห้ามสร้างรายการรอยืนยันในฐานข้อมูล
    - สมุดบัญชีคู่ (R16): ซื้อ = +asset (A+F) −กระเป๋า · ขาย = +กระเป๋า net −asset costOut และผลต่างเป็นรายรับหมวด "กำไรจากการลงทุน" หรือรายจ่ายหมวด "ขาดทุนจากการลงทุน" · ปันผล = รายรับหมวด "ปันผล" (WHT เป็นรายจ่ายหมวด "ภาษีหัก ณ ที่จ่าย") · กำไรจากการลงทุนและปันผลต้องแสดงแยกจากรายรับเงินเดือน · Line ที่ได้ 0 ข้ามทุกแถว Entry ที่เหลือ <2 บรรทัดปฏิเสธ
    - ลำดับรายการเรียงตาม (date, createdAt, id) · ห้ามเพิ่ม/แก้/ลบรายการซื้อ ขาย ปันผลลงทุนต่อ ที่มีวันที่ ณ หรือก่อนรายการขายล่าสุดของสินทรัพย์เดียวกัน (ต้องลบรายการขายหลังจากนั้นก่อน)
    - บัญชีลงทุน (`kind: 'investment'`) **ห้ามนับรวมใน `cashBalance`, SAFE-TO-SPEND และ RUNWAY** ตั้งแต่วันแรกที่มีบัญชีลงทุน (ต้องมีเทสต์) · Integrity Check: ต้นทุนในสมุดต่อสินทรัพย์ = C ที่เล่นซ้ำ, U ไม่ติดลบ, ทุกรายการมี Entry ผูกและค่าตรงกัน, ทุกรายการสกุลตรงกับสกุลของสินทรัพย์ (THB หรือ USD ตาม R20)
18. **Retirement Estimate (R18):** (เจ้าของอนุมัติ 12 พ.ย. 2569 · ที่มาและเหตุผลเต็ม `docs/money-rules-R18-proposal.md`)
    - **ประมาณการ ไม่ใช่ยอดบัญชี:** ผลทุกค่า (เงินที่ต้องมี, เงินเก็บต่อเดือน, ค่าใช้จ่าย ณ วันเกษียณ, มูลค่าวันนี้, ความคืบหน้า) คำนวณสดจากข้อมูลเข้า **ห้ามสร้าง `Entry`/`Line` ห้ามเก็บเป็นยอดตายตัว (R16)** ห้ามปนกับ SAFE-TO-SPEND, `cashBalance`, RUNWAY, รายรับ, รายจ่าย และห้ามนับเงินที่ต้องเก็บต่อเดือนเป็นบิลหรืองวดค้างของ R15 · บันทึกได้เฉพาะข้อมูลเข้า (อายุ, bps, สตางค์) ไม่บันทึกผลลัพธ์ · ฟังก์ชันอยู่ใน `src/domain/retirement/` ไม่แตะ DOM/ฐานข้อมูล/ledger
    - **ข้อความบังคับ** ติดกับผลลัพธ์ทุกครั้งในหน้าจอและการส่งออก: "ตัวเลขนี้เป็นประมาณการจากสมมติฐานที่คุณกรอก ไม่ใช่ยอดในบัญชีของคุณ ผลตอบแทน เงินเฟ้อ และอายุขัยจริงอาจต่างจากที่ตั้งไว้ ไม่ใช่คำแนะนำการลงทุนและไม่ใช่การรับประกันผลลัพธ์" · แสดงสมมติฐานทุกตัวคู่ผลลัพธ์ · ติดป้าย "ประมาณการ" ที่ตัวเลขทุกตัว · บอกข้อจำกัด (ไม่รวมภาษี ค่าธรรมเนียม บำนาญ/ประกันสังคม ความเสี่ยงอายุยืนกว่าที่ตั้ง) · ห้ามคำสื่อรับประกัน ("รับประกัน", "การันตี", "แน่นอน", "ปลอดภัยแน่", "จะได้", "เกษียณสบาย")
    - **ช่วงค่า** (นอกช่วง = `RangeError` ข้อความไทย ห้ามปัด/ตัดค่าเงียบๆ): อายุปัจจุบัน 18–79 (และน้อยกว่าอายุเกษียณ) · อายุเกษียณ 30–80 (ค่าเริ่มต้น 60) · อายุคาดการณ์ > อายุเกษียณ และ ≤ 110 · ค่าใช้จ่ายต่อเดือน 1 สตางค์–1,000,000 บาท · เงินเฟ้อ 0–1,000 bps (ค่าเริ่มต้น 300) · ผลตอบแทนก่อน/หลังเกษียณ −500 ถึง 1,500 bps **ไม่มีค่าเริ่มต้น ผู้ใช้กรอกเอง** · เงินออมปัจจุบัน 0–1,000 ล้านบาท (ไม่บังคับ) · bps เป็นจำนวนเต็มล้วน ห้าม `NaN`, `Infinity`, ทศนิยม, `-0` · money-auditor ปรับช่วงได้ถ้ามีเหตุผล (เจ้าของมอบสิทธิ์ 12 พ.ย. 2569) แต่ต้องจดเหตุผลใน `docs/decisions/`
    - **คำนวณด้วย `bigint` ทั้งหมด** ห้าม `Math.pow`, `**` กับ number, `parseFloat`, `toFixed` · วนลูปรายเดือน ไม่ใช้สูตรปิด (ไม่มีการหารด้วย "อัตรา − เงินเฟ้อ") · สเกล `S = 10^18` · ลำดับการปัดตายตัว เปลี่ยนต้องเทียบ golden: ค่าใช้จ่าย ณ วันเกษียณปัดครั้งเดียวแบบเศษส่วนตรงตัว → เงินถอนรายเดือนรายปี → เงินที่ต้องมี `N = roundHalfUp(PV / S)` → ช่วงสะสม → `PMT = ceilDiv(gap x S / A)`
    - **การปัด (ข้อยกเว้นของ R8):** ปัดครึ่งขึ้นทุกขั้น **ยกเว้น "เงินเก็บต่อเดือน (PMT)" ปัดขึ้น** เพื่อไม่ให้เก็บขาด · `ceilDivBig` อยู่ที่ `src/domain/money/round.ts` ที่เดียว ใช้กับ PMT และการแสดงผล PMT เท่านั้น ห้ามใช้กับค่าอื่นหรือยอดบัญชีจริง ห้าม `Math.ceil`
    - **หน้าจอแสดงผลปัดเป็นหลักร้อยบาท** (ปัดครึ่งขึ้น ยกเว้นเงินเก็บต่อเดือนปัดขึ้น) พร้อมคำเตือนว่าเป็นการประมาณ · ค่าที่ปัดเพื่อแสดงห้ามนำไปคำนวณต่อ · ความคลาดเคลื่อนจากค่าคณิตศาสตร์แท้เมื่อมีเงินเฟ้อ (เงินถอนรายเดือนถูกปัดเป็นสตางค์) ยอมรับได้ในระดับหลักสิบถึงร้อยสตางค์
    - **ผลตอบแทนหลังเกษียณต่ำกว่าเงินเฟ้อ** เป็นกรณีปกติ แต่ต้องเตือน "เงินจะหมดเร็วกว่าที่รู้สึก" · เงินออมเกินเงินที่ต้องมี → PMT = 0 และแสดง "เงินที่เก็บไว้แล้วถึงเป้าตามสมมติฐานแล้ว" ห้ามแสดงติดลบ · ห้ามคืน `Infinity`/`NaN` ผลไม่ใช่จำนวนเต็มปลอดภัย = `RangeError`
    - **อัตราจากข้อความผู้ใช้:** `parseRateToBps` ฟังก์ชันเดียว ที่ขอบ UI รับ `^-?\d{1,3}(\.\d{1,2})?$` · ปฏิเสธ ทศนิยมเกิน 2 ตำแหน่ง, ว่าง, `-0`, `1e2`, `3.`, `.5`, `+`, `%`, ลูกน้ำ · เงินใช้ `parseBahtToSatang` (R2)
    - **เฟส 2 (ผูกพอร์ต/DCA):** มูลค่าพอร์ตตาม R17 ด้วยราคาที่ผู้ใช้ป้อนพร้อมวันที่ราคา · **ห้ามใช้ราคาทุนแทนมูลค่าเงียบๆ** สินทรัพย์ไม่มีราคา = "ยังไม่มีราคา" และบอกว่ามูลค่ารวมไม่ครบ (ไม่นับเป็น 0) · ราคาเก่ากว่า 30 วัน (เวลาไทย) ต้องเตือน · ผู้ใช้เลือกเองว่าบัญชีลงทุน/สินทรัพย์ไหนนับเป็นเงินเกษียณ ค่าเริ่มต้นไม่เลือกสักอัน · THB เท่านั้น · ผูกพอร์ตแล้ว "เงินออมปัจจุบัน" ใช้มูลค่าพอร์ตแทน ห้ามบวกซ้ำกับค่าที่กรอกเอง และบอกที่มา · ความคืบหน้า = `roundHalfUp(มูลค่าพอร์ตสตางค์ x 10000, N)` เป็น bps แสดงผลอย่างเดียว ห้ามป้อนกลับสูตร ห้ามแสดง 100% ถ้ายังน้อยกว่า N · แผน DCA เป็นตัวเตือน ไม่ใช่เงินผูกพัน ห้ามนับ DCA ที่ยังไม่ยืนยันเป็นเงินออม ติดป้าย "แผนที่ตั้งไว้ ไม่ใช่เงินที่ผูกพันว่าจะทำตามจริง" · ห้ามบันทึกความคืบหน้า/มูลค่าที่ใช้เทียบเป็นยอด (R16)
19. **Personal Income Tax Estimate (R19):** (เจ้าของอนุมัติ 12 พ.ย. 2569 · แผนและแหล่งที่มา `docs/plans/2026-11-12-tax-2569.md`, `docs/plans/2026-11-12-tax-2569-sources.md` · ต่อยอดจาก R13)
    - **ประมาณการ ไม่ใช่ยอดบัญชี:** ผลภาษีทุกค่าคำนวณสดจากข้อมูลเข้า **ห้ามสร้าง `Entry`/`Line` ห้ามเก็บผลเป็นยอดตายตัว (R16)** ห้ามปนกับ SAFE-TO-SPEND, `cashBalance`, RUNWAY, รายรับ, รายจ่าย · ผลภาษีไม่ใช่รายจ่ายจนกว่าผู้ใช้จ่ายจริง · บันทึกได้เฉพาะข้อมูลเข้าในเฟสที่เจ้าของอนุญาต · ฟังก์ชันอยู่ใน `src/domain/tax/` ไม่แตะ DOM/ฐานข้อมูล/ledger
    - **config รายปีภาษีที่เดียว (R13):** ขั้นบันได เพดาน อัตรา ขีดต่างๆ อยู่ใน `src/domain/tax/config.ts` ห้าม hard-code ที่อื่น · ทุกค่ามีที่มา (ลิงก์) และระดับความมั่นใจ (`verified` / `partial` / `unverified`) · ค่า `unverified` ใช้ในสูตรได้ก็ต่อเมื่อมี **ทั้ง** (1) เจ้าของอนุมัติให้ใช้ค่านั้นเป็นรายการ **และ** (2) ป้าย "ยังไม่ยืนยัน" บนจอคู่ตัวเลขนั้น ขาดอย่างใดอย่างหนึ่งห้ามใช้ · **ขีดของวิธีที่ 2 (0.5%) คือ 120,000 และ 5,000 ต้องอยู่ใน config ก่อนเริ่มเฟสที่ใช้วิธีนี้** · หน้าจอแสดงปีภาษีของ config เสมอ
    - **เงินเป็นสตางค์ (จำนวนเต็ม) อัตราเป็น bps คำนวณด้วย `bigint`** ห้าม float/`toFixed`/`parseFloat` · ข้อมูลเข้าติดลบ, NaN, -0, ไม่ใช่จำนวนเต็ม, เกินช่วงสูงสุด = `RangeError` ข้อความไทย ห้ามปัดหรือตัดค่าเงียบๆ · **ช่วงสูงสุดของข้อมูลเข้า (`MAX_TAX_INPUT_SATANG` = 100 ล้านบาท) อยู่ใน `src/domain/tax/config.ts` และใช้กับทุกช่องเงิน** (เงินได้ ภาษีที่ถูกหัก ค่าลดหย่อนที่ผู้ใช้กรอก) · ผลเกิน 2^53 = `RangeError`
    - **การปัด (ไม่มีข้อยกเว้นใหม่ ใช้ `roundHalfUpBig` ตาม R8):** ภาษีขั้นบันได **รวมตัวเศษ (ส่วนของเงินในแต่ละขั้น × bps) ทุกขั้นก่อน แล้วปัดครั้งเดียว** · เพดานที่เป็นร้อยละของเงินได้ (30%, 15%) และค่าใช้จ่ายเหมา 50% ปัดครึ่งขึ้นด้วยตัวปัดกลางตัวเดียวกัน
    - **ค่าใช้จ่ายเหมาเงินเดือน:** 50% ของเงินได้ **รวมกันครั้งเดียว** ไม่เกิน 100,000 บาท (ไม่ใช่ต่อประเภท) · ฐานของเพดานร้อยละคือเงินได้พึงประเมินรวม ไม่ใช่เงินได้สุทธิ
    - **ค่าลดหย่อนเกินเพดาน:** ใช้ได้ตามเพดาน และต้องแสดง "ขอ X ใช้ได้ Y" ไม่เงียบ · เพดานรายตัวก่อน แล้วเพดานกลุ่ม (กลุ่มเกษียณ 500,000 ฯลฯ) ผลรวมต้องไม่เกินเพดานกลุ่มเสมอ · **เมื่อเพดานกลุ่มชนก่อน ตัดตามลำดับคงที่ `DEDUCTION_ORDER` (รายการที่อยู่ก่อนได้ก่อน เช่น กองทุนสำรองเลี้ยงชีพ ก่อน RMF ก่อนประกันชีวิตแบบบำนาญ) ไม่ตัดตามสัดส่วน** · ลำดับแสดงผลคงที่ · เงินได้สุทธิติดลบ = 0 ภาษีไม่ติดลบ · ผลต่างกับภาษีที่ถูกหักแล้วใช้เครื่องหมายแยกชัด (บวก = ชำระเพิ่ม, ลบ = ขอคืน, ศูนย์ = เท่ากัน ห้าม -0)
    - **กลุ่มเกษียณ 500,000 และลำดับตัดคงที่ (เจ้าของตัดสิน 13 พ.ย. 2569):** กลุ่มเกษียณประกอบด้วย **กองทุนสำรองเลี้ยงชีพ (PVD) + RMF + เบี้ยประกันชีวิตแบบบำนาญ** (ส่วนที่เข้ากลุ่ม) รวมกันไม่เกิน 500,000 บาท · เมื่อเพดานกลุ่มชน ตัดตามลำดับคงที่ **PVD → RMF → ประกันชีวิตแบบบำนาญ** (ตามลำดับใน `DEDUCTION_ORDER`) ไม่ตัดตามสัดส่วน · Thai ESG อยู่นอกกลุ่ม ยังคงนับตามเพดานของตัวเอง
    - **กองทุนสำรองเลี้ยงชีพ (PVD):** เงินสะสมของลูกจ้างแบ่งเป็น (ก) **ส่วนหักลดหย่อน** ไม่เกิน 10,000 บาท และ (ข) **ส่วนเกินที่ได้รับยกเว้น** ไม่เกิน 490,000 บาท และไม่เกิน 15% ของค่าจ้าง (ค่าจ้าง = เงินได้เงินเดือนทั้งปี, 15% ปัดครึ่งขึ้นด้วยตัวปัดกลาง) · รวม (ก)+(ข) นับในกลุ่มเกษียณ 500,000 และอยู่ก่อน RMF/บำนาญในลำดับตัดคงที่ · **ส่วนที่ได้รับยกเว้นหักออกจากเงินได้พึงประเมินเหมือนค่าลดหย่อน** (นับรวมใน "ค่าลดหย่อนรวม" ของผลลัพธ์) · **ค่าใช้จ่ายเหมา 50% ไม่เกิน 100,000 ยังคิดจากเงินได้ทั้งหมดตามเดิม** ไม่หักส่วนที่ได้รับยกเว้นก่อน · ต้องแสดงแยก "หักลดหย่อน X + ส่วนที่ไม่ต้องนำมาคิดภาษี Y" และ "ขอ X ใช้ได้ Y" เมื่อเกินเพดาน
    - **เบี้ยบำนาญเติมช่องประกันชีวิตก่อน (เจ้าของตัดสิน 13 พ.ย. 2569 เลือกแบบที่ผู้เสียภาษีได้สิทธิสูงสุด ตามตัวอย่างกรมสรรพากรหน้า 43975):** ลำดับคงที่ **ประกันชีวิต → ประกันสุขภาพ → บำนาญเติมช่องประกันชีวิต → กลุ่มเกษียณ** · เบี้ยบำนาญเติมช่องประกันชีวิต (คีย์ `pensionToLife`) เท่าที่ช่องประกันชีวิต (ไม่เกิน 100,000) และช่องชีวิต+สุขภาพรวม (ไม่เกิน 100,000) ยังเหลือหลังหักประกันชีวิตและประกันสุขภาพแล้ว · **ส่วนที่เหลือจึงนับเข้ากลุ่มเกษียณ** ภายใต้เพดานรายตัว 15% ของเงินได้ ไม่เกิน 200,000 และเพดานกลุ่ม 500,000 · **แถวประกันชีวิตแบบบำนาญนับเฉพาะส่วนที่เข้ากลุ่ม** (ไม่รวมส่วน `pensionToLife`) ผลรวมสองส่วนต้องไม่เกินเบี้ยที่กรอก และห้ามนับซ้ำ · ส่วน `pensionToLife` ไม่ถูกจำกัดด้วยเพดาน 15%/200,000 และไม่กินโควตากลุ่มเกษียณ · ประกันสุขภาพต้องไม่ถูกบำนาญแย่งช่อง (สุขภาพมาก่อน) · หน้าจอต้องบอกเบี้ยบำนาญที่กรอกทั้งหมดและส่วนที่แบ่งไปช่องประกันชีวิต
    - **สถานะ `basis: 'continuing'` (เกณฑ์ที่ใช้ต่อเนื่อง):** ใช้กับค่าที่มาจากเอกสารของปีก่อนๆ และ **ไม่พบประกาศเปลี่ยนแปลงสำหรับปี 2569** · ป้ายบนจอต้องเป็น **"เกณฑ์ที่ใช้ต่อเนื่อง ไม่พบประกาศเปลี่ยนแปลงสำหรับปี 2569"** พร้อมคำอธิบายปีของเอกสารจริง (เช่น หน้ากรมสรรพากรปี 2560, ถาม-ตอบปี 2553, อินโฟกราฟิกปี 2565) · **ห้ามเรียกว่า "ยืนยันแล้ว"** และระดับความมั่นใจยังเป็น `partial` (ไม่ยกเป็น `verified`) · `unverified` ยังมีผลเหนือกว่า `continuing` เสมอ (ป้ายเป็น "ยังไม่ยืนยัน") · ทุกค่าที่ใช้สถานะนี้ต้องมีลิงก์ rd.go.th ใน config
    - **"สิทธิที่ยังใช้ได้":** แสดงเพดานที่เหลือเป็นข้อเท็จจริงเท่านั้น ห้ามคำชวนซื้อหรือแนะนำกองทุน ("ควรซื้อ", "รีบ", "คุ้ม", "ประหยัดภาษีได้")
    - **ข้อความบังคับ** ติดผลลัพธ์ทุกจุด: "ตัวเลขนี้เป็นการประมาณการเท่านั้น ไม่ใช่คำแนะนำทางภาษี ไม่ใช่การรับประกันผล และอาจต่างจากที่กรมสรรพากรคำนวณ โปรดตรวจกับ e-Filing หรือกรมสรรพากรก่อนยื่นแบบ" · ห้ามคำสื่อรับประกัน ("ต้องจ่าย", "ได้คืนแน่", "แน่นอน", "รับรอง") · แสดงปีภาษีและป้าย "ประมาณการ" ที่ตัวเลขทุกตัว · แสดงข้อจำกัด (รองรับเฉพาะเงินเดือน ไม่รวมเงินได้อื่น ไม่ตรวจเงื่อนไขถือครอง RMF/Thai ESG ไม่ตรวจเงื่อนไขของกองทุนสำรองเลี้ยงชีพและประกันบำนาญ เช่น อายุ ระยะเวลาถือครอง ไม่รวม SSF/กบข./กอช.)
    - **เงินได้ที่ไม่ใช่เงินเดือน** (เฟสแรก): ไม่คำนวณ ขึ้นข้อความ "ยังไม่รองรับ" แทนการให้ตัวเลขผิดแบบเงียบๆ
    - **เฟสผูกพอร์ต (เฟส 3):** ใช้เฉพาะ **ยอดซื้อในปีภาษี** (1 ม.ค.–31 ธ.ค. เวลาไทย, พ.ศ. 2569 = ค.ศ. 2026) ของสินทรัพย์ที่ **ผู้ใช้เลือกติดป้าย RMF/Thai ESG เอง** (ค่าเริ่มต้นไม่ติด) · **ไม่รวมค่าธรรมเนียม ไม่นับปันผลที่ลงทุนต่อ** · ไม่ใช้มูลค่าตลาดหรือต้นทุนเฉลี่ยคงเหลือ · ไม่นับแผน DCA ที่ยังไม่ยืนยัน · ไม่บวกซ้ำกับยอดที่ผู้ใช้กรอกเอง · ผู้ใช้แก้ยอดตามหนังสือรับรองการซื้อจาก บลจ. ได้ · อ่านอย่างเดียว ไม่เขียนกลับ ledger ไม่ปนกับกำไร/ปันผล (R17) · บอกข้อจำกัด "ขายก่อนครบเงื่อนไขถือครองอาจต้องคืนสิทธิ แอปตรวจไม่ได้"

20. **Multi-Currency Investment (R20):** (เจ้าของอนุมัติ 15 พ.ย. 2569 · ตัวอย่างตัวเลขเต็มและเหตุผลอยู่ที่ `docs/plans/phase-a-us-stocks.md` · แทนข้อความ "รุ่นแรก THB เท่านั้น" และ "กำไรจากอัตราแลกเปลี่ยนรอกฎแยก" ใน R11 และ R17 · สกุลที่รองรับตอนนี้: THB และ USD)
    - **หน่วยเงิน:** USD เก็บเป็นเซนต์ (จำนวนเต็ม ช่วงปลอดภัยเหมือนสตางค์ใน R1) · ห้าม float · ห้ามบวก/ลบข้ามสกุลโดยตรง (R3/R10) · ยอดในสมุดบัญชีคู่ของบัญชี USD เป็นเซนต์ ผลรวมต่อ Entry เป็น 0 แยกตามสกุล (R16) การแลกเงินข้ามสกุลต้องมีบัญชีพักอัตราแลกเปลี่ยน (`equity`) ฝั่งละสกุล · สินทรัพย์มีสกุลของตัวเอง เงินในรายการลงทุน (มูลค่าซื้อ ค่าธรรมเนียม ปันผล ภาษีหัก) เป็นหน่วยย่อยของสกุลนั้น ราคาต่อหน่วย = micro ของสกุลนั้น (× 10^6) หน่วย = × 10^8 (R17) · **ค่าธรรมเนียมรับเป็นสกุลของสินทรัพย์เท่านั้น** (USD สำหรับหุ้นสหรัฐ)
    - **อัตราแลกเปลี่ยน:** `fxRateMicro` = บาทต่อ 1 หน่วยสกุลต่างประเทศ × 10^6 จำนวนเต็มบวก ไม่เกิน 2^53−1 (ตาม R10) · ห้าม float · แปลงเงิน `satang = roundHalfUp(cents × fxRateMicro / 10^6)` **ปัดครั้งเดียว** ด้วย `roundHalfUpBig` ตัวกลาง (R8) ห้ามปัดผ่านขั้นกลาง ผลเกินช่วงปลอดภัยโยน `RangeError` อัตราเป็น 0 หรือติดลบปฏิเสธ · มูลค่าหุ้นเป็นเซนต์ `roundHalfUp(units × priceMicro / 10^12)` · **การแลกเงินเก็บจำนวนเงินสองฝั่ง (บาทที่จ่าย ดอลลาร์ที่ได้) เป็นข้อมูลหลัก** อัตราของรายการแลกเงินคำนวณจากสองค่านี้ `roundHalfUp(satang × 10^6 / cents)` (ค่าอ้างอิง ไม่ใช่ข้อมูลหลัก) · อัตราของรายการซื้อ/ขาย/ปันผล: ระบบเติมค่าตั้งต้นจากรายการแลกเงินล่าสุด ผู้ใช้แก้ได้ ค่าที่บันทึกคือค่าสุดท้ายที่ผู้ใช้ยืนยัน
    - **ต้นทุนบาทใช้อัตราวันที่เกิดรายการ:** ต่อสินทรัพย์เก็บ 2 ถังจากการเล่นซ้ำรายการ ไม่เก็บยอดตายตัว (R16): `Cusd` (เซนต์ รวมค่าธรรมเนียมซื้อ) และ `Cthb` (สตางค์) · ซื้อ: `Cusd += A+F`, `Cthb += roundHalfUp((A+F) × fxซื้อ / 10^6)` · ขายบางส่วน (ต้นทุนเฉลี่ย R11/R17): `costOutUsd = min(roundHalfUp(Cusd×u/U), Cusd−1)` และ `costOutThb = min(roundHalfUp(Cthb×u/U), Cthb−1)` ขายหมดตัดทั้งก้อนทั้งสองถัง · **ปฏิเสธรายการซื้อที่ทำให้ `Cthb < 1`** · เงินสด USD ในรุ่นแรกไม่มีต้นทุนบาทของตัวเอง
    - **แยกกำไรจากราคาหุ้นกับจากค่าเงิน (ขาย):** `netUsd = grossUsd − feeUsd` · `proceedsThb = roundHalfUp(netUsd × fxขาย / 10^6)` · `gainThb = proceedsThb − costOutThb` · `priceGainUsd = netUsd − costOutUsd` · `priceGainThb = roundHalfUp(priceGainUsd × fxขาย / 10^6)` · **`fxGainThb = gainThb − priceGainThb` (ส่วนที่เหลือ)** ผลรวมสองส่วนเท่ากำไรรวมเป๊ะเสมอ · ส่วนแยกเป็นค่าแสดงผลที่คลาดได้ราว fx/2 สตางค์ต่อการขาย และไม่รับประกันเป็น 0 เมื่ออัตราซื้อเท่าอัตราขาย · **ไม่ใช่ฐานภาษีไทย** ต้องติดป้ายทุกจุดที่แสดง (ฐานภาษีตาม ป.161/2566 คิดจากเงินที่นำเข้า ณ อัตราวันนำเข้า ดู R13/R19 · คิดในเฟสโอนกลับ)
    - **สมุดบัญชีคู่ (R16):** Entry รายการ USD เป็นสกุล USD ล้วน ไม่ผสมสกุล (ยกเว้นการแลกเงินที่มีบัญชีพักฝั่งละสกุล) · ซื้อ = +สินทรัพย์ (A+F) −เงินสด USD · ขาย = +เงินสด USD net −สินทรัพย์ costOutUsd และผลต่างเป็นรายรับ/รายจ่ายหมวดผลลงทุนสกุล USD · ปันผล = +เงินสด USD (D−W) +รายจ่ายภาษีหัก W −รายรับปันผล D · บัญชีผลลงทุน USD ใช้ชื่อเฉพาะ (`inv-gain-usd` `inv-loss-usd` `inv-dividend-usd` `inv-wht-usd`) ป้องกันแบบเดียวกับ `inv-*` · Line เป็น 0 ไม่สร้าง Entry เหลือ <2 บรรทัดปฏิเสธ · ตัวเลขบาทของกำไร/ปันผลคำนวณจากรายการลงทุนที่เล่นซ้ำ ไม่ใช่จากบรรทัดในสมุด · รายได้/รายจ่ายรายเดือนนับเฉพาะสกุลบาท · บัญชี USD ห้ามนับใน `cashBalance`, SAFE-TO-SPEND และ RUNWAY (ทั้งเพราะสกุลและ `kind: 'investment'`)
    - **ปันผลและภาษีหัก:** ผู้ใช้กรอก D (ก่อนภาษี) และ W (ภาษีที่ถูกหัก) เป็นเซนต์ `0 ≤ W < D` · ระบบมีตัวช่วยเติมค่าแนะนำ `W = roundHalfUp(D × 15 / 100)` ผู้ใช้แก้ได้ ค่าที่บันทึกคือค่าสุดท้ายที่ผู้ใช้ยืนยัน (อัตรา 15% เป็นค่าตั้งต้นของตัวช่วยใน config กลางตาม R13 ไม่ใช่การตัดสินสิทธิ์ W-8BEN) · บาท: `grossThb = roundHalfUp(D × fx / 10^6)`, `whtThb = roundHalfUp(W × fx / 10^6)`, **`netThb = grossThb − whtThb`** (หักเอา ไม่ปัดแยกอีกรอบ)
    - **มูลค่าปัจจุบันและความมั่งคั่ง:** มูลค่าหุ้น USD แปลงเป็นบาทด้วยอัตราล่าสุดที่กรอก ต้องแสดงวันที่ของราคาและอัตรา เกิน 30 วันเตือนว่าเก่า · เป็นค่าแสดงผล ไม่ลงสมุด · เงินสด USD และหุ้นในบัญชี USD นับเข้าความมั่งคั่งสุทธิเป็นบาทด้วยอัตราล่าสุด (ไม่นับใน SAFE-TO-SPEND/RUNWAY)
    - **Invariant (ต้องมีเทสต์):** `Cusd = Cusd' + costOutUsd` และ `Cthb = Cthb' + costOutThb` ตรงเป๊ะ · `U' = 0 ⇔ Cusd' = 0 ⇔ Cthb' = 0` · `priceGainThb + fxGainThb = gainThb` ตรงเป๊ะ · ผลรวม Line ต่อสกุลของทุก Entry = 0 · Integrity: ต้นทุน USD ในสมุดต่อสินทรัพย์ = `Cusd` ที่เล่นซ้ำ, ทุกรายการสกุลต่างประเทศมี `fxRateMicro` > 0, สกุลบัญชีลงทุน = สกุลสินทรัพย์ · ข้อมูลเงินบาทเดิมต้องไม่เปลี่ยน (ทำสแนปช็อตก่อน migration และเทียบยอดทุกตัวหลัง migration)

## D. กฎด้านคุณภาพ

14. **Test Rule:**
    - ทุกฟังก์ชันคำนวณเงิน (PMT, ตารางผ่อน, FIFO, FX, ภาษี, Safe-to-spend) ต้องมี unit test ก่อน merge
    - ต้องมีเทสต์ขอบเขต: ยอด 0, ยอดน้อยมาก, งวดสุดท้าย, ขายเกินจำนวนที่ถือ, วันสิ้นเดือน
    - ต้องมี Integrity Check ตรวจว่ายอดกระเป๋า = ผลรวมธุรกรรม, ไม่มีทศนิยมหลุดเข้ามา, Transfer สมดุล
15. **Recurring & Safe-to-spend:**
    - การจ่ายบิลประจำสร้างธุรกรรมจริงได้เพียงครั้งเดียวต่อรอบ (เก็บ `lastPaidMonth`)
    - `lastPaidMonth` ต้องไม่เกินเดือนปัจจุบัน ในทุกเส้นทางที่เขียนค่านี้ ไม่ใช่เฉพาะตอนกดจ่ายบิล (เจ้าของอนุมัติ 4 พ.ย. 2569) · "เดือนปัจจุบัน" และ "วันนี้" ของกฎข้อนี้นับตามเวลาประเทศไทย (Asia/Bangkok) ทั้งฝั่งเว็บและฐานข้อมูล ไม่ใช้เวลาของเครื่องผู้ใช้ (เจ้าของอนุมัติ 8 พ.ย. 2569 แทนถ้อยคำเดิม "ตามวันที่ของเครื่อง")
    - รายการจ่ายบิลประจำต้องผูกกับบิลและรอบที่จ่าย (และ `lastPaidMonth` ก่อนจ่าย) ในรายการเดียวกัน การลบหรือยกเลิกรายการจ่ายต้องคืน `lastPaidMonth` ในธุรกรรมเดียวกันเสมอ ห้ามลบรายการโดยบิลยังค้างสถานะ "จ่ายแล้ว" (เจ้าของอนุมัติ 4 พ.ย. 2569)
    - `safeToSpend()` = (ยอดกระเป๋าที่ใช้จ่ายได้ − บิลและงวดหนี้ที่ยังไม่จ่ายก่อนวันรับเงินเดือนถัดไป − เงินสำรองที่ผู้ใช้ตั้ง) ÷ จำนวนวันที่เหลือ
    - ช่วงนับบิลค้างคือ [วันนี้, วันรับเงินเดือนถัดไป] **รวมวันรับเงินเดือน**: บิลที่ครบกำหนดตรงวันรับเงินเดือนถัดไปถูกหักจากรอบปัจจุบัน (ทางปลอดภัย) ส่วนจำนวนวันที่เหลือที่ใช้หารนับ [วันนี้, วันรับเงินเดือนถัดไป) (เจ้าของอนุมัติ 11 พ.ย. 2569)
    - ถ้าวันนี้คือวันรับเงินเดือน บิลงวดวันนี้ที่ยังไม่จ่ายกับบิลงวดวันรับเงินเดือนถัดไปเป็นหนี้คนละก้อน ถูกหักทั้งคู่ ไม่ใช่การนับซ้ำ (เจ้าของอนุมัติ 11 พ.ย. 2569)
    - ผลลัพธ์ติดลบให้แสดงเป็น 0 พร้อมคำเตือน ห้ามแสดงตัวเลขติดลบเป็นเงินที่ใช้ได้
