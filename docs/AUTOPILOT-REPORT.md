# รายงานโหมดทำเอง (เริ่ม 27 พ.ย. 2569 · อัปเดตล่าสุด 28 พ.ย. 2569)

กติกา: `docs/AUTOPILOT.md` · อัปเดตทุกครั้งที่จบงานชิ้นหนึ่ง

## รอเจ้าของ (เรียงตามความสำคัญ)

### 1. อนุมัติ migration แก้บั๊ก (draft #290) · **แนะนำให้ทำก่อน**
- **บั๊กที่ใช้งานจริงอยู่:** นำเข้าไฟล์สำรองใหญ่ (เกิน 1,500 รายการ หรือบรรทัดรวมเกินเพดานต่อคำสั่ง) ที่มีค่าตั้งค่า ถูกฐานข้อมูลปฏิเสธทั้งก้อน (42501) ไม่มีข้อมูลเข้า ไม่มีข้อมูลเสียหาย
- พิสูจน์แล้ว: เทสต์ใหม่ล้ม 42501 เมื่อไม่ใส่ migration และผ่านเมื่อใส่แบบย้อนกลับ · money-auditor และ security-auditor ไม่พบระดับสูงในตัว migration
- ก่อนใส่: (1) เทียบนิยามฟังก์ชันจริง (`pg_get_functiondef`) กับ `20261111000200` (2) ใส่ migration (3) รันเทสต์ SQL **ครบทุกไฟล์** (ติดข้อ 2 ด้านล่าง) (4) live-contract บน branch (5) money-auditor ดูซ้ำบรรทัดที่แก้ในเทสต์ (`import_chunked_settings_test.sql` เพิ่ม `logout` ก่อนสลับผู้ใช้ · ข้อระดับสูงจากการตรวจ ยืนยันด้วยการรันแล้ว แต่ยังไม่ได้ส่งตรวจซ้ำ) แล้วจึง merge

### 2. `batched_delete_test.sql` หมดเวลา 120 วินาที (กระทบข้อ 1 และ 3)
- รอบแรกของคืน 28 พ.ย. ผ่านใน 26.7 วินาที · สามรอบถัดมาหมดเวลา (57014) ทั้ง **ใส่และไม่ใส่** migration จึงไม่ได้เกิดจาก migration ใหม่
- คำสั่งที่ถูกตัด (log Supabase รอบที่สอง): `private.assert_entry_balanced` ที่ทำงานตอน `set constraints all immediate` ระหว่างเตรียมข้อมูลจำนวนมาก
- **ยังพิสูจน์สาเหตุไม่ได้** ข้อสันนิษฐาน: แถวที่ถูกย้อนกลับจากการรันซ้ำค้างในตารางและสถิติไม่ทันสมัย ฐานข้อมูลจึงเลือกวิธีค้นที่ช้า
- ผู้ใช้จริง: live-contract หลังจากนั้น 3 รอบผ่าน 70/70 ในเวลาปกติ
- **แนะนำ:** รัน `admin:sql-tests` อีกครั้งหลังพักฐานข้อมูลหลายชั่วโมง ถ้ายังช้า ให้ดูจำนวนแถวค้างของ `lines`/`entries` และพิจารณา `ANALYZE` (ผู้ช่วยไม่มีสิทธิ์อ่านหรือสั่งโดยไม่กดยืนยัน) · ห้ามแก้ด้วยการเพิ่มเวลารออย่างเดียว

### 3. อนุมัติ migration กันผิดบัญชีที่ฐานข้อมูล (draft #291)
- เพิ่มอย่างเดียว: ตัวห่อ `*_as(p_expected_user, …)` 9 ฟังก์ชัน ไม่ตรงบัญชี = `PT412` ก่อนทำอะไร · ฟังก์ชันเดิมไม่ถูกแตะ
- เทสต์ใหม่ผ่านในการรันแบบย้อนกลับ 2 รอบ · security-auditor และ money-auditor ผ่าน
- **ใส่หลังข้อ 1** (เทสต์ของใบนี้ใช้ค่าตั้งค่าในการแบ่งก้อน) · มี grant/revoke ต้องรันเทสต์ SQL ครบทุกไฟล์หลังใส่
- หลังใส่ ยังต้องแก้เว็บให้เรียกฟังก์ชัน `_as` (ยังไม่ได้ทำ) · ยังไม่ครอบทางบันทึกรายการทั่วไป และฟังก์ชันล้างรุ่นเก่า `reset_my_ledger` / `delete_my_account` (การถอนสิทธิ์ต้องรออนุมัติ)

### คำสั่งที่ไม่ได้ทำเพราะต้องกดยืนยัน
- ไม่ได้ใช้ `execute_sql` / `apply_migration` เลย · ไม่ได้รัน `admin:sql-tests` แบบส่งชื่อไฟล์
